  <name>Task 1: Install MCP SDK and create MCP server process</name>
  <files>backend/package.json, backend/src/mcp/mcp-server.ts, backend/src/mcp/mcp-router.ts, backend/src/mcp/index.ts</files>
  <action>
Install `@modelcontextprotocol/sdk` in backend. Create `backend/src/mcp/` directory with three files:

**mcp-server.ts** — Core MCP server using `McpServer` from `@modelcontextprotocol/sdk/server/mcp.js`. On startup:
1. Import `BASTION_TOOLS` from `../ironclaw/tool-bridge.js` (this is the canonical tool list)
2. For each tool in BASTION_TOOLS, register it with `server.tool(name, description, inputSchema, handler)`.
3. The handler validates the caller's agent DID from the request context against tool permissions. For Phase 52 MVP, accept a `x-agent-did` header and check it against a simple allowlist loaded from environment or DB. If DID not authorized for this tool, return error content.
4. Dispatch tool execution to the tool-bridge's existing logic (reuse `ToolBridge.handleToolCall` approach but without the action pipeline — MCP tools are deterministic, not action cards).
5. Return `{ content: [{ type: 'text', text: JSON.stringify(result) }] }` per MCP protocol.

**mcp-router.ts** — Express router with SSE transport endpoint. Use `SSEServerTransport` from `@modelcontextprotocol/sdk/server/sse.js`. Mount at `/mcp/sse` for SSE connections and `/mcp/messages` for message posting. Include health check at `GET /mcp/health` returning `{ status: 'ok', tools: N }`.

**index.ts** — Entry point for the Docker container. Creates Express app, mounts mcp-router, starts server on port 3334 (follows bastion port convention). Logs startup with tool count.

Run `bash -lc 'cd backend && npm install @modelcontextprotocol/sdk'` to install the dependency.
