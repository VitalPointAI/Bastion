**IronclawContext.tsx** — Add task state management:

1. Add state: `activeTask: IronclawTaskData | null` (useState)
2. Add WebSocket listener for `ironclaw.step-progress` messages. When received:
   - Parse the StepProgressData from the message
   - If there's an associated taskId, fetch full task status from `GET /api/ironclaw/tasks/:taskId/status`
   - Update `activeTask` state
3. Add WebSocket listener for `ironclaw.task-complete` messages. When received:
   - Update activeTask status to 'awaiting_approval' or 'completed'
4. Add action handlers exposed via context:
   - `approveTaskSuggestion(taskId: string, suggestionId: string)` — calls `POST /api/ironclaw/tasks/:taskId/approve/:suggestionId`
   - `dismissTaskSuggestion(taskId: string, suggestionId: string)` — calls `POST /api/ironclaw/tasks/:taskId/dismiss/:suggestionId`
   - `refineTask(taskId: string, feedback: string)` — calls `POST /api/ironclaw/tasks/:taskId/refine` with `{ feedback }`
5. On problem set change, fetch active tasks: `GET /api/ironclaw/tasks/:problemSetId?status=active`

Add these to the context value object so IronclawTaskPanel can access them.

```
    "target_fields": { "field.path": "Field Label" },

writing mission statements, performing threat assessments, building intelligence estimates,

for problem set content.

For simple questions or clarifications, respond normally without task_request.
```

```
}
```
