  <action>
Create `backend/src/ai-staff/ai-staff-router.ts`:

Express router mounted at `/api/ai-staff` with the following endpoints:

1. `GET /api/ai-staff/:problemSetId/feed` -- returns ranked feed items (query params: tab, limit=50, offset=0). Uses store.getFeedItems + rankFeedItems.
2. `POST /api/ai-staff/:problemSetId/feed` -- creates a new feed item. After inserting, publishes to WebSocket channel `ai.staff.${problemSetId}` with message type `ai.feed.new`. Returns the created item.
3. `PATCH /api/ai-staff/:problemSetId/feed/:itemId/read` -- marks item as read.
4. `POST /api/ai-staff/:problemSetId/feed/read-all` -- marks all items as read.
5. `GET /api/ai-staff/:problemSetId/annotations` -- returns annotations for problem set.
6. `POST /api/ai-staff/:problemSetId/annotations` -- creates annotation. Publishes `ai.annotation.new` to WebSocket.
7. `PATCH /api/ai-staff/:problemSetId/annotations/:annotationId` -- updates annotation status (accept/dismiss/modify/escalate).
8. `GET /api/ai-staff/:problemSetId/chat` -- returns chat history (query: limit=100).
9. `POST /api/ai-staff/:problemSetId/chat` -- adds chat message. If sender is 'user', this is where the agent routing would trigger (placeholder for now -- just stores and returns). Publishes `ai.chat.new` to WebSocket.
10. `GET /api/ai-staff/:problemSetId/routing` -- returns tab agent routing config.
11. `PUT /api/ai-staff/:problemSetId/routing/:tabId` -- updates agent routing for a tab (user augmentation).

WebSocket integration:
- Import the MessageBus from `backend/src/messaging.ts`
- Publish to channel `ai.staff.${problemSetId}` using the existing `publish` method
- Message format: `{ type: 'message', data: { messageType: string, channel: string, payload: any } }`

Error handling: wrap each handler in try/catch, return 500 with { error: string }. Use zod for request body validation where applicable.

Do NOT wire this router into the main app.ts yet -- that happens in Plan 05 integration.
