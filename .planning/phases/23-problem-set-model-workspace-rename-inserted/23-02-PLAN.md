Write a comprehensive SQL migration script that:

1. Renames all tables (parent tables first to handle FK cascades correctly):
   ```sql
   ALTER TABLE workspaces RENAME TO problem_sets;
   -- then child tables...
   ```

2. Renames all `workspace_id` columns to `problem_set_id` across every table that has one.

3. Renames `workspace_type` to `echelon` in the main problem_sets table.

4. Renames `parent_workspace_id` to `parent_problem_set_id`.

5. Migrates WorkspaceType values to echelon values:
   ```sql
   UPDATE problem_sets SET echelon = CASE
     WHEN echelon = 'Organization' THEN 'strategic'
     WHEN echelon = 'Unit' THEN 'operational'
     WHEN echelon = 'Team' THEN 'tactical'
     ELSE 'operational'
   END;
   ```

6. Adds `problem_statement TEXT` column to problem_sets table.

7. Updates off-chain ID prefixes in data:
   ```sql
   UPDATE problem_sets SET id = REPLACE(id, 'WS-', 'PS-') WHERE id LIKE 'WS-%';
   UPDATE problem_set_members SET id = REPLACE(id, 'WM-', 'PM-') WHERE id LIKE 'WM-%';
   -- etc for all tables with prefixed IDs
   ```
   Also update FK references that point to these IDs.

8. Renames all indexes:
   ```sql
   ALTER INDEX IF EXISTS idx_workspace_parent RENAME TO idx_problem_set_parent;
   -- etc
   ```

9. Renames exercise_scenarios.workspace_id to exercise_scenarios.problem_set_id.

Wrap the entire migration in a transaction (BEGIN/COMMIT).

IMPORTANT: Also update the FK references in child tables when parent IDs change. For example, when updating `problem_sets.id` from `WS-*` to `PS-*`, also update `problem_set_members.problem_set_id` to match. Use a CTE or do updates in the correct order.
