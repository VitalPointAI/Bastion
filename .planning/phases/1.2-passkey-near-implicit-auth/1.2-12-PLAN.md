## Why This Fix Is Needed

The WebAuthn authentication flow has this data path:
```
Backend (JSON) --> Frontend (fetch) --> startAuthentication(options) --> Browser WebAuthn API
```

The error trace proves the issue is in the INPUT options:
```
Failed to execute 'get' on 'CredentialsContainer':
  Failed to read 'extensions' from 'PublicKeyCredentialRequestOptions':
    Failed to read 'prf' from 'AuthenticationExtensionsClientInputs':
      Failed to read 'eval.first' from 'AuthenticationExtensionsPRFValues':
        The provided value is not of type '(ArrayBuffer or ArrayBufferView)'
```

This error occurs DURING `navigator.credentials.get()` (called by startAuthentication) when the browser parses the PRF extension from the INPUT options - NOT when reading PRF output from results.

**The mismatch:**
- JSON transport requires strings (base64url encoding)
- WebAuthn API requires ArrayBuffer for `prf.eval.first`
- Backend correctly sends base64url for JSON transport
- Frontend must decode to ArrayBuffer BEFORE calling startAuthentication()

## Implementation

In authenticateWithPasskey() function, after line 72 where options are received from backend, and BEFORE calling startAuthentication() at line 75:

1. Check if the INPUT options contain PRF extension with base64url-encoded first parameter:
   ```typescript
   // PRF extension data flows: backend JSON -> frontend -> WebAuthn API
   // JSON requires strings, but WebAuthn API requires ArrayBuffer for prf.eval.first
   // We must decode the base64url string to ArrayBuffer BEFORE passing to startAuthentication()
   const prfExt = (options.extensions as Record<string, unknown>)?.prf as {
     eval?: { first?: string };
   } | undefined;
   ```

2. If PRF extension exists in the input options, decode the base64url string to ArrayBuffer:
   ```typescript
   if (prfExt?.eval?.first && typeof prfExt.eval.first === 'string') {
     // Backend sends base64url string (required for JSON transport)
     // Browser's WebAuthn API requires ArrayBuffer (per W3C spec)
     // Decode here, between receiving options and calling startAuthentication()
     const base64url = prfExt.eval.first;
     const base64 = base64url.replace(/-/g, '+').replace(/_/g, '/');
     const padding = '='.repeat((4 - (base64.length % 4)) % 4);
     const binary = atob(base64 + padding);
     const bytes = new Uint8Array(binary.length);
     for (let i = 0; i < binary.length; i++) {
       bytes[i] = binary.charCodeAt(i);
     }
     // Replace base64url string with ArrayBuffer for WebAuthn API
     prfExt.eval.first = bytes.buffer as unknown as string;
   }
   ```

3. Pass the modified options (now with ArrayBuffer) to startAuthentication() (existing line 75)

**Code location context:**
```typescript

// >>> INSERT PRF DECODING HERE <<<
// (Decode prf.eval.first from base64url string to ArrayBuffer)

// Line ~75: Pass options to WebAuthn - browser will parse prf.eval.first

```

Note: Processing PRF output from results (after authentication) is a separate concern. This fix addresses the INPUT options that cause the browser to fail during authentication.
