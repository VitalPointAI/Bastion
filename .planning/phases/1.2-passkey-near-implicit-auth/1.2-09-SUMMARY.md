## Technical Details

### Email Templates

Created branded email template system at `backend/src/templates/email/`:

- **base.ts**: Base layout with BASTION header (dark blue #1a365d), white content area, gray footer
- **magic-link.ts**: Login and registration verification emails
- **recovery.ts**: Account recovery email with passkey replacement instructions
- **index.ts**: Barrel file exporting all templates

All templates:
- Mobile-responsive design (max-width 600px)
- Inline CSS for email client compatibility
- System fonts for broad support
- MSO compatibility for Outlook

### Email Service

Created `backend/src/services/email.ts` with:

- **Conditional SES initialization**: Only creates client if `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY` present
- **validateSESConnection()**: Health check that verifies domain/email verification status
- **sendLoginMagicLinkEmail()**: For returning users
- **sendRegistrationMagicLinkEmail()**: For new users
- **sendRecoveryEmail()**: For account recovery
- **Dev mode fallback**: Logs email content to console when no AWS credentials

### Domain Restriction

Extended platform settings for admin-configurable domain restriction:

- **DeploymentConfig.allowedEmailDomains**: Array of allowed domains (empty = all allowed)
- **getAllowedEmailDomains()**: Get current restriction
- **setAllowedEmailDomains()**: Set restriction (normalizes to lowercase)
- **isEmailDomainAllowed()**: Validate email against restriction

### Admin API Endpoints

Added to `/api/admin/config/`:

- `GET /email-domains` - Get allowed domains
- `PUT /email-domains` - Set allowed domains with validation
- `DELETE /email-domains` - Clear restriction (allow all)

### Magic Link Service Integration

Updated `MagicLinkService.sendMagicLink()`:

1. Check domain restriction for new user registration
2. Use appropriate email template based on flow (login/registration/recovery)
3. Removed old SendGrid implementation
