## Architecture Decisions

### 1. User UUID as Stable Identifier for MPC

**Decision:** Backend-generated UUID serves as permanent anchor for MPC derivation path.

**Alternatives considered:**
- Email address as identifier → Rejected: email can change
- Passkey public key as identifier → Rejected: passkey can be lost/replaced
- Privy user ID as identifier → Rejected: removing vendor dependency

**Rationale:**
- MPC derivation path format: `bastion,{uuid}`
- UUID never changes, survives email changes, passkey changes
- NEAR account signing keys derived via Chain Signatures MPC
- User can recover account access by re-registering passkey (same UUID = same MPC path = same NEAR account)

**Impact:** Enables true account recovery without orphaning NEAR accounts.

### 2. Passkeys for Authentication ONLY (Not NEAR Derivation)

**Decision:** Passkeys authenticate users; they do NOT derive NEAR account IDs.

**Alternatives considered:**
- Derive NEAR implicit account from passkey public key → Rejected: breaks recovery (new passkey = new account = orphaned assets)
- Store passkey private key for NEAR signing → Rejected: WebAuthn doesn't expose private keys

**Rationale:**
- Passkey loss/replacement common (device upgrade, loss, damage)
- New passkey = new public key
- If NEAR account tied to passkey public key, recovery impossible
- MPC with stable UUID solves this: same UUID → same MPC path → same signing key

**Impact:** Clean separation of concerns: passkeys for auth, MPC for NEAR signing.

### 3. TOTP Encryption with AES-256-GCM

**Decision:** Encrypt TOTP secrets at rest using AES-256-GCM from @noble/ciphers.

**Alternatives considered:**
- Store secrets in plaintext → Rejected: database breach exposes 2FA
- Use argon2/scrypt for encryption → Rejected: password hashing, not encryption
- Use different cipher (e.g., ChaCha20) → Rejected: GCM provides authenticated encryption

**Rationale:**
- @noble/ciphers already in use (Phase 2 DID encryption)
- AES-256-GCM provides authenticated encryption (detects tampering)
- 12-byte nonce prevents nonce reuse
- Encryption key from TOTP_ENCRYPTION_KEY env var (32 bytes)

**Impact:** TOTP secrets protected even if database compromised.

### 4. Magic Link as PRF Fallback

**Decision:** Email-based magic link authentication when PRF extension unavailable.

**Alternatives considered:**
- PRF-only authentication → Rejected: browser compatibility issues (Safari <18, older Firefox)
- SMS OTP fallback → Rejected: phone number requirement, SIM swap attacks
- Recovery codes only → Rejected: users lose codes frequently

**Rationale:**
- PRF extension browser support evolving (2026 outlook: good, but not universal)
- Email access required for registration anyway (email verification)
- Magic link provides graceful degradation for PRF-unsupported devices
- 15-minute expiration + one-time use prevents replay attacks

**Impact:** Ensures authentication works across all browsers/devices.

### 5. Session Management with Sliding Window

**Decision:** 7-day session expiration with sliding window (extends at 50% lifetime).

**Alternatives considered:**
- Fixed 7-day expiration → Rejected: forces re-login for active users
- Refresh token pattern → Rejected: added complexity for minimal benefit
- Redis for session storage → Deferred: PostgreSQL sufficient for v1, Redis in production

**Rationale:**
- Active users don't need to re-authenticate frequently
- Sliding window: if session >50% through lifetime, extend to full 7 days
- Session activity tracked for anomaly detection
- HttpOnly cookies prevent XSS attacks

**Impact:** Better UX for active users, security for inactive sessions.

### 6. Deployment Environment Configuration

**Decision:** Three environment types with different auth requirements: public, enterprise, classified.

**Alternatives considered:**
- Single fixed configuration → Rejected: can't adapt to deployment context
- Per-user configuration → Rejected: inconsistent security posture
- Hardcoded environment detection → Rejected: inflexible

**Rationale:**
- Public: TOTP only, 7-day sessions (internet-facing deployments)
- Enterprise: TOTP or hardware token, 24-hour sessions (corporate networks)
- Classified: Hardware token or CAC/PIV, 8-hour sessions (SCIFs, no phones)
- Admin-configurable via Admin UI
- Phase 1.2 implements public; hardware token/CAC support in future phase

**Impact:** Single codebase adapts to deployment environment security requirements.

## Technical Highlights

### UUID-Based MPC Derivation Path

```typescript
// At user registration
const userId = randomUUID(); // Stable identifier - NEVER changes
const mpcDerivationPath = `bastion,${userId}`;

// During recovery: same UUID → same MPC path → same NEAR signing key
const mpcPublicKey = await mpcManager.deriveMPCPublicKey(mpcDerivationPath);
```

### Passkey Credential Storage

```typescript
// Store passkey credential with PRF capability flag
await passkeyStore.createCredential(
  userId,
  credentialId,    // WebAuthn credential ID (unique)
  publicKey,       // COSE public key bytes
  counter,         // Signature counter (replay protection)
  transports,      // usb, nfc, ble, hybrid, internal
  prfSupported     // Can this credential derive PRF secrets for DID?
);
```

### TOTP Secret Encryption

```typescript
// Encrypt TOTP secret with AES-256-GCM
function encryptSecret(secret: string): { encrypted: Buffer; nonce: Buffer } {
  const key = getEncryptionKey(); // 32 bytes from TOTP_ENCRYPTION_KEY env var
  const nonce = randomBytes(12);  // 12-byte nonce for GCM
  const cipher = gcm(key, nonce);
  const plaintext = utf8ToBytes(secret);
  const encrypted = cipher.encrypt(plaintext);
  return { encrypted: Buffer.from(encrypted), nonce: Buffer.from(nonce) };
}
```

### Magic Link Token Generation

```typescript
// Generate cryptographically secure token
const token = randomBytes(32).toString('hex'); // 64 hex chars
const expiresAt = new Date(Date.now() + 15 * 60 * 1000); // 15 minutes

// Invalidate existing unused tokens for this email
await pool.query(`UPDATE magic_link_tokens SET used = true WHERE email = $1 AND used = false`, [email]);

// Store new token
await pool.query(`INSERT INTO magic_link_tokens (token, email, expires_at) VALUES ($1, $2, $3)`, [token, email, expiresAt]);
```

### Session Sliding Window

```typescript
// Extend expiration if session >50% through lifetime
const lifetime = session.expiresAt.getTime() - session.createdAt.getTime();
const elapsed = now.getTime() - session.createdAt.getTime();

if (elapsed > lifetime * 0.5) {
  const newExpiresAt = new Date(now.getTime() + DEFAULT_SESSION_DURATION_MS);
  await pool.query(`UPDATE user_sessions SET expires_at = $1 WHERE id = $2`, [newExpiresAt, sessionId]);
}
```

## Database Schema

### auth_users
- `id` (TEXT PRIMARY KEY) - UUID, stable identifier for MPC
- `email` (TEXT UNIQUE NOT NULL) - Primary email address
- `alternate_email` (TEXT) - Alternate email for recovery
- `near_account_id` (TEXT) - NEAR account created via MPC
- `mpc_derivation_path` (TEXT NOT NULL) - Format: bastion,{uuid}
- `totp_enabled` (BOOLEAN DEFAULT false) - Has user set up TOTP 2FA?
- `passkey_registered` (BOOLEAN DEFAULT false) - Has user registered passkey?
- `created_at`, `updated_at` (TIMESTAMPTZ)

**Indexes:**
- `idx_auth_users_email` on email
- `idx_auth_users_alternate_email` on alternate_email
- `idx_auth_users_near_account` on near_account_id

### passkey_credentials
- `id` (TEXT PRIMARY KEY) - Auto-generated UUID
- `user_id` (TEXT NOT NULL FK → auth_users) - User UUID
- `credential_id` (BYTEA UNIQUE NOT NULL) - WebAuthn credential ID
- `public_key` (BYTEA NOT NULL) - COSE public key bytes
- `counter` (BIGINT DEFAULT 0) - Signature counter (replay protection)
- `transports` (JSONB DEFAULT '[]') - usb, nfc, ble, hybrid, internal
- `prf_supported` (BOOLEAN DEFAULT false) - Can derive PRF secrets for DID?
- `created_at`, `last_used_at` (TIMESTAMPTZ)

**Indexes:**
- `idx_passkey_user` on user_id
- `idx_passkey_credential_id` on credential_id (UNIQUE)

**Foreign keys:** CASCADE delete on auth_users

### totp_credentials
- `id` (TEXT PRIMARY KEY) - Auto-generated UUID
- `user_id` (TEXT UNIQUE NOT NULL FK → auth_users) - User UUID
- `secret_encrypted` (BYTEA NOT NULL) - AES-256-GCM encrypted TOTP secret
- `encryption_nonce` (BYTEA NOT NULL) - 12-byte GCM nonce
- `backup_codes` (JSONB DEFAULT '[]') - Encrypted backup codes
- `created_at`, `last_used_at` (TIMESTAMPTZ)

**Indexes:**
- `idx_totp_user` on user_id (UNIQUE)

**Foreign keys:** CASCADE delete on auth_users

### user_sessions
- `id` (TEXT PRIMARY KEY) - Session ID (stored in HttpOnly cookie)
- `user_id` (TEXT NOT NULL FK → auth_users) - User UUID
- `account_id` (TEXT) - NEAR account ID if available
- `prf_available` (BOOLEAN DEFAULT false) - Can perform DID operations?
- `created_at`, `expires_at`, `last_activity_at` (TIMESTAMPTZ)
- `ip_address`, `user_agent` (TEXT)

**Indexes:**
- `idx_session_user` on user_id
- `idx_session_expires` on expires_at

**Foreign keys:** CASCADE delete on auth_users

### magic_link_tokens
- `id` (TEXT PRIMARY KEY) - Auto-generated UUID
- `token` (TEXT UNIQUE NOT NULL) - 64-char hex (32 random bytes)
- `email` (TEXT NOT NULL) - Email address
- `expires_at` (TIMESTAMPTZ NOT NULL) - 15-minute expiration
- `used` (BOOLEAN DEFAULT false) - One-time use flag
- `created_at`, `used_at` (TIMESTAMPTZ)

**Indexes:**
- `idx_magic_link_token` on token (UNIQUE)
- `idx_magic_link_email` on email
- `idx_magic_link_expires` on expires_at

### platform_settings
- `id` (TEXT PRIMARY KEY) - Always 'default'
- `environment` (TEXT NOT NULL) - public / enterprise / classified
- `allowed_second_factors` (JSONB NOT NULL) - Array of allowed 2FA methods
- `require_second_factor` (BOOLEAN DEFAULT true) - Always true for recovery
- `session_duration_minutes` (INTEGER DEFAULT 10080) - 7 days default
- `require_reauth_for_high_value` (BOOLEAN DEFAULT false) - Passkey reauth for sensitive ops
- `created_at`, `updated_at` (TIMESTAMPTZ)

**Default row:** public environment with TOTP-only authentication
