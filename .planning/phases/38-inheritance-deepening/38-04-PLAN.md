**File 1: inheritance-ws.ts**

Create a WebSocket handler following the resource-ws.ts pattern:

```
export function setupInheritanceWebSocket(serverOrWss: HTTPServer | WebSocketServer): void
```

- Accept connections on `/ws/inheritance` with query param `parentPsId` for parent subscribers or `childPsId` for child publishers.
- Maintain two maps:
  - `parentSubscriptions: Map<string, Set<WebSocket>>` — parent PSes subscribing to child status updates
  - `childPublishers: Map<string, WebSocket>` — child PSes publishing status
- On message from child (type 'mission_status'): validate payload as MissionStatusSnapshot, persist via `inheritanceStore.upsertMissionStatus()`, broadcast to all parent subscribers via `broadcastStatusUpdate()`.
- On message from parent (type 'drill_down_request'): look up full status for requested childProblemSetId from store, send back as 'drill_down_response'.
- On message (type 'status_batch'): handle array of MissionStatusSnapshot — for DDIL reconnection flush. Persist all, broadcast all.
- Handle connection close: clean up from maps.
- Export `broadcastStatusUpdate(parentPsId: string, update: StatusUpdateMessage): void` for external callers.

**File 2: status-aggregation-service.ts**

Create StatusAggregationService class:

```
getAggregatedStatusForParent(parentPsId: string): Promise<AggregatedMissionStatus[]>
```
- Calls `inheritanceStore.getMissionStatusForParent()`.
- Returns array of summary cards with: childPsId, childPsName, missionState, mdmpPhase, percentComplete, latestKeyEvent, overallResourceHealth ('green'|'amber'|'red'), objectiveCount and completedCount, lastUpdated.

```
getDrillDownStatus(childPsId: string): Promise<MissionStatusSnapshot | null>
```
- Returns full detailed status snapshot for a specific child mission.

```
getAssessAggregation(parentPsId: string): Promise<CampaignAssessment>
```
- Aggregates all child mission statuses into campaign-level objective progress.
- Groups objective progress across children, calculates overall campaign completion percentage.
- Returns: `{ overallProgress: number, objectiveSummaries: Array<{ name, childStatuses, overallStatus }>, missionCount, completedMissions }`.

Export singleton: `export const statusAggregationService = new StatusAggregationService();`

**File 2: backend/src/api/inheritance.ts**

Add status-related API routes (REST fallback for non-WS access and initial data load):

1. `GET /:id/mission-status` — Get aggregated status of all child missions for parent PS `:id`. Calls `statusAggregationService.getAggregatedStatusForParent()`. Used by COP tab on initial load before WS connects.

2. `GET /:id/mission-status/:childPsId` — Get detailed status snapshot for specific child. Calls `statusAggregationService.getDrillDownStatus()`. Used for drill-down.

3. `POST /:id/mission-status` — Publish status update via REST (DDIL fallback when WS unavailable). Body: MissionStatusSnapshot. Persists via store, broadcasts via WS if connected. Returns 200.

4. `GET /:id/campaign-assessment` — Get campaign-level assessment aggregation. Calls `statusAggregationService.getAssessAggregation()`. Used by Assess tab.

All routes use requireAuth, zod validation, standard error handling.
