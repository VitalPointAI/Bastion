# Phase 25.1: Training Package Upload & From-Scenario Integration - Context

**Gathered:** 2026-03-06
**Status:** Ready for planning

<domain>
## Phase Boundary

Wire existing training package upload infrastructure into the new tab structure and problem set creation flow. Users can create problem sets from scenarios via the wizard and upload document packages directly from the Understand tab. No new document parsing, extraction, or AI capabilities — this is integration of existing components into the Phase 23/24 structure.

</domain>

<decisions>
## Implementation Decisions

### "Create from Scenario" wizard flow
- Add Step 0 (pre-step) to CreateProblemSetWizard: "Start fresh" or "Create from scenario"
- Choosing scenario shows a scenario picker listing all available scenarios
- Scenarios that already have a problem set created show a badge (e.g., "In use") — multiple problem sets from the same scenario is allowed
- Selecting a scenario pre-fills all fields (name, description, echelon=strategic, problem statement) — all editable by the user
- Show "Mode: Training" as a locked/read-only field when creating from scenario
- After creation, auto-navigate to the new problem set's Understand tab (not default view)
- Step flow: Step 0 (source choice) -> Step 1 (name/echelon, pre-filled) -> Step 2 (classification) -> Step 3 (review, shows scenario source)

### Upload placement in Understand tab
- Add "Training Packages" as a new sidebar item in UnderstandTab (3rd item alongside Strategic Documents and Data Sharing)
- Sidebar item only visible when app is in training mode — completely hidden in operational mode
- No indication of training features when in operational mode (clean separation)
- Show document count badge next to sidebar label (e.g., "Training Packages (12)") plus pending extraction indicator
- When no scenario is linked to the problem set, show a prompt: "No scenario linked. Create from scenario or link an existing one." with action buttons

### Document systems (separate)
- Keep strategic documents and training/scenario documents as separate systems
- strategic_documents table (StrategicDashboard) and scenario_documents table (ScenarioPackageUpload) remain distinct
- Different data models, extraction pipelines, and purposes — no unification
- Training package documents are accessible to AI staff agents for analysis (same as strategic docs)
- Clicking a training doc shows inline preview of extracted content (summary, key entities, full text) — similar to StrategicDashboard document detail pattern

### Mode awareness
- From-scenario wizard enforces training mode with visible locked indicator
- Classification ceiling enforcement: if problem set is UNCLASSIFIED, warn/block uploads tagged above that level
- Prevents accidentally mixing classification levels in training packages

### Claude's Discretion
- Classification banner display in Training Packages view (standard DoD practice — green UNCLASSIFIED, red SECRET, etc.)
- Exact pre-fill mapping from scenario data fields to wizard fields
- Empty state design for the prompt-to-link-scenario view
- Inline preview layout for extracted training document content

</decisions>

## Existing Code Insights

### Reusable Assets
- `ScenarioPackageUpload` (frontend/src/components/exercise/ScenarioPackageUpload.tsx): Full drag-drop upload with client-side tag inference, progress, doc list with extraction polling — wire into Understand tab
- `CreateProblemSetWizard` (frontend/src/components/problem-set/CreateProblemSetWizard.tsx): 3-step wizard with StepIndicator — add Step 0 pre-step
- `TabLayout` + `SidebarItem` (frontend/src/components/tabs/TabLayout): Sidebar navigation pattern used by UnderstandTab — add new item
- `exerciseService` (frontend/src/services/exercise-service.ts): uploadPackage, getDocuments, updateDocument, deleteDocument, retryExtraction
- `StrategicDashboard` document detail pattern: ReviewPanel, ObjectiveDetail — reference for inline training doc preview

### Established Patterns
- UnderstandTab uses `TabLayout` with `SidebarItem[]` array and conditional rendering by selectedView
- CreateProblemSetWizard uses step-based state with StepIndicator component
- ScenarioPackageUpload takes `scenario` prop and `onUploadComplete` callback
- Tag inference mirrors backend/src/exercise/package-parser.ts heuristics on client side
- Extraction polling: 5s interval checking for pending docs (extractionConfidence === 0)

### Integration Points
- Backend `POST /api/problem-sets/from-scenario` endpoint already exists (forces training mode)
- UnderstandTab (frontend/src/components/tabs/UnderstandTab.tsx): Add 'training-packages' view
- ProblemSetContext provides mode (training/operational) for conditional sidebar rendering
- ProblemSetSelector/ProblemSetSwitcher: Where wizard is triggered from
