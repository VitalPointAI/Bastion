# Phase 25.1: Training Package Upload & From-Scenario Integration - Research

**Researched:** 2026-03-06
**Domain:** Frontend integration -- wiring existing components into Phase 23/24 structure
**Confidence:** HIGH

## Summary

This phase is pure integration work. All the building blocks exist: `ScenarioPackageUpload` for drag-drop upload with tag inference, `CreateProblemSetWizard` for problem set creation, `UnderstandTab` with `TabLayout` sidebar pattern, `exerciseService` for all API calls, and the `POST /api/problem-sets/from-scenario` backend endpoint. The work is wiring these together with a Step 0 in the wizard, a new sidebar item in UnderstandTab, and mode-aware conditional rendering.

One significant gap discovered: the from-scenario backend endpoint creates a problem set but does NOT link it back to the scenario. The `exercise_scenarios` table has a `problem_set_id` column (added in Phase 23 migration), but it is never populated. The from-scenario endpoint also hardcodes `echelon: 'tactical'` rather than using `'strategic'` as the CONTEXT.md specifies for wizard pre-fill. These backend gaps need fixing.

**Primary recommendation:** Structure work as: (1) fix backend from-scenario endpoint to link scenario<->problem-set and accept pre-filled fields, (2) add Step 0 to wizard, (3) add Training Packages sidebar item to UnderstandTab, (4) add inline document preview.

## Common Pitfalls

### Pitfall 1: Scenario-ProblemSet Linkage Gap

**What goes wrong:** The from-scenario endpoint creates a problem set but never updates `exercise_scenarios.problem_set_id`. This means there is no way to look up which scenario a problem set was created from, breaking the "Training Packages" view which needs to know the linked scenario to show its documents.

**Why it happens:** The linkage column was added in Phase 23 migration but the from-scenario endpoint was likely written before that migration was fully planned.

**How to avoid:** Fix the backend endpoint to: (1) update `exercise_scenarios SET problem_set_id = ?` after creating the problem set, (2) add a query to find scenarios linked to a problem set. The ScenarioPackageUpload component needs the linked `ExerciseScenario` object to function.

### Pitfall 2: Backend Hardcodes Echelon as Tactical

**What goes wrong:** The from-scenario endpoint hardcodes `echelon: 'tactical'` but CONTEXT.md says pre-fill should be `echelon: strategic`. The endpoint also ignores user-provided fields like description, classification, and problem statement.

**Why it happens:** The endpoint was a minimal implementation. It needs to accept all wizard fields.

**How to avoid:** Expand `CreateFromScenarioSchema` to accept optional overrides for name, description, echelon, classification, inviteMode, discoverability, problemStatement. Use these values when creating the problem set, falling back to defaults.

### Pitfall 3: Mode Context Not Available in UnderstandTab

**What goes wrong:** UnderstandTab currently only receives `problemSetId` as a prop and does not import mode context, so it cannot conditionally show the Training Packages sidebar item.

**How to avoid:** Import `useMode()` from `ModeContext` in UnderstandTab. The mode is available via `const { mode } = useMode();`.

### Pitfall 4: ScenarioPackageUpload Tied to Scenario ID, Not Problem Set ID

**What goes wrong:** `ScenarioPackageUpload` and `exerciseService` methods (uploadPackage, getDocuments) operate on `scenarioId`, not `problemSetId`. To show training packages in the Understand tab, you need to first resolve the linked scenario from the problem set.

**How to avoid:** Add a backend endpoint or query: `GET /api/problem-sets/:id/linked-scenario` that returns the ExerciseScenario linked via `exercise_scenarios.problem_set_id`. Use this in the Understand tab to get the scenario object before rendering ScenarioPackageUpload.

### Pitfall 5: StepIndicator Component Renumbering

**What goes wrong:** The `StepIndicator` component renders step numbers starting at 1. Adding Step 0 means either showing "0, 1, 2, 3" (confusing) or adjusting the display.

**How to avoid:** Keep internal step state at 0, but pass `current={step + 1}` and `total={4}` to StepIndicator so it displays steps 1-4 visually while the code uses 0-3 internally. Or refactor to use named steps.

### UnderstandTab: Conditional Training Packages Sidebar
```typescript
import { useMode } from '../../context/ModeContext';

export function UnderstandTab({ problemSetId }: UnderstandTabProps) {
  const { mode } = useMode();
  const [selectedView, setSelectedView] = useState<UnderstandView>('strategic-docs');
  const [docCount, setDocCount] = useState(0);

  const items: SidebarItem[] = [
    { id: 'strategic-docs', label: 'Strategic Documents' },
    { id: 'subscriptions', label: 'Data Sharing', tooltip: '...' },
    // Only show in training mode
    ...(mode === 'training' ? [{
      id: 'training-packages',
      label: `Training Packages${docCount > 0 ? ` (${docCount})` : ''}`,
    }] : []),
  ];

  return (
    <TabLayout items={items} selectedItem={selectedView} onSelectItem={(id) => setSelectedView(id as UnderstandView)}>
      {selectedView === 'strategic-docs' && <StrategicDashboard problemSetId={problemSetId} />}
      {selectedView === 'subscriptions' && <SubscriptionManager problemSetId={problemSetId} />}
      {selectedView === 'training-packages' && <TrainingPackagesView problemSetId={problemSetId} />}
    </TabLayout>
  );
}
```

## Open Questions

1. **Scenario "in use" badge query**
   - What we know: Need to show which scenarios already have problem sets linked
   - What's unclear: Should this be a count of linked problem sets, or just a boolean? The CONTEXT says multiple are allowed.
   - Recommendation: Query `SELECT scenario_id, COUNT(*) FROM exercise_scenarios WHERE problem_set_id IS NOT NULL GROUP BY scenario_id` and show count badge

2. **Classification ceiling enforcement**
   - What we know: Warn/block uploads tagged above problem set classification
   - What's unclear: Where is classification checked -- client-side before upload, or server-side?
   - Recommendation: Client-side warning before upload (compare doc tags to problem set classification), server-side enforcement in upload endpoint

3. **Document detail preview pattern**
   - What we know: "Similar to StrategicDashboard document detail pattern" with ReviewPanel/ObjectiveDetail
   - What's unclear: Whether to reuse ReviewPanel directly or build a simpler preview
   - Recommendation: Build a simpler `TrainingDocPreview` component showing extracted summary, key entities, and full text in a side panel (similar layout, simpler content structure)
