  <action>
  **scenario-store.ts** -- Add three new methods to ScenarioStore class:

  1. `async updateProblemSetLink(scenarioId: string, problemSetId: string): Promise<void>` -- runs `UPDATE exercise_scenarios SET problem_set_id = $1 WHERE id = $2` with params `[problemSetId, scenarioId]`. Uses the existing `problem_set_id` column on `exercise_scenarios` table (added in Phase 23 migration, never populated until now).

  2. `async findByProblemSetId(problemSetId: string): Promise<ExerciseScenario | null>` -- runs `SELECT * FROM exercise_scenarios WHERE problem_set_id = $1 LIMIT 1` and returns `this.rowToScenario(result.rows[0])` or `null`. Note: this returns the MOST RECENT linkage if a scenario was reused (each from-scenario creation overwrites the column). This is acceptable since Plan 02 uses this to resolve the linked scenario for Training Packages view.

  3. `async getUsageCounts(): Promise<Record<string, number>>` -- query the `problem_set_activity_log` table which already records `scenario_loaded` events with `scenarioId` in the `data` JSON column (see line ~419 of problem-sets.ts). Run: `SELECT data->>'scenarioId' as scenario_id, COUNT(DISTINCT problem_set_id) as count FROM problem_set_activity_log WHERE action = 'scenario_loaded' AND data->>'scenarioId' IS NOT NULL GROUP BY data->>'scenarioId'`. Parse rows into `Record<string, number>` and return. This supports the "In use (N)" badge showing how many problem sets were created from each scenario, even when multiple problem sets come from the same scenario.

  **problem-sets.ts** -- Three changes:

  1. Expand `CreateFromScenarioSchema` to accept optional wizard fields:
  ```typescript
  const CreateFromScenarioSchema = z.object({
    scenarioId: z.string().min(1),
  ```

  2. In the from-scenario POST handler, use body values with fallbacks instead of hardcoded values: `echelon: body.echelon ?? 'strategic'` (NOT 'tactical'), `description: body.description ?? \`Training problem set based on ${scenario.name}\``, `classification: body.classification ?? 'UNCLASSIFIED'`, pass through `inviteMode`, `discoverability`, `problemStatement` if provided. After creating the problem set, call `await scenarioStore.updateProblemSetLink(body.scenarioId, problemSet.id)` to link the scenario.

  3. Add two new GET endpoints (BEFORE the `/:id` routes to avoid param conflict):
  - `GET /api/problem-sets/scenario-usage-counts` -- returns `await scenarioStore.getUsageCounts()`.
  - `GET /api/problem-sets/:id/linked-scenario` -- calls `scenarioStore.findByProblemSetId(req.params.id)`, returns scenario JSON or 404 `{ error: 'No linked scenario' }`.
