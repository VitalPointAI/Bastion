Create `frontend/src/hooks/useStaffNotifications.ts` — a custom React hook that provides real-time notification state.

Per CONTEXT.md: "Global notification panel (bell icon) shows everything across the exercise — one unified feed. Filter toggle available to scope to current role workspace. Notifications persist until explicitly dismissed — user marks them read/done."

Per research: Use the existing WebSocket at `/ws/messages` with subscribe/unsubscribe protocol. No polling (research pitfall #2).

```typescript
interface UseStaffNotificationsResult {
  notifications: StaffNotification[];
  unreadCount: number;
  roleUnreadCount: number; // filtered to activeRole
  loading: boolean;
  markRead: (notificationId: string) => Promise<void>;
  markIntegrated: (notificationId: string) => Promise<void>;
  refresh: () => Promise<void>;
}

function useStaffNotifications(scenarioId: string | null, activeRole: string): UseStaffNotificationsResult
```

Implementation:
1. On mount (when scenarioId is truthy): fetch all notifications via `exerciseService.getStaffNotifications(scenarioId)` — this is the global feed
2. Compute `unreadCount` = notifications.filter(n => !n.isRead).length
3. Compute `roleUnreadCount` = notifications.filter(n => !n.isRead && n.targetRole === activeRole).length
4. Set up WebSocket connection to `/ws/messages`:
   - Use the existing WebSocket URL pattern from the project (check messaging.ts for the exact URL/port)
   - On open: send subscribe message: `{ type: 'subscribe', channel: 'exercise.staff.{scenarioId}' }`
   - On message: if `msg.data.messageType === 'staff.product.published'`, call `refresh()` to reload notifications from the REST endpoint
   - On close/error: attempt reconnect with exponential backoff (1s, 2s, 4s, max 30s)
5. Cleanup: on unmount or scenarioId change, send unsubscribe and close WebSocket
6. `markRead`: call `exerciseService.markNotificationRead(scenarioId, notificationId)`, then update local state (set isRead=true on that notification)
7. `markIntegrated`: call `exerciseService.markNotificationIntegrated(scenarioId, notificationId)`, then update local state
8. `refresh`: re-fetch all notifications from REST endpoint

IMPORTANT: The WebSocket URL should match the existing project pattern. Check `backend/src/api/messaging.ts` for the websocket server setup — it uses `wss.handleUpgrade` on path `/ws/messages`. The frontend should connect to `ws://localhost:3001/ws/messages` (or use window.location for production). Add query param `?did={userDid}` if the existing WS protocol requires it.
