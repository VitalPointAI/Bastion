**Add pre-population (seeding) endpoint** in `exercise.ts`:

`POST /scenarios/:id/staff-workspaces/:role/seed`

This endpoint checks if products already exist for this role in this scenario. If no products exist, it seeds them from Phase 14 data:

- **J2 seeding**: Query `ipbStore.findByScenario(scenarioId, visibleTeams)` to get existing IPB assessments. For each assessment, create a staff_product of type 'ipb_assessment' with `structured.ipbAssessmentId = ipb.id` and `content = ipb.threatAssessment` (the narrative text). Also query `documentStore.findByScenario()` for OOB-type documents and create 'oob' products with reference IDs.
- **J3/J35 seeding**: Query `coaStore.findByScenario(scenarioId, visibleTeams)` for existing COAs. Create 'coa_development' (J35) or 'coa_sketch' (J3) products with `structured.coaId` references. Query `orderStore.findByScenario()` for published orders.
- **Commander seeding**: Query `coaStore.findByScenario()` for COAs with `commanderDecision` set. Create 'coa_decision' product with decision details.
- **J4/J5/J6/J1**: Create empty template products from PRODUCT_TYPE_CONFIG (no Phase 14 data to seed from).

The endpoint is idempotent — if products already exist for the role, return them without re-seeding.

CRITICAL per research pitfall 4: Do NOT copy Phase 14 data content wholesale. Store reference IDs in `structured` field (e.g., `{ ipbAssessmentId: "..." }`). The narrative/content field contains staff edits and analysis. Phase 14 records are loaded at render time via their IDs.

Add a `getProductTypeConfig(role: string)` export from the store that returns the available product types for a given role, for frontend template library display.

Also add route: `GET /scenarios/:id/staff-workspaces/:role/product-types` — returns the product type config for a role (for the "create product from template" modal).

**Create StaffProduct component** (`StaffProduct.tsx`):

This is the hybrid template editor per CONTEXT.md decision. Props:
- `product: StaffProduct` — the product being edited
- `scenarioId: string`
- `onSave: () => void` — callback after save
- `onPublish: () => void` — callback after publish
- `onBack: () => void` — return to dashboard

Layout — two sections:

1. **Structured fields section** (top):
   - Title input (editable text field)
   - Status badge: draft (grey) or published (green) with published_at timestamp
   - Dynamic structured fields based on product.productType:
     - Look up the product type in PRODUCT_TYPE_CONFIG (imported or fetched)
     - For each structuredField, render an appropriate form control:
       - String fields → `<input type="text">`
       - Array fields (like 'objectives', 'forces') → simple list editor (add/remove items)
       - Reference fields (like 'ipbAssessmentId', 'coaId') → read-only display with the referenced entity title
     - Pre-filled from `product.structured` values
   - All structured fields are editable and auto-save on blur or explicit "Save Draft" button

2. **Freeform content section** (bottom):
   - `<textarea>` for markdown/narrative content (per research: project uses plain textareas, NOT a rich text editor)
   - Pre-filled from `product.content`
   - Auto-grows to fit content
   - Placeholder text: "Enter your analysis, narrative, or notes here..."

3. **Action buttons** (footer):
   - "Save Draft" button — calls `exerciseService.updateStaffProduct()` with current structured + content values
   - "Publish" button — calls `exerciseService.publishStaffProduct()`. Only enabled when product has a title and content. Per CONTEXT.md: "Do not gate publish on completeness" — enable publish once title exists.
   - "Back to Dashboard" button — calls onBack

Per research anti-pattern: Do NOT introduce a heavy rich text editor. Use standard `<textarea>` with markdown conventions — matches existing patterns (COAScoringPanel, OrderEditor narrative fields).

**StaffProduct.css**: Card-based layout. Structured fields in a bordered section with subtle background. Content textarea full-width below. Action buttons right-aligned in footer. Use existing project color variables.
