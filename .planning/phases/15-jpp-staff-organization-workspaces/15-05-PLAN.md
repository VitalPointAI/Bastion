**ProductDiffView** (`frontend/src/components/exercise/ProductDiffView.tsx`):

Per CONTEXT.md: "Auto-merge with preview: system proposes merged content — user reviews a before/after diff and confirms. Diff view splits structured field changes (shown as summary table) from narrative text changes (shown as text diff below)."

Props: `{ notification: StaffNotification, sourceProduct: StaffProduct, targetProduct: StaffProduct | null, onAccept: () => Promise<void>, onReject: () => void, onClose: () => void }`

The diff_snapshot is already stored in `notification.diffSnapshot` (computed by backend during publish).

Layout (modal overlay or slide-in panel):
1. **Header**: "Integration Review" title + source role badge + product title + Close button
2. **Structured Field Changes** section:
   - Render as a summary table: | Field | Previous Value | New Value |
   - Read from `notification.diffSnapshot.structuredChanges[]`
   - Each row shows field name, old value (red background), new value (green background)
   - If no structured changes: "No structured field changes"
3. **Narrative Content Changes** section:
   - If `notification.diffSnapshot.contentChanged === true`:
     - Show `notification.diffSnapshot.contentSummary` as a one-line summary (from backend)
     - Below, show the source product's full content in a readonly textarea with label "Source Product Content"
     - If targetProduct exists, show current target product content alongside for comparison
   - If `contentChanged === false`: "No narrative content changes"
4. **Action buttons**:
   - "Accept & Integrate" (green) — calls onAccept, which should: merge source changes into target product (update structured fields + append/replace content), then mark notification as integrated
   - "Reject" (red) — calls onReject, just marks notification as read without integration
   - "Close" — dismisses without any action

No external diff library needed — the diff is shallow (structured field comparison table + content summary). Per research: "For content changes, show a one-paragraph AI-generated summary of what changed rather than a line-diff."

3. onAccept handler: fetch target product for the current role (find by matching product type), merge structured changes, append source content, call `exerciseService.updateStaffProduct()` to save, then call `exerciseService.markNotificationIntegrated()`
4. onReject handler: call `exerciseService.markNotificationRead()`

**AgentSuggestionPanel** (`frontend/src/components/exercise/AgentSuggestionPanel.tsx`):

Per CONTEXT.md: "Collapsible right-side panel that slides open alongside the editor — non-intrusive, human stays in control. On-demand only: user clicks 'Generate Suggestion' button — AI stays silent until asked. Agent teams configured per-role with per-product overrides: each role has a configured agent team (applies to all products), with ability to customize per product if needed. Accept/reject blocks: suggestion broken into blocks — user accepts or rejects each piece individually."

Props: `{ product: StaffProduct, scenarioId: string, roleKey: string, onApplyBlock: (blockIndex: number, content: string) => void }`

State:
- `isOpen: boolean` — panel expanded/collapsed
- `isGenerating: boolean`
- `suggestion: AgentSuggestion | null` — `{ blocks: Array<{ id: string, type: 'structured_field' | 'narrative', fieldName?: string, content: string, status: 'pending' | 'accepted' | 'rejected' }> }`
- `error: string | null`
- `agentTeamConfig: AgentTeamConfig | null` — the resolved agent team config for this role+product
- `showAgentSettings: boolean` — toggle for the agent team settings sub-panel

Layout:
1. **Toggle button**: Small "AI Assistant" button on the right edge of the product editor. Click slides panel open/closed.
2. **Panel** (slides from right, ~300px wide):
   - Header: "AI Suggestion" + product type label + gear icon (opens agent team settings) + close button
   - **Agent Team Settings** (collapsible sub-section, toggled by gear icon):
     - "Agent Team for {roleName}" — dropdown to select agent team (fetches available teams from existing LLM config)
     - "Override for this product" — checkbox + dropdown to set a product-type-specific agent team override
     - On change: call `PUT /api/exercise/scenarios/:id/agent-team-config` to persist the selection
     - Shows current config: "Using: {teamName}" (from role default) or "Using: {teamName} (product override)"
     - "Reset to Role Default" link when a per-product override is active
   - "Generate Suggestion" button (prominent, centered)
   - When generating: spinner + "Analyzing {productType}..."
   - When suggestion available: render blocks:
     - Each block: card with content preview, field label if applicable
     - "Accept" button (applies the suggestion to the corresponding field in the product editor via onApplyBlock callback)
     - "Reject" button (marks block as rejected, greys out)
     - Accepted blocks show green checkmark
     - Rejected blocks show red X and greyed text
   - "Regenerate" button at bottom to get a new suggestion
3. Empty state: "Click 'Generate Suggestion' to get AI-assisted content for this product"

On mount: fetch agent team config via `GET /api/exercise/scenarios/:id/agent-team-config?roleKey={roleKey}` to resolve which agent team is active. Check for product-type-specific override first, fall back to role default, then to STAFF_ROLE_CONFIG default.

Generate handler:
- Call backend: `POST /api/exercise/scenarios/:id/staff-products/:productId/suggest` — this endpoint reads the resolved agent team config (from agent_team_config table with fallback chain: product override -> role default -> STAFF_ROLE_CONFIG default), constructs a prompt from the product's doctrinal context (role, product type, current structured data, current content), and calls the configured LLM. Parse the response into suggestion blocks.
- The endpoint MUST be implemented (no mock fallback). Use the existing `anthropicClient` and LLM config pattern from Phase 14 IPB assembly. The endpoint constructs a role-specific system prompt including the agent team context, sends to the LLM, and returns structured suggestion blocks.

**Backend suggest endpoint** (`backend/src/api/exercise.ts`):
Add `POST /scenarios/:id/staff-products/:productId/suggest`:
1. Load the staff product by ID
2. Resolve agent team config: query agent_team_config for (scenarioId, roleKey, productType) — if no product-specific override, query for (scenarioId, roleKey, NULL productType) — if no role config, use STAFF_ROLE_CONFIG default agentTeamId — if still null, use the default LLM from existing config
3. Load the agent team's LLM config (use existing LLM config pattern from Phase 14 IPB)
4. Construct role-specific system prompt: include role doctrinal focus (from STAFF_ROLE_CONFIG), product type context (from PRODUCT_TYPE_REGISTRY), current structured data, current content
5. Call `anthropicClient` (existing pattern) with the system prompt
6. Parse LLM response into suggestion blocks: `{ blocks: Array<{ id, type, fieldName?, content, status: 'pending' }> }`
7. Return JSON response
