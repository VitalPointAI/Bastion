**StaffProductStore** (`staff-product-store.ts`):
Follow exact patterns from existing stores (e.g., `ipb-store.ts`, `coa-store.ts`):
- `ensureTable()` method that runs the migration SQL on first call (lazy init pattern used by all existing stores)
- `create(input: CreateStaffProduct): Promise<StaffProduct>` — INSERT with crypto.randomUUID() id
- `findById(id: string): Promise<StaffProduct | null>`
- `findByRole(scenarioId: string, roleKey: string): Promise<StaffProduct[]>` — all products for a role in a scenario
- `findByScenario(scenarioId: string): Promise<StaffProduct[]>` — all products across all roles
- `findOne(scenarioId: string, roleKey: string, productType: string): Promise<StaffProduct | null>` — specific product lookup
- `update(id: string, fields: Partial<Pick<StaffProduct, 'title' | 'structured' | 'content'>>): Promise<StaffProduct>` — SET updated_at = NOW()
- `publish(id: string, publishedBy: string): Promise<StaffProduct>` — SET status='published', published_at=NOW(), published_by, increment version
- `delete(id: string): Promise<void>`
- Export singleton: `export const staffProductStore = new StaffProductStore()`

**StaffNotificationService** (`staff-notification-service.ts`):
- Constructor receives staffProductStore reference
- `publishProduct(productId: string, publishedBy: string): Promise<void>`:
  1. Call staffProductStore.publish() to mark published
  2. Compute diff: load previous version (version - 1) snapshot from structured fields — for first publish, diff is "new product"
  3. Query scenario's enabledRoles, filter out source role
  4. INSERT staff_notifications row for each target role with diff_snapshot
  5. Broadcast via MessageBus: `getMessageBus().publish()` on channel `exercise.staff.${scenarioId}` with messageType `staff.product.published` — follow exact MessageBus.publish() signature from existing code (see `CreateMessageInput` type in message-bus.ts)
- `getNotifications(scenarioId: string, targetRole: string): Promise<StaffNotification[]>` — SELECT WHERE scenario_id AND target_role ORDER BY created_at DESC
- `getUnreadCount(scenarioId: string, targetRole: string): Promise<number>` — COUNT WHERE is_read=false
- `markRead(notificationId: string): Promise<void>` — UPDATE is_read=true
- `markIntegrated(notificationId: string): Promise<void>` — UPDATE is_integrated=true
- Export singleton: `export const staffNotificationService = new StaffNotificationService()`

**StrategicImportService** (`strategic-import-service.ts`):
- Import `objectiveStore` from `../strategic/objectives/index.js` and `intentStore` from `../strategic/intent/index.js` — direct store import, NOT HTTP call (per research anti-pattern guidance)
- `importToCommanderWorkspace(scenarioId: string, importedBy: string): Promise<StaffProduct>`:
  1. Query `objectiveStore.findByStatus('APPROVED')` for approved strategic objectives
  2. Query `intentStore.findLatest()` for most recent commander's intent
  3. Build structured JSONB: `{ objectiveCount, objectives: [...], intentId }`
  4. Build content narrative: formatted markdown with objective descriptions and intent text
  5. Check if Commander strategic_guidance product exists for this scenario (via staffProductStore.findOne)
  6. If exists, update; if not, create new product with roleKey='commander', productType='strategic_guidance'
  7. Return the created/updated StaffProduct
- Export singleton: `export const strategicImportService = new StrategicImportService()`

**Update barrel export** (`index.ts`): Add exports for StaffProductStore, StaffNotificationService, StrategicImportService and their singletons.

**REST routes** in `exercise.ts` — add these routes following the existing pattern (try/catch, req.params, req.body, req.headers['x-did']):

Staff Products:
- `GET /scenarios/:id/staff-products` — list all products for scenario (optional ?role= query param filter)
- `GET /scenarios/:id/staff-products/:productId` — get single product
- `POST /scenarios/:id/staff-products` — create product (body: roleKey, productType, title, structured?, content?)
- `PUT /scenarios/:id/staff-products/:productId` — update product (body: title?, structured?, content?)
- `POST /scenarios/:id/staff-products/:productId/publish` — publish product (triggers notification pipeline)
- `DELETE /scenarios/:id/staff-products/:productId` — delete product

Notifications:
- `GET /scenarios/:id/staff-notifications/:role` — list notifications for a role
- `GET /scenarios/:id/staff-notifications/:role/unread-count` — get unread count
- `PUT /scenarios/:id/staff-notifications/read/:notificationId` — mark notification as read
- `PUT /scenarios/:id/staff-notifications/integrate/:notificationId` — mark as integrated

Strategic Import:
- `POST /scenarios/:id/import-strategic-direction` — trigger strategic direction import to Commander workspace

Enabled Roles:
- `PUT /scenarios/:id/enabled-roles` — update scenario's enabled roles (body: { enabledRoles: string[] })

Also update the existing `POST /scenarios` route to accept `enabledRoles` in the body and pass it through to ScenarioStore.create(). Update ScenarioStore to handle the new column in its SELECT and INSERT queries.
