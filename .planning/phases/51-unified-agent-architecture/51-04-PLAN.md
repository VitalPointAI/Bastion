  <name>Task 1: Agent admin API endpoints (including tool assignment)</name>
  <files>backend/src/api/agents.ts</files>
  <action>
    Extend `backend/src/api/agents.ts` (or create a separate `backend/src/api/agent-admin.ts` if the existing file is too large) with admin endpoints. All require auth + admin role check (use existing `requireAuth` and `requireAdmin` middleware from api/admin.ts patterns).

    Endpoints:
    - GET /api/admin/agents — list all agents with health metrics (from agents_v2 columns, not from JSONB). Return: [{agentId, name, status, lastInvocation, successRate, avgResponseTimeMs, validationScore}]
    - GET /api/admin/agents/:agentId — get full agent detail (agent_data JSONB, including tools array)
    - POST /api/admin/agents — create new agent. Body: StandardAgent fields (including tools[]). Uses AgentStore.registerAgent()
    - PUT /api/admin/agents/:agentId — update agent config. Body: partial StandardAgent fields (including tools[]). Uses AgentStore.updateAgent(). The tools field accepts an array of tool IDs to bind to this agent.
    - DELETE /api/admin/agents/:agentId — delete agent. Uses AgentStore.deleteAgent()
    - POST /api/admin/agents/:agentId/activate — activate agent. Check canActivateAgent() health gate first. Update status to 'active'.
    - POST /api/admin/agents/:agentId/deactivate — deactivate agent. Set status to 'inactive'.
    - GET /api/admin/agents/:agentId/memory — list agent's memory entries. Query params: type (knowledge|working|episode), limit, offset. Uses AgentMemoryStore.listEntries()
    - DELETE /api/admin/agents/:agentId/memory/:entryId — delete a memory entry. Uses AgentMemoryStore.forget()
    - POST /api/admin/agents/:agentId/test — send test prompt. Body: {prompt, skill?}. Execute agent via AgentExecutor (from Plan 03's generalized executor), return output + timing. Wrap in try/catch, return error details on failure.
    - GET /api/admin/agents/:agentId/health — get detailed health for one agent
    - GET /api/admin/tools — list all available tools from the tool registry. Returns: [{toolId, name, description, schema}]. Used by the frontend tool assignment UI to populate the available tools list.

    Register the router in the appropriate place (likely api/admin.ts or index.ts where other routers are mounted). Check existing mount patterns.

    Use polling-friendly responses (include Cache-Control: no-cache for health endpoints).
  </action>
