  <action>
Create backend/src/api/jpp.ts as an Express router. Follow the pattern from backend/src/api/design.ts. Register static routes BEFORE parametric routes to prevent Express route shadowing.

**JPP Instance endpoints:**
- GET /api/jpp/:problemSetId -- Get or auto-create JPP instance for problem set (jppStore.getInstanceByProblemSet)
- PUT /api/jpp/:instanceId/step-status -- Update step status (body: { step, status }; calls jppStore.updateStepStatus)

**Step Product endpoints:**
- GET /api/jpp/:instanceId/steps/:step/products -- Get step products (jppStore.getStepProducts)
- POST /api/jpp/:instanceId/steps/:step/products -- Save step product (jppStore.saveStepProduct)
- GET /api/jpp/:instanceId/parent-products -- Get parent JPP products for inheritance

**E-W-M Linkage endpoints:**
- GET /api/jpp/:instanceId/ewm -- Get all linkages (ewmStore.getLinkagesByInstance)
- POST /api/jpp/:instanceId/ewm -- Create linkage (ewmStore.createLinkage)
- DELETE /api/jpp/:instanceId/ewm/:linkageId -- Delete linkage
- PUT /api/jpp/:instanceId/ewm/:linkageId/allocation -- Update allocation
- GET /api/jpp/:instanceId/ewm/gaps -- Get gap analysis (ewmStore.findGaps)
- GET /api/jpp/:instanceId/ewm/summary -- Get E-W-M summary counts

**Entity Resolution endpoints** (thin wrappers around existing entity tools):
- GET /api/entities/search?q=term&type=nation -- entityToolHandlers.search_entities
- POST /api/entities/merge -- entityToolHandlers.merge_entities
- POST /api/entities/alias -- entityToolHandlers.create_entity_alias
- GET /api/entities/:entityId/references -- entityToolHandlers.get_entity_references

All routes use requireAuth middleware (check how design.ts applies it). Export router as jppRouter. Register in backend/src/api/index.ts (or wherever routers are mounted).

Create 4 frontend service files following the pattern from frontend/src/lib/design-service.ts (class with private fetch wrapper using credentials: 'include', X-DID header).

**jpp-service.ts (JppService):**
- `getInstance(problemSetId)`: GET /api/jpp/:problemSetId -> JPPInstance
- `updateStepStatus(instanceId, step, status)`: PUT /api/jpp/:instanceId/step-status
- `getStepProducts(instanceId, step)`: GET /api/jpp/:instanceId/steps/:step/products -> JPPStepProduct[]
- `saveStepProduct(instanceId, step, product)`: POST /api/jpp/:instanceId/steps/:step/products
- `getParentProducts(instanceId)`: GET /api/jpp/:instanceId/parent-products
- Export singleton: `export const jppService = new JppService();`

**ewm-service.ts (EwmService):**
- `getLinkages(instanceId)`: GET /api/jpp/:instanceId/ewm -> EWMLinkage[]
- `createLinkage(instanceId, data)`: POST /api/jpp/:instanceId/ewm
- `deleteLinkage(instanceId, linkageId)`: DELETE /api/jpp/:instanceId/ewm/:linkageId
- `updateAllocation(instanceId, linkageId, pct)`: PUT /api/jpp/:instanceId/ewm/:linkageId/allocation
- `getGaps(instanceId)`: GET /api/jpp/:instanceId/ewm/gaps -> EWMGap[]
- `getSummary(instanceId)`: GET /api/jpp/:instanceId/ewm/summary
- Export singleton: `export const ewmService = new EwmService();`

**osint-service.ts (OsintService):**
- `getFeeds(problemSetId)`: GET /api/osint/feeds/:problemSetId
- `createFeed(data)`: POST /api/osint/feeds
- `getRecentEvents(problemSetId, limit?)`: GET /api/osint/events?problemSetId=X&limit=20 (use existing OSINT event API if available, else add endpoint)
- `getEventsByRelevance(problemSetId, objectiveIds)`: GET relevant OSINT events for specific objectives
- Export singleton: `export const osintService = new OsintService();`

**entity-service.ts (EntityService):**
- `searchEntities(query, type?)`: GET /api/entities/search?q=term&type=type
- `mergeEntities(sourceIds, targetId)`: POST /api/entities/merge
- `createAlias(canonicalId, alias, source)`: POST /api/entities/alias
- `getEntityReferences(entityId)`: GET /api/entities/:entityId/references
- Export singleton: `export const entityService = new EntityService();`

All services: use credentials: 'include' for cookie auth, include X-DID header from stored DID, handle errors consistently (throw on non-OK responses).
