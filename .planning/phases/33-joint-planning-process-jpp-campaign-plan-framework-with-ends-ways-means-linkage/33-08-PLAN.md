Create EWMTree.tsx adapting the CoGTree SVG pattern for E-W-M visualization.

Props:
```
interface EWMTreeProps {
  jppInstanceId: string;
  problemSetId: string;
  ends: EWMEnd[];       // Strategic objectives
  ways: EWMWay[];       // LOEs and COAs
  means: EWMMean[];     // Forces and resources
  linkages: EWMLinkage[];
  gaps: EWMGap[];
  onCreateLinkage: (endId: string, wayId: string, wayType: string) => void;
  onDeleteLinkage: (linkageId: string) => void;
  onUpdateAllocation: (linkageId: string, pct: number) => void;
  readOnly?: boolean;
}
```

Layout: 3-level vertical tree (adapted from CoGTree pattern):
- **Level 0 (top)**: Ends -- Strategic Objectives (red nodes, #ef4444)
- **Level 1 (middle)**: Ways -- LOEs (blue, #3b82f6) and COAs (indigo, #6366f1)
- **Level 2 (bottom)**: Means -- Forces/Resources (green, #10b981)

Node rendering:
- Each node: rounded rect with label, truncated to ~40 chars
- Ends nodes: show priority badge (CRITICAL=red, HIGH=orange, MEDIUM=yellow, LOW=gray)
- Ways nodes: show type badge (LOE vs COA)
- Means nodes: show allocation percentage bar
- Gap nodes (from gaps array): amber glow border, pulsing animation

Edge rendering:
- SVG paths connecting linked nodes (Ends->Ways, Ways->Means)
- Edge width proportional to allocation percentage for Ways->Means
- Dashed edges for suggested (AI-recommended) linkages
- Click edge to delete linkage

Interaction:
- Click node to select (highlight + show detail panel)
- Drag from one level to adjacent level to create linkage (onCreateLinkage)
- Right-click edge to delete (onDeleteLinkage)
- Click allocation percentage on edge to edit (onUpdateAllocation)

Use CoGTree's flattenTree and computePositions patterns for node layout. SVG for edges, HTML overlays for nodes (same hybrid approach as CoGTree).

If CoGTree pattern is too complex to adapt fully, fall back to a simpler flexbox-based tree layout with:
- 3 horizontal rows (Ends, Ways, Means)
- Cards for nodes
- Canvas or SVG lines connecting them
- Drag handles for creating connections

**EWMSankey.tsx:**
Read-only analytical Sankey diagram using recharts Sankey component.

Props:
```
interface EWMSankeyProps {
  ends: EWMEnd[];
  ways: EWMWay[];
  means: EWMMean[];
  linkages: EWMLinkage[];
}
```

Implementation:
1. Build nodes array: [...ends.map(e => ({ name: e.description })), ...ways.map(w => ({ name: w.name })), ...means.map(m => ({ name: m.name }))]
2. Build links array with NUMERIC INDICES (critical -- recharts Sankey uses array indices, not IDs):
   - For each linkage where wayType exists: find end index (endOffset + indexOf), find way index (wayOffset + indexOf). Push { source: endIdx, target: wayIdx, value: 1 }.
   - For each linkage where meanId exists: find way index, find mean index (meanOffset + indexOf). Push { source: wayIdx, target: meanIdx, value: linkage.allocationPct || 1 }.
3. Render:
   ```
   <Sankey data={{ nodes, links }} width={960} height={500} nodeWidth={10} nodePadding={30}
     margin={{ top: 20, right: 20, bottom: 20, left: 20 }}
     node={<CustomSankeyNode />}  // Color by level: red/blue/green
     link={<CustomSankeyLink />}  // Hover highlights full path
   >
     <Tooltip content={<EWMTooltip />} />
   </Sankey>
   ```
4. Custom node component: color based on position (ends=red, ways=blue, means=green)
5. Custom tooltip: show node name, connected nodes, allocation details
6. Hover on any node/link highlights the full connected path (source-to-sink)
