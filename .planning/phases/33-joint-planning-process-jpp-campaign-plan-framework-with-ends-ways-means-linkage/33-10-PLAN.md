**document-templates.ts — Doctrinal document structure definitions:**

Define template structures for each plan type:
- `CampaignPlanTemplate`: Title page metadata, strategic context section, campaign objectives, phasing construct, LOE-to-objective mapping, annexes
- `OPLANTemplate`: Classification banner, references, 5-paragraph order (situation, mission, execution, sustainment, command & signal), annexes A-Z
- `CONPLANTemplate`: Abbreviated OPLAN — situation, mission, execution concept (no detailed task org), logistics summary
- `OPORDTemplate`: Same structure as OPLAN but marked as directive (execution-immediate), includes time-sensitive fields (DTG, effective time)

Each template:
- Maps sections to the OperationalPlan/FiveParagraphOrder/Annex types from planning/types.ts
- Includes section ordering, required vs optional sections, and classification marking placeholders
- Defines a `renderSections(plan: OperationalPlan): DocumentSection[]` function that extracts and orders content from the plan data

**document-generator.ts — Server-side rendering engine:**

```typescript
type DocumentFormat = 'pdf' | 'docx';

interface GenerateOptions {
  planId: string;
  planType: PlanType;
  format: DocumentFormat;
  classification?: string;
  includeAnnexes?: string[]; // subset of annexes, default all
}

async function generatePlanDocument(options: GenerateOptions): Promise<Buffer>
```

Implementation:
- Fetch the OperationalPlan from the database by planId
- Select the correct template based on planType
- Render sections in doctrinal order using the template's renderSections
- For PDF: use a lightweight HTML-to-PDF approach (render to HTML string, convert with a headless renderer or pdfkit)
- For DOCX: use the `docx` npm package (already available or add as dependency) to build a Word document with proper heading styles, tables for task org, and page breaks between major sections
- Include: cover page with plan name/DTG/classification, table of contents, 5-paragraph body, annexes as appendix sections
- Return the document as a Buffer

**document-routes.ts — REST API endpoints:**

Mount on the existing planning router.

Endpoints:
1. `POST /api/planning/:problemSetId/documents/generate`
   - Body: { planId, format, includeAnnexes? }
   - Returns: document as file download (application/pdf or application/vnd.openxmlformats)

2. `POST /api/planning/:problemSetId/documents/versions`
   - Body: { planId, status: 'draft' | 'coordinating_draft' | 'final', notes? }
   - Creates a version snapshot of the current plan state
   - Returns: { versionId, status, createdAt, createdBy }

3. `GET /api/planning/:problemSetId/documents/:planId/versions`
   - Returns: array of version records with status, timestamp, author, notes

4. `POST /api/planning/:problemSetId/documents/distribute`
   - Body: { planId, versionId, targetProblemSetIds: string[] }
   - Copies the approved plan version as higher HQ guidance to each target problem set
   - Creates a distribution record
   - Returns: { distributionId, targets: [{ problemSetId, status }] }

5. `GET /api/planning/:problemSetId/documents/:planId/distributions`
   - Returns: distribution history (who received what version, when)
