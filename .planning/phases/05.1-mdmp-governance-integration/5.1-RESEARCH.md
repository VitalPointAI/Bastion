# Phase 5.1 Research: MDMP Governance Integration

## Research Source

This phase was designed through a comprehensive analysis of the Military Decision
Making Process (MDMP) checklist for Theater Army planning at the ASCC level,
evaluated against Bastion's existing architecture. The full specification is in
`.planning/mdmp-governance/`.

## Key Research Artifacts

|------|---------|
| `mdmp-governance/mdmp-types.ts` | Complete TypeScript data model: 5 authority levels, 22 activity categories, 22 agent roles, safety matrix, 9 governance invariants |

## Key Design Decisions

### Five-Tier Authority Model

Extends the original checklist's binary AI/Human split:

| Level | Control Posture | Bastion AutonomyLevel | Usage |
|-------|-----------------|----------------------|-------|
| AI_AUTONOMOUS | FULLY_DELEGATED | FullyDelegated (new) | Data pipelines, validation, monitoring (~20%) |
| AI_PRIMARY | HUMAN_OUT_OF_LOOP | Autonomous | Pattern recognition, sustainment (~8%) |
| HYBRID_AI_LED | HUMAN_ON_LOOP | SemiAutonomous | Analysis, COA gen, wargaming (~37%) |
| HYBRID_HUMAN_LED | HUMAN_IN_LOOP | NotAutonomous + AI | Problem framing, intent, coalition (~8%) |
| HUMAN_ONLY | HUMAN_EXCLUSIVE | NotAutonomous, no AI | Authority, ethics, risk (~27%) |

### Safety Matrix

Enforced at smart contract level. Categories map to permitted authority ranges:

- **AI Autonomous permitted (4 categories)**: DATA_AGGREGATION, VALIDATION_CONSISTENCY, MONITORING, META_COGNITIVE
- **Human Only locked (3 categories)**: AUTHORITY_DECISION, ETHICAL_LEGAL, RISK_JUDGMENT
- **All others**: Hybrid range with ceiling and floor per category

### Nine Governance Invariants

1. STRIKE_AUTHORIZATION - Always NotAutonomous (existing, unchanged)
2. MDMP_PHASE_PROGRESSION - Gates must be satisfied before advancing
3. ASSUMPTION_ACCOUNTABILITY - Explicit human acceptance required
4. RED_TEAM_COMPLETENESS - All challenges addressed before phase transition
5. UNCERTAINTY_TRANSPARENCY - AI outputs must include confidence intervals
6. ASSUMPTION_INVALIDATION_TRIGGER - Critical invalidation triggers replanning
7. COMMANDER_GUIDANCE_TRACEABILITY - Guidance recorded and linked
8. FULLY_DELEGATED_SCOPE - Restricted to 4 deterministic categories
9. SAFETY_MATRIX_ENFORCEMENT - Authority must comply with safety matrix

### New Smart Contract Modules

Three new modules under `near-contracts/src/mdmp/`:

1. **types.rs** - MDMPPhase, ActivityCategory enums with safety methods
2. **assumptions.rs** - AssumptionRegistry with lifecycle tracking
3. **workflow.rs** - MDMPWorkflow with phase gates and transition enforcement

Plus extensions to existing `dao/types.rs`, `dao/execution.rs`, `dao/voting.rs`.

### New AI Agents (Priority 1 for this phase)

| Agent | Purpose | Category |
|-------|---------|----------|
| Assumption Auditor | Surface/track planning assumptions | Core MDMP |
| Orders Validator | Validate orders format/consistency | Core MDMP |

## Backward Compatibility

All changes to existing contracts are additive:
- New `FullyDelegated` variant added to `AutonomyLevel` (no existing variant changed)
- 5 new `ProposalKind` variants (no existing variant changed)
- New `mdmp/` contract module (no existing modules modified)
- Default role permissions unchanged
- No data migration required
