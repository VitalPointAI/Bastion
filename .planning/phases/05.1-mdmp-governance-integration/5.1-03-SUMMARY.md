## Decisions Made

**Storage key pattern:** Used BorshStorageKey enum (WorkflowStorageKey) instead of byte slice prefixes for type safety and NEAR SDK 5.x compatibility.

**Gate satisfaction tracking:** Gates stored with composite keys (`mission_id:phase:gate_id`) for efficient lookup without nested collections.

**Error reporting:** `validate_phase_complete` returns `Result<(), Vec<String>>` so callers know exactly which gates are unsatisfied (not just boolean).

**Safety as pure function:** `validate_autonomy_assignment` implemented as pure function taking references for reusability across different proposal validation contexts.

## Issues Encountered

**NEAR SDK 5.x storage key requirements:** Initial implementation used byte slice prefixes (`b"mdmp_phases"`) which failed compilation. Fixed by defining BorshStorageKey enum per NEAR SDK 5.x requirements. This is a known pattern from existing codebase (DAOStorageKey, RoleStorageKey, etc.).
