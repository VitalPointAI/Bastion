# Plan 32-11: Client-Side Discovery Bridge

## Objective
Enable the user's browser/device to discover nearby resources using Web Bluetooth, Web Serial, and network APIs, then relay those discoveries back to the Bastion backend for onboarding through the standard pipeline.

## Context
Scenario 2 requires discovery from the computer or device accessing Bastion (not the server). Modern browsers expose Web Bluetooth API and Web Serial API for local device scanning. Discovered devices are reported to the backend via POST /client-discovery (created in 32-10) where they enter the normal onboarding pipeline with origin='client'.

## Tasks

### Task 1: Client Discovery Hook & API Client Extension
**What:** Create useClientDiscovery hook that uses navigator.bluetooth.requestDevice() for BLE scanning and navigator.serial.requestPort() for serial device detection. Reports each discovery to backend via discoveryService.reportClientDiscovery(). Add reportClientDiscovery() and scan target methods to the frontend API service. Track browser API availability.

**Files:**
- `frontend/src/hooks/useClientDiscovery.ts` — Hook with startBluetoothScan(), startSerialScan(), discoveries state, availability checks for Web Bluetooth/Serial APIs
- `frontend/src/lib/discovery-service.ts` — Add reportClientDiscovery(), getScanTargets(), addScanTarget(), updateScanTarget(), removeScanTarget() methods

**Acceptance:**
- [ ] useClientDiscovery exports startBluetoothScan, startSerialScan, discoveries, isBluetoothAvailable, isSerialAvailable
- [ ] Each browser-discovered device is reported to POST /client-discovery
- [ ] Graceful degradation when browser APIs unavailable (shows message, doesn't crash)
- [ ] Frontend API service has scan target CRUD methods

### Task 2: Client Discovery Panel Component
**What:** Create ClientDiscoveryPanel that shows which browser APIs are available, provides scan trigger buttons, displays locally-discovered devices with relay status, and indicates which devices have been sent to the backend pipeline.

**Files:**
- `frontend/src/components/cop/ClientDiscoveryPanel.tsx` — Panel with API availability indicators, scan buttons, discovered device list with relay status badges

**Acceptance:**
- [ ] Shows Web Bluetooth / Web Serial availability with green/red indicators
- [ ] Scan buttons trigger browser permission dialogs
- [ ] Discovered devices listed with name, type, relay status (pending/sent/failed)
- [ ] Follows ui-brand.md styling (slate-900 bg, Fira Code, military aesthetic)
