# Plan 32-12: Legal Consent Flow & Network Targets Management UI

## Objective
Require explicit legal acknowledgement before scanning any network, with jurisdiction-aware legal text. Create a network targets management page where users configure remote scan addresses with required legal consent per target.

## Context
Before a user connects to or scans any network (server-local, client-side, or remote target), they must be reminded of legal issues specific to that network context and confirm acceptance. This protects operators from unauthorized network access violations (CFAA, CMA, EU Directive 2013/40/EU, military UCMJ Art. 92 considerations).

Legal consent is tracked per-user, per-target, per-session. Expired consent requires re-acknowledgement.

## Tasks

### Task 1: Legal Consent Backend (Types, Storage, Validation, API)
**What:** Create legal-consent.ts with consent types, legal text templates per context (server-local, client-device, remote-network, military-network), and consent validation logic. Add consent_records table to discovery-store. Add REST endpoints for recording consent and checking consent status. Require valid consent before starting any scan.

**Files:**
- `backend/src/discovery/legal-consent.ts` — LegalConsentService with getRequiredConsent(origin, targetAddress?), recordConsent(), validateConsent(), legal text templates
- `backend/src/discovery/discovery-store.ts` — Add consent_records table (id, user_did, consent_type, target_id, legal_text_hash, accepted_at, expires_at, ip_address), CRUD methods
- `backend/src/discovery/discovery-router.ts` — GET /legal-consent/:origin (get required text), POST /legal-consent (record acceptance), modify POST /start to validate consent
- `backend/src/discovery/index.ts` — Export LegalConsentService

**Acceptance:**
- [ ] 4 legal text templates: server_local, client_device, remote_network, military_network
- [ ] consent_records table tracks per-user, per-target consent with expiry
- [ ] POST /start returns 451 (Unavailable For Legal Reasons) if consent not recorded
- [ ] GET /legal-consent/:origin returns required legal text and consent status
- [ ] POST /legal-consent records acceptance with timestamp and IP

### Task 2: Network Targets Page & Legal Consent Dialog
**What:** Create NetworkTargetsPage component for managing remote scan targets (add/edit/remove addresses, enable/disable, view consent status). Create LegalConsentDialog modal that displays jurisdiction-appropriate legal text and requires explicit acceptance before any scan can start. Wire into existing discovery components.

**Files:**
- `frontend/src/components/cop/NetworkTargetsPage.tsx` — Full CRUD page for scan targets with address input, port range, protocol selector, enable toggle, consent status badge per target
- `frontend/src/components/cop/LegalConsentDialog.tsx` — Modal dialog showing legal text, requiring checkbox acknowledgement + confirm button. Shown before scan start from any origin. Records consent via POST /legal-consent
- `frontend/src/lib/discovery-service.ts` — Add getLegalConsent(), recordLegalConsent() methods

**Acceptance:**
- [ ] NetworkTargetsPage shows table of configured remote targets with add/edit/delete
- [ ] Each target shows consent status (valid/expired/none) with colored badge
- [ ] LegalConsentDialog shows before ANY scan start (server, client, or remote)
- [ ] Dialog text varies by origin type (local hardware vs browser device vs remote network)
- [ ] Consent must be checked (checkbox) before confirm button enables
- [ ] After consent, scan proceeds normally; without consent, scan is blocked
- [ ] Military network text includes UCMJ reference
- [ ] Follows ui-brand.md styling
