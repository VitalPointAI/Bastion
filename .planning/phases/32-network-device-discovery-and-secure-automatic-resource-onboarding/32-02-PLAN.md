  <name>Task 1: Add CommandAdapter facet to ResourcePlugin and hot-load support to plugin-loader</name>
  <files>backend/src/resources/plugins/base-plugin.ts, backend/src/resources/plugins/plugin-loader.ts</files>
  <action>
**base-plugin.ts** — Add CommandAdapter types and extend ResourcePlugin:

1. Add `BastionCommand` type: 'move' | 'report' | 'configure' | 'execute' (use const object pattern)
2. Add `CommandResponse` interface: success (boolean), command (BastionCommand | string), data (Record<string, unknown>), timestamp (number)
3. Add `CommandAdapter` interface:
   - `readonly supportedCommands: BastionCommand[]`
   - `translateCommand(command: BastionCommand, params: Record<string, unknown>): Promise<Buffer | string>`
   - `parseResponse(raw: Buffer | string): Promise<CommandResponse>`
   - `sendNative?(command: string, payload: unknown): Promise<unknown>` — native command escape hatch
4. Add optional `commandAdapter?: CommandAdapter` property to the existing `ResourcePlugin` interface
5. Export all new types: BastionCommand, CommandResponse, CommandAdapter

Existing plugins remain unaffected since commandAdapter is optional.

**plugin-loader.ts** — Extend with generated/ directory and file watching:

1. After loading static plugins from the current directory, also load from `generated/` subdirectory using the same `-plugin.(ts|js)` convention
2. Create `generated/` directory if it doesn't exist (use `mkdir` with recursive:true)
3. Add `watchForNewPlugins(onNewPlugin: (plugin: ResourcePlugin) => void): void` export:
   - Uses `fs.watch` on the `generated/` directory
   - On new `-plugin.js` file: dynamic import, validate it has `category` string property, call onNewPlugin callback
   - Debounce watch events (300ms) to handle USB-style rapid file creation
   - Log all plugin load attempts for audit trail
4. Add `loadFromDirectory(dir: string, plugins: Map<string, ResourcePlugin>)` helper to avoid code duplication between static and generated loading
