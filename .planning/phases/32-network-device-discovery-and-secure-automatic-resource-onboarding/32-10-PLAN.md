# Plan 32-10: Discovery Origin Model & Remote Network Scan Targets

## Objective
Extend the discovery subsystem with a tri-origin model (server, client, remote) so scanning can happen from the Bastion server hardware, from the user's browser/device, or against user-specified remote network addresses. Add scan target CRUD for remote addresses.

## Context
Currently all scanning runs server-side with a flat `scope` string. The three discovery scenarios require:
1. **Server origin** (existing) — scanners run on Bastion host hardware
2. **Client origin** (new) — browser reports discoveries back via WebSocket
3. **Remote origin** (new) — Bastion probes user-specified network addresses/ranges

## Tasks

### Task 1: Discovery Origin Types & Scan Target Persistence
**What:** Add `DiscoveryOrigin` const object to types.ts. Add `ScanTarget` interface for remote network addresses (id, address, port range, protocol, label, enabled, legal consent status). Add `scan_targets` table to discovery-store with full CRUD. Extend `DiscoveredDevice` with `origin` field. Extend `discovered_devices` table with `origin` and `source_target_id` columns.

**Files:**
- `backend/src/discovery/types.ts` — Add DiscoveryOrigin, ScanTarget, extend DiscoveredDevice
- `backend/src/discovery/discovery-store.ts` — Add scan_targets table creation, CRUD methods (addScanTarget, listScanTargets, updateScanTarget, removeScanTarget), add origin column to discovered_devices

**Acceptance:**
- [ ] DiscoveryOrigin = { server, client, remote } const object
- [ ] ScanTarget interface with address, portRange, protocol, label, enabled, legalConsentAt fields
- [ ] scan_targets table with CRUD in discovery-store
- [ ] discovered_devices table gains origin and source_target_id columns

### Task 2: Origin-Aware Discovery Service & Scan Target REST API
**What:** Extend DiscoveryService.start() to accept an origin parameter. When origin is 'remote', iterate enabled scan targets and probe each address. Add REST endpoints for scan target management. Add client-reported discovery ingestion endpoint. Export new types from barrel.

**Files:**
- `backend/src/discovery/discovery-service.ts` — Extend start() with origin param, add startRemoteScan(), add ingestClientDiscovery() for receiving browser-reported devices
- `backend/src/discovery/discovery-router.ts` — Add CRUD endpoints: GET/POST/PUT/DELETE /scan-targets, POST /client-discovery for browser-reported devices, extend POST /start with origin field
- `backend/src/discovery/index.ts` — Export new types

**Acceptance:**
- [ ] POST /start accepts { origin: 'server' | 'client' | 'remote', scope? }
- [ ] GET /scan-targets returns configured remote addresses
- [ ] POST /scan-targets adds a new target (requires legal consent timestamp)
- [ ] PUT /scan-targets/:id updates target config
- [ ] DELETE /scan-targets/:id removes a target
- [ ] POST /client-discovery accepts browser-reported device events with origin='client'
