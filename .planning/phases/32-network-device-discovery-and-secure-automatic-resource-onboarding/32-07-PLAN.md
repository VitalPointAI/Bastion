  <files>backend/src/discovery/em-spectrum/em-types.ts, backend/src/discovery/em-spectrum/em-collector.ts</files>
  <action>
**em-types.ts** — EM spectrum domain types:

1. `EMBand` const: 'bluetooth' (2.4GHz), 'wifi_2g' (2.4GHz), 'wifi_5g' (5GHz), 'vhf' (30-300MHz), 'uhf' (300-3000MHz), 'hf' (3-30MHz), 'satcom' (L/S/C/Ku/Ka bands), 'unknown'
2. `EMSignalEntry`: band (EMBand), frequencyMHz (number), signalStrengthDbm (number), sourceIdentifier (string, device rawId or 'self'), sourceType ('discovered' | 'self' | 'unknown'), timestamp (number), transportType? (TransportType)
3. `EMFootprint`: entries (EMSignalEntry[]), activeTransmissions (EMSignalEntry[] — Bastion's own emissions), lastUpdated (number)
4. `EMDataSource` interface (clean extension point for future SDR):
   - `readonly sourceType: 'inferred' | 'sdr'`
   - `getSignals(): EMSignalEntry[]`
   - `start(): void`
   - `stop(): void`
5. `EMSnapshot`: timestamp, environmentSignals (EMSignalEntry[]), ownEmissions (EMSignalEntry[]), bandSummary (Record<EMBand, { count: number; avgStrength: number }>)

**em-collector.ts** — Aggregates EM data from scanner events:

1. `EMCollector` class:
   - Maintains sliding window of EMSignalEntry (last 5 minutes, configurable)
   - `ingestDiscoveryEvent(event: DiscoveryEvent): void` — Extract EM signal data:
     - BLE: band='bluetooth', freq=2402-2480 (derive from channel if available), strength from RSSI
     - WiFi: band='wifi_2g' or 'wifi_5g' (infer from channel/frequency in rawData), strength from signal
     - TAK: band based on configured RF frequency (VHF/UHF typically)
     - USB: no EM contribution (wired)
   - `recordOwnEmission(band: EMBand, frequencyMHz: number, powerDbm: number): void` — Track Bastion's own transmissions:
     - When BLE scanner is actively scanning, record bluetooth emission
     - When WiFi scanner sends mDNS/SSDP queries, record wifi emission
     - When TAK scanner is listening (passive) vs transmitting (active), record accordingly
   - `getSnapshot(): EMSnapshot` — Return current EM picture with band summaries
   - `getOwnFootprint(): EMSignalEntry[]` — Return only Bastion's own emissions (OPSEC view)

2. The collector automatically ingests events by subscribing to MessageBus `discovery.device.discovered` channel.

3. Own-emission tracking is updated when scanners start/stop (DiscoveryService publishes scanner lifecycle events).

4. Tier 1 only (inferred from scanners). Tier 2 (SDR) implemented via EMDataSource interface — add SDR source later without refactoring.

<task type="auto">
  <name>Task 2: Create network topology mapper with configurable network hopping</name>
  <files>backend/src/discovery/network-topology.ts</files>
  <action>
Create `NetworkTopology` class:

1. **Data structures:**
   - `TopologyNode`: id (string), type ('device' | 'network' | 'bastion'), displayName, transportType? (TransportType), deviceDid?, trustTier? (ResourceTrustTier), metadata (Record<string, unknown>)
   - `TopologyEdge`: sourceId, targetId, connectionType ('direct' | 'bridged' | 'discovered'), transportType, signalStrength?, latency?, hopCount (number)
   - `TopologyNetwork`: id, name?, cidr?, gatewayNodeId?, hopDepth (how many hops from Bastion)
   - `TopologyGraph`: nodes (Map<string, TopologyNode>), edges (TopologyEdge[]), networks (Map<string, TopologyNetwork>)

2. **Core methods:**
   - `addDevice(device: DiscoveredDevice): void` — Add device as node, create edge to discovery network
   - `addConnection(sourceId: string, targetId: string, edge: Omit<TopologyEdge, 'sourceId' | 'targetId'>): void`
   - `removeDevice(deviceId: string): void` — Remove node and all its edges
   - `getGraph(): TopologyGraph` — Return full topology for visualization
   - `getSubgraph(networkId: string): TopologyGraph` — Return nodes/edges for a specific network
   - `getPath(fromId: string, toId: string): TopologyNode[]` — BFS shortest path between nodes

3. **Network hopping:**
   - `hoppingEnabled: boolean` — default false per user decision ("Disabled by default")
   - `maxHopDepth: number` — configurable admin setting (default 3)
   - `async discoverAdjacentNetworks(bridgeDeviceId: string): Promise<TopologyNetwork[]>`:
     - Verify bridge device is at 'participant' or 'autonomous' trust tier (reject observers)
     - Check current hop depth against maxHopDepth
     - Use bridge device's command adapter to scan its accessible networks
     - Create new TopologyNetwork entries for discovered adjacent networks
     - Trigger DiscoveryService to scan new networks through the bridge
     - Apply global allowlist/blocklist to newly discovered networks (per Phase 26 inheritance)
   - `getHopChain(deviceId: string): TopologyNode[]` — Show the chain of bridge devices from Bastion to a given device

4. **DAO governance for hopping:**
   - Each newly discovered network via hopping inherits global allowlist/blocklist
   - PS-level overrides can restrict hopping scope (prevent hopping into specific networks)

5. **Topology persistence:**
   - In-memory graph with periodic snapshot to PostgreSQL (JSON column in a `network_topology` table)
   - Table: id, problem_set_id, graph_data (JSONB), updated_at
   - Load from DB on initialization, save on significant changes (new network discovered, device added/removed)

6. **Bastion self-node:**
   - Always includes a 'bastion' node at the center of the topology
   - All directly connected devices have edges to the bastion node
   - Hop count starts at 0 for bastion, 1 for direct devices, 2+ for hopped
