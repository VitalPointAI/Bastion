       ```python
       import re
       import uuid
       from datetime import datetime
       from typing import Optional
       from models import MissionJSON, MissionParams

       TEMPLATES = [
           (re.compile(r"recon|reconn|surveil|survey|sweep area", re.I), "recon_area"),
           (re.compile(r"find|search|locate|look for|identify", re.I), "visual_search"),
           (re.compile(r"watch|overwatch|monitor|observe|surveil.*position", re.I), "overwatch"),
           (re.compile(r"resupply|deliver|supply|logistics", re.I), "resupply_route"),
           (re.compile(r"patrol|sweep perimeter|circuit", re.I), "patrol_route"),
           (re.compile(r"engage|intercept|neutralize", re.I), "find_engage"),
       ]

       def template_translate(text: str, robot_id: str, issued_by: str) -> Optional[MissionJSON]:
           if not text or not text.strip():
               return None
           for pattern, command in TEMPLATES:
               if pattern.search(text):
                   return MissionJSON(
                       mission_id=str(uuid.uuid4()),
                       robot_id=robot_id,
                       command=command,
                       params=MissionParams(),
                       issued_by=issued_by,
                       timestamp=datetime.utcnow(),
                       auth_token="",
                   )
           return None
       ```

    Ensure regex order matters — more specific patterns first (e.g., "resupply" before generic "supply"). Test that "survey" matches recon_area and not something else.

         - `async translate(self, text: str, robot_id: str, issued_by: str) -> List[MissionJSON]`:
           - If not available, fall back to template_translate (import from fallback)
           - Call instructor client.chat.completions.create with response_model=List[MissionJSON]
           - Set robot_id and issued_by on all returned missions
           - Wrap in try/except — on any error, fall back to template_translate
           - Run LLM call in asyncio.to_thread to avoid blocking
         - Property `is_available` -> bool
       - Module-level `translate_intent(text, robot_id, issued_by)` convenience function that uses config to construct translator

    2. Create `robot/intent/decomposer.py`:
       - `decompose_objective(objective: str, robot_id: str, issued_by: str, translator: Optional[IntentTranslator] = None) -> List[MissionJSON]`:
         - For simple objectives (single sentence, no "and"/"then"), delegate directly to translator or template_translate
         - For complex objectives (contains "and"/"then"/"followed by"/numbered steps):
           - Split into sub-objectives
           - Translate each independently
           - Return combined list in order
         - If translator is available, use it for the full objective (LLM handles decomposition natively)
         - If offline, use the sentence-splitting heuristic + template_translate for each part
       - This is intentionally simple — the LLM does the heavy lifting when available; the local fallback just splits on conjunctions

    Note: Cloud translator tests are NOT automated (require API keys). The fallback path is tested in Task 1. Document in a comment that integration testing of the cloud path requires OPENAI_API_KEY or ANTHROPIC_API_KEY env var.
