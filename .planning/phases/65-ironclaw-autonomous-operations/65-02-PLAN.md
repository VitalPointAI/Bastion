<task type="auto">
  <name>Task 1: Create intelligence MCP tool handlers</name>
  <files>backend/src/mcp/tools/intelligence.ts</files>
  <action>
Create `backend/src/mcp/tools/intelligence.ts` following the same pattern as `backend/src/mcp/tools/knowledge.ts` (read it first to match the export pattern).

Define 7 new MCP tools as MCPToolDefinition[] exported as `intelligenceTools`:

1. **`bastion.intel.web_search`** (riskLevel: 'medium')
   - Input: `{ query: string, max_results?: number }` (required: query)
   - Handler: Import `performWebSearch` from `../../doc-intelligence/web-search.js`, call it, return results as JSON
   - Description: "Search the web via SearXNG for intelligence on a topic. Returns search results with titles, URLs, and snippets."

2. **`bastion.intel.create_research_event`** (riskLevel: 'medium')
   - Input: `{ problem_set_id: string, title: string, content: string, source_url?: string, source_name?: string }`
   - Handler: Import `osintEventStore` from `../../graph/osint/event-store.js`, call `createEvent()` with the input mapped to an OSINTEvent (set type='research', feed_id='ironclaw-autonomous')
   - Description: "Create a synthetic OSINT event from autonomous research findings. The event enters the standard ingestion pipeline."

3. **`bastion.intel.process_osint_event`** (riskLevel: 'medium')
   - Input: `{ event_id: string, problem_set_id: string }`
   - Handler: Fetch the event from osintEventStore, then call `processOSINTEventThroughAgents()` with a synthetic feed config
   - Description: "Trigger the OSINT specialist agent pipeline to process an event, extracting entities, relationships, and tensions."

4. **`bastion.intel.detect_conflicts`** (riskLevel: 'low')
   - Input: `{ problem_set_id: string, entity_name?: string }`
   - Handler: Import `brainStore` from `../../brain/brain-store.js`, query for contradicting relationships and tensions. Look for relationships with opposing sentiment or conflicting facts about the same entity. Return conflicts as array of `{ entity, claim_a, claim_b, source_a, source_b }`.
   - Description: "Scan the knowledge graph for contradictions, conflicting claims, or opposing intelligence about entities."

5. **`bastion.intel.draft_situation_assessment`** (riskLevel: 'low')
   - Input: `{ problem_set_id: string, focus_area?: string, time_window_hours?: number }`
   - Handler: Gather recent OSINT events, graph changes, and active PIRs for the problem set within the time window (default 24h). Compile into a structured situation summary with sections: key developments, intelligence gaps, recommended actions. Return as structured JSON (NOT as LLM-generated text -- Ironclaw itself will synthesize).
   - Description: "Gather raw intelligence data for a situation assessment. Returns structured data that Ironclaw synthesizes into a narrative."

6. **`bastion.autonomous.log_activity`** (riskLevel: 'low')
   - Input: `{ problem_set_id: string, activity_type: string, severity: string, summary: string, detail?: object }`
   - Handler: Import `autonomousActivityStore` from `../../ironclaw/autonomous-activity-store.js`, call `log()`. Also publish to WebSocket via `getMessageBus().publish()` on channel `ironclaw.{problem_set_id}` with messageType `ironclaw.autonomous-activity`.
   - Description: "Log an autonomous activity entry visible in the commander's activity feed."

7. **`bastion.autonomous.send_alert`** (riskLevel: 'medium')
   - Input: `{ problem_set_id: string, message: string, severity: 'critical' | 'urgent' | 'routine', telegram?: boolean }`
   - Handler: Always push to WebSocket via MessageBus. If severity is critical or urgent AND telegram is true, also send via TelegramBotService (import dynamically, graceful fallback if not configured).
   - Description: "Send an alert to commanders via WebSocket and optionally Telegram. Use for time-sensitive findings."

Export pattern: `export const intelligenceTools: MCPToolDefinition[] = [...]` for the definitions, and `export const intelligenceToolHandlers: Record<string, (args: Record<string, unknown>) => Promise<unknown>> = {...}` for the handlers.

Check how existing tool groups (knowledge.ts, operations.ts) export their handlers and follow the same pattern exactly.
