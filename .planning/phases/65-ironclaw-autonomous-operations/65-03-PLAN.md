  <action>
Create `backend/src/ironclaw/event-forwarder.ts`:

1. **EventForwarder class** with batched forwarding:
   - Internal buffer: `Map<string, EventSummary[]>` keyed by problemSetId
   - `enqueue(event: { type, problemSetId, summary, entityIds? })` — adds to buffer
   - `flush(problemSetId)` — sends batched summary to Ironclaw via `ironclawClient.sendMessageAsync()` on thread `autonomous-{problemSetId}`, then clears buffer
   - Auto-flush timer: 30-second window per problem set (clearTimeout/setTimeout pattern)
   - Message format: `[EVENTS] {count} events since last check:\n- {type}: {summary}\n- {type}: {summary}`
   - Use `sendMessageAsync` (fire-and-forget) — NEVER block the pipeline that generated the event

2. **Export:**
   - `export const eventForwarder = new EventForwarder();`
   - `export function forwardEventToIronclaw(event: {...}): void` — convenience wrapper that calls `eventForwarder.enqueue(event)`, wrapped in try/catch (never throw from event forwarding)

3. **Wire into OSINT pipeline** (`backend/src/osint/osint-agent-bridge.ts`):
   - Read the file first to find where `processOSINTEventThroughAgents()` completes successfully
   - After successful processing, call: `forwardEventToIronclaw({ type: 'osint_ingested', problemSetId: event.problem_set_id, summary: \`OSINT event processed: ${event.title || event.source_url}\` })`
   - Import from `../ironclaw/event-forwarder.js`

4. **Wire into document pipeline** (`backend/src/doc-intelligence/orchestrator-wiring.ts`):
   - Read the file first to find where document processing completes
   - After successful processing, call: `forwardEventToIronclaw({ type: 'document_processed', problemSetId, summary: \`Document processed: ${documentTitle}\` })`

5. **Wire into graph builder** (`backend/src/graph/construction/graph-builder.ts`):
   - Read the file first to find `buildFromDocument()` or similar completion points
   - After graph update, call: `forwardEventToIronclaw({ type: 'graph_changed', problemSetId, summary: \`Graph updated: ${entityCount} entities, ${relCount} relationships\` })`

CRITICAL: All hook calls must be wrapped in try/catch. Event forwarding failures must NEVER break the pipeline that generated the event. Log warnings on failure, do not throw.
