CREATE TABLE IF NOT EXISTS ironclaw_autonomous_activity (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  problem_set_id TEXT NOT NULL,
  activity_type TEXT NOT NULL,
  severity TEXT NOT NULL DEFAULT 'informational',
  summary TEXT NOT NULL,
  detail JSONB,
  decision_id UUID,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()

CREATE INDEX IF NOT EXISTS idx_autonomous_activity_ps ON ironclaw_autonomous_activity(problem_set_id, created_at DESC);

<task type="auto">
  <name>Task 2: Create callback webhook router on bastion-mcp and mount it</name>
  <files>backend/src/mcp/ironclaw-callback-router.ts, backend/src/mcp/index.ts</files>
  <action>
Create `backend/src/mcp/ironclaw-callback-router.ts`:

1. **Express Router** with `POST /callback` endpoint:
   - HMAC authentication via `verifyRequest` from `../ironclaw/hmac-auth.js` (import the existing middleware)
   - Request body validation: require `type` (string), `problemSetId` (string), `payload` (object), `severity` (string, one of critical/urgent/routine/informational)
   - Return 400 for missing/invalid fields

2. **Circuit breakers** (checked before processing):
   - Max 10 callbacks per problem set in the last 30 minutes (use `autonomousActivityStore.getCountSince()`)
   - Max 100 callbacks per problem set per day (use `autonomousActivityStore.getDailyCount()`)
   - Return 429 with `{ error: 'rate_limit', retryAfter: seconds }` if exceeded

3. **Type-based routing** (switch on `type`):
   - `intelligence_gap_detected` — import and call `createPIRAlertDecision()` from `../../decisions/pir-alert-handler.js`, store resulting decision_id
   - `conflict_detected` — import `DecisionService`, call `createDecision()` with type `CONFLICT_RESOLUTION`, store decision_id
   - `situation_assessment` — just log to activity store (no decision gate)
   - `skill_creation_request` — call `createDecision()` with type `SKILL_CREATION` (medium-risk governance gate)
   - `alert` — import `TelegramBotService`, call `sendNotification()` for urgent/critical severity
   - Default: log to activity store only

4. **Always** (after routing):
   - Log to `autonomousActivityStore.log()`
   - Publish to WebSocket via `getMessageBus().publish()` on channel `ironclaw.{problemSetId}` with messageType `ironclaw.autonomous-activity`
   - Return `{ status: 'ok', activityId: entry.id }`

5. **Mount in `backend/src/mcp/index.ts`:**
   - Import `callbackRouter` from `./ironclaw-callback-router.js`
   - Add `app.use('/api/ironclaw', callbackRouter)` BEFORE the listen call
   - This makes the endpoint available at `http://bastion-mcp:3334/api/ironclaw/callback`

CRITICAL NETWORK CONSTRAINT: This endpoint MUST be on the bastion-mcp container (port 3334), NOT on the main backend (port 3001). Ironclaw sits on `ironclaw-network` and can ONLY reach `bastion-mcp`. The MCP container bridges both `bastion-network` and `ironclaw-network`.

For imports that won't resolve in the MCP container context (decision-service, telegram-bot-service, pir-alert-handler), use dynamic imports with try/catch fallback that logs a warning if the service isn't available. The MCP container shares the same compiled source as the backend but may not have all services initialized. Alternatively, route these through HTTP calls to the main backend (localhost:3001) from within bastion-mcp — follow whichever pattern existing MCP tool handlers use for accessing backend services.

Check how existing MCP tool handlers in `backend/src/mcp/tools/` access backend services (e.g., knowledge.ts, operations.ts) and follow the same pattern for accessing decision-service, telegram-bot-service, etc.
