Create `backend/src/ironclaw/ironclaw-client.ts` -- HTTP client to the Ironclaw sidecar.

Class `IronclawClient`:
- Constructor takes baseUrl (string, defaults to process.env.IRONCLAW_URL || 'http://ironclaw:3000').
- `async sendMessage(sessionId: string, content: string, mentionedAgent?: string): Promise<ReadableStream<Uint8Array>>` -- POST to `${baseUrl}/api/chat` with JSON body { session_id: sessionId, message: content, mentioned_agent: mentionedAgent }. Returns `response.body` as ReadableStream for SSE streaming. Throws if response not ok (with status + statusText).
- `async createSession(sessionId: string, systemPrompt: string): Promise<{ session_id: string }>` -- POST to `${baseUrl}/api/sessions` with JSON body { session_id: sessionId, system_prompt: systemPrompt }. Returns parsed JSON response.
- `async healthCheck(): Promise<boolean>` -- GET to `${baseUrl}/health`. Returns true if status 200, false otherwise (catch errors, return false).
- `async registerMCPServer(serverUrl: string, tools: Array<{ name: string; description: string; inputSchema: Record<string, unknown> }>): Promise<void>` -- POST to `${baseUrl}/api/mcp/register` with JSON body { server_url: serverUrl, tools }. This registers BASTION as an MCP server that Ironclaw connects to.

Use native `fetch` (Node 18+ built-in). No axios dependency.

Export singleton: `export const ironclawClient = new IronclawClient();`

Add helper function `parseSSEStream(stream: ReadableStream<Uint8Array>): AsyncGenerator<{ event?: string; data: string }>` -- reads the stream using TextDecoderStream or manual TextDecoder, splits on double newlines, parses SSE format (event: and data: fields). Yields parsed events. Uses `eventsource-parser` library's `createParser` for correct SSE parsing.

**ironclaw-service.ts:**

Class `IronclawService`:
- Dependencies: ironclawClient, ironclawStore (imported from siblings).
- `async handleMessage(problemSetId: string, userDid: string, content: string, mentionedAgent?: string): Promise<void>` --
  1. getOrCreateSession from store
  2. If no ironclaw_session_id, call ironclawClient.createSession with system prompt that includes problem set context and specialist agent descriptions
  3. Persist user message to ironclaw_chat via store.addMessage({ problem_set_id, content, sender: 'user' })
  4. Call ironclawClient.sendMessage with the session's ironclaw_session_id
  5. Parse SSE stream using parseSSEStream
  6. For each SSE event: detect if it's a specialist delegation (look for specialist_id in event data), create IronclawChatMessage with appropriate sender ('ironclaw' or 'specialist'), persist via store.addMessage
  7. Publish each chunk to WebSocket channel `ironclaw.${problemSetId}` via MessageBus for real-time frontend updates
  8. If event contains an action request (tool_call), create ActionCardData and include in the persisted message

- `async getHistory(problemSetId: string, limit?: number): Promise<IronclawChatMessage[]>` -- delegates to store.getHistory.

- `async isHealthy(): Promise<boolean>` -- delegates to ironclawClient.healthCheck.

- `buildSystemPrompt(problemSetId: string): string` -- returns system prompt establishing Ironclaw as BASTION's chief of staff with instructions about specialist delegation, action confirmation, and scope rules. Include: "You are the Chief of Staff for this problem set. When a query is domain-specific, delegate to the appropriate specialist agent and attribute their response. Always confirm actions before executing. For ambiguous scope (this PS vs children), ask to clarify. Never assume."

Export singleton: `export const ironclawService = new IronclawService();`

**ironclaw-router.ts:**

Express Router with these endpoints (all require authentication -- will be mounted behind requireAuth):

1. `POST /:problemSetId/message` -- Body: { content: string, mentionedAgent?: string }. Reads userDid from req.zeroTrust?.did or (req as any).user?.did (consistent with existing routes). Calls ironclawService.handleMessage. Returns 202 Accepted (streaming happens via WebSocket). Error handling: 400 if content missing, 500 with error message.

2. `GET /:problemSetId/history` -- Query: limit (optional number). Calls ironclawService.getHistory. Returns 200 with JSON array.

3. `GET /health` -- Calls ironclawService.isHealthy. Returns { healthy: boolean }.

Export: `export { ironclawRouter }`
