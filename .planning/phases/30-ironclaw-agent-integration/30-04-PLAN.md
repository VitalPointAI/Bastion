Class `ToolBridge`:
- `async registerTools(): Promise<void>` -- Calls ironclawClient.registerMCPServer with the backend's own URL (process.env.APP_URL or 'http://backend:3001') and BASTION_TOOLS array. Also registers each tool's risk level with actionRegistry.registerAction. Wraps in try/catch -- logs warning if Ironclaw not reachable but doesn't throw (allows backend to start without Ironclaw).

- `validateScope(toolName: string, args: Record<string, unknown>, userProblemSetId: string): { valid: boolean; error?: string; needsClarification?: boolean }` --
  Checks if the tool invocation targets the user's current problem set scope:
  - Extract target PS id from args (look for 'id', 'problem_set_id', 'parent_id' fields).
  - If target matches userProblemSetId: valid.
  - If target is a child of userProblemSetId: valid (would need to check hierarchy, but for now accept -- TODO: integrate with inheritance-store for full hierarchy check).
  - If target is different and not a child: return { valid: false, needsClarification: true, error: 'This action targets a different problem set. Please clarify which problem set you mean.' } -- per locked decision "agent always asks to clarify, never assumes".
  - If no PS-scoped field in args (e.g., system tools): valid only if tool starts with 'bastion.system.' (system-scoped tools).

- `handleToolCall(toolName: string, args: Record<string, unknown>, userDid: string, problemSetId: string): Promise<ActionResult>` --
  1. Validate scope. If needsClarification, return { status: 'denied', error: clarification message }.
  2. Create IronclawAction from tool call.
  3. Route through actionPipeline.processAction.
  4. Return result.

Export singleton: `export const toolBridge = new ToolBridge();`

**Add to ironclaw-router.ts** (append new routes to existing router):

1. `POST /:problemSetId/confirm` -- Body: { actionId: string, decision: 'yes' | 'no' | 'always' }. Reads userDid from req.zeroTrust?.did. Validates decision is one of the three values. Calls actionPipeline.handleConfirmation(actionId, userDid, problemSetId, decision). If decision resulted in execution, publish execution result to WebSocket channel `ironclaw.${problemSetId}`. Returns 200 with ActionResult.

2. `GET /trust-preferences` -- Reads userDid from req.zeroTrust?.did. Optional query param: problemSetId. If problemSetId provided, calls ironclawStore.getAllTrustPreferences(userDid, problemSetId). Otherwise returns 400 "problemSetId required". Returns 200 with array of TrustPreference.

3. `DELETE /trust-preferences/:preferenceId` -- Reads userDid from req. Gets preference, verifies it belongs to the user. Calls ironclawStore.revokeTrust(userDid, preference.problem_set_id, preference.action_type). Returns 204.

4. `POST /:problemSetId/emergency` -- Body: { actionId: string, justification: string }. Reads userDid. Validates justification is non-empty string. Calls actionPipeline.handleEmergencyAction with constructed action, userDid, justification. Returns 200 with result.
