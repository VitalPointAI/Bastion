<task type="auto">
  <name>Task 1: Create AAR event store and checkpoint store</name>
  <files>backend/src/exercise/aar-store.ts, backend/src/exercise/checkpoint-store.ts</files>
  <action>
1. Create `backend/src/exercise/aar-store.ts`:
   - Import getPool from database, crypto for UUIDs
   - Define interface `AAREvent`: id (string), workspaceId (string), scenarioId (string | null), exercisePhase (string), eventType ('decision' | 'ai_recommendation' | 'governance_vote' | 'outcome' | 'phase_change'), actorDid (string), payload (Record<string, unknown>), createdAt (Date)
   - Create `initAARTable()` function (idempotent):
     ```sql
     CREATE TABLE IF NOT EXISTS aar_events (
       id TEXT PRIMARY KEY,
       workspace_id TEXT NOT NULL,
       scenario_id TEXT,
       exercise_phase TEXT NOT NULL DEFAULT 'unknown',
       event_type TEXT NOT NULL,
       actor_did TEXT NOT NULL,
       payload JSONB NOT NULL DEFAULT '{}',
       created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
     );
     CREATE INDEX IF NOT EXISTS idx_aar_workspace ON aar_events(workspace_id);
     CREATE INDEX IF NOT EXISTS idx_aar_type ON aar_events(event_type);
     ```
   - Class `AARStore` with methods:
     - `async init()`: calls initAARTable
     - `async record(event: Omit<AAREvent, 'id' | 'createdAt'>): Promise<AAREvent>`: INSERT with generated UUID
     - `async listByWorkspace(workspaceId: string, opts?: { eventType?: string; limit?: number }): Promise<AAREvent[]>`: SELECT ordered by created_at DESC
     - `async listByScenario(scenarioId: string): Promise<AAREvent[]>`: SELECT by scenario_id
   - Export singleton: `export const aarStore = new AARStore()`
   - AAR events are append-only — no delete or update methods. This ensures reset does not lose AAR data.

2. Create `backend/src/exercise/checkpoint-store.ts`:
   - Import getPool, crypto
   - Define interface `ExerciseCheckpoint`: id (string), workspaceId (string), scenarioId (string | null), exercisePhase (string), label (string), snapshotData (Record<string, unknown>), createdAt (Date)
   - Create `initCheckpointTable()` (idempotent):
     ```sql
     CREATE TABLE IF NOT EXISTS exercise_checkpoints (
       id TEXT PRIMARY KEY,
       workspace_id TEXT NOT NULL,
       scenario_id TEXT,
       exercise_phase TEXT NOT NULL,
       label TEXT NOT NULL,
       snapshot_data JSONB NOT NULL DEFAULT '{}',
       created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
     );
     CREATE INDEX IF NOT EXISTS idx_checkpoint_workspace ON exercise_checkpoints(workspace_id);
     ```
   - Class `CheckpointStore` with methods:
     - `async init()`: calls initCheckpointTable
     - `async createCheckpoint(opts: { workspaceId: string; scenarioId?: string; exercisePhase: string; label: string; snapshotData: Record<string, unknown> }): Promise<ExerciseCheckpoint>`: INSERT
     - `async listForWorkspace(workspaceId: string): Promise<ExerciseCheckpoint[]>`: SELECT ordered by created_at DESC
     - `async getCheckpoint(id: string): Promise<ExerciseCheckpoint | null>`: SELECT by id
     - `async restoreCheckpoint(id: string): Promise<{ restored: boolean; checkpointId: string }>`: Load checkpoint's snapshotData, return it for the caller to apply (the actual restore logic depends on what workspace state to overwrite — keep this as a data retrieval for now, actual application will be wired when exercise integration is complete)
   - Export singleton: `export const checkpointStore = new CheckpointStore()`
   - NOTE: Checkpoint reset NEVER touches aar_events table — AAR events persist across resets
  </action>
