Create `backend/src/exercise/types.ts` with all exercise domain types following the RESEARCH.md recommended schema:

1. **ExerciseScenario** — id, name, designation ('training/exercise' | 'operational'), exercisePhases (string array: Competition, Crisis, Conflict Day 4, Conflict Day 10, Conflict Day 22, Negotiation), currentPhaseIndex, status ('draft' | 'active' | 'complete'), createdBy (DID), timestamps.

2. **ScenarioDocument** — id, scenarioId (FK), team ('blue' | 'red' | 'controller'), exercisePhase, documentType enum (ALERTORD, SITREP, CAMPAIGN_PLAN, FRAGO, OOB, COUNTRY_POLICY, PLANNING_MAP, DIRECTIVE, OTHER), filename, mimeType, textContent, extractedData (typed as Record<string, unknown>), extractionConfidence (number 0-1), timestamps.

3. **IPBAssessment** — id, scenarioId, team ('blue' | 'red'), perspective ('own' | 'enemy_assessment'), exercisePhase, areaOfOperations (GeoJSON-compatible JSONB), terrainAnalysis (OAKOC structure), threatAssessment, civilConsiderations, namedAreasOfInterest (array), forceDispositions (OOB with geo positions), overlayLayers (IPBLayer array for ValidityMap), version (number), parentVersionId (nullable — for history chain), createdBy, timestamps.

4. **IPBLayer** — id, name, type ('unit' | 'area' | 'line' | 'point'), team ('blue' | 'red'), layerType ('forces' | 'key_terrain' | 'avenue_of_approach' | 'nai' | 'engagement_area' | 'obstacle'), geometry (GeoJSON), properties (Record), sidc (optional MIL-STD-2525D string for milsymbol).

5. **ScenarioCOA** — id, scenarioId, team, exercisePhase, number, name, description, scheme, doctScores (ExerciseCOAScore), wargameEvidence (JSONB), combinedScore, narrative (string, staff-editable), commanderDecision ('accepted' | 'rejected' | 'modified' | 'combined' | 'returned' | null), commanderDecisionNotes, decisionHash, blockchainTx, selected (boolean), createdBy, timestamps.

6. **ExerciseCOAScore** — feasibility, acceptability, suitability, distinguishability, completeness — each with { score: number, rationale: string, wargameEvidence?: string }. combinedScore (number). narrative (string). wargamingSessionId (optional).

7. **ExerciseOrder** — id, scenarioId, team ('blue' | 'red'), orderType ('WARNORD' | 'OPORD' | 'FRAGO'), exercisePhase, version, content (WARNORDContent | OPORDContent | FRAGOContent), status ('draft' | 'published'), publishedAt, createdBy, timestamps.

8. **WARNORDContent** — situation, missionStatement, commandersIntent, initialTasks (array of {assignedTo, task, purpose, deadline?}), timelineSummary, serviceAndSupport, commandAndSignal.

9. **OPORDContent** — Full 5-paragraph: situation, mission, execution (concept, tasks, coordinating instructions), serviceAndSupport, commandAndSignal. Reuse structures from existing planning/types.ts SituationParagraph etc where applicable.

10. **FRAGOContent** — changedParagraphs (partial of OPORDContent), effectiveTime, references (array of order IDs this FRAGO modifies).

11. **PlanningTask** — id, orderId (FK), scenarioId, team, assignedRole ('blue_staff' | 'red_cell' | 'exercise_control'), title, description, deadline (optional Date), status ('pending' | 'in_progress' | 'complete'), completedAt, timestamps.

12. **ExerciseGate** — id, scenarioId, exercisePhase, gateType ('info_release' | 'phase_transition' | 'order_required'), conditionDescription, isOpen (boolean), openedBy, openedAt.

13. **ExerciseRole** type — 'blue_staff' | 'red_cell' | 'exercise_control'.

14. **ExerciseDocumentType** enum — ALERTORD, SITREP, CAMPAIGN_PLAN, FRAGO, OOB, COUNTRY_POLICY, PLANNING_MAP, DIRECTIVE, OTHER.

Create `backend/src/exercise/schemas.ts` with Zod schemas for all types, using z.object patterns consistent with existing backend/src/planning/schemas.ts. Include create/update variants (e.g., CreateExerciseScenarioSchema omitting id and timestamps).

Create `backend/src/exercise/information-barrier.ts`:
- `ExerciseRole` type (re-export from types)
- `getVisibleTeams(role: ExerciseRole): string[]` — exercise_control sees ['blue', 'red', 'controller'], blue_staff sees ['blue', 'controller'], red_cell sees ['red', 'controller']
- `withExerciseBarrier` Express middleware that reads `req.user.exerciseRole` and sets `req.visibleTeams`
- Type augmentation for Express Request to include `visibleTeams` and `exerciseRole` properties

Create `backend/db/migrations/014-exercise-tables.sql` with CREATE TABLE statements for all 7 tables following the RESEARCH.md schema. Include:
- TEXT primary keys (UUID pattern matching existing codebase)
- Foreign key constraints with ON DELETE CASCADE from children to exercise_scenarios
- team column on every table that stores team-specific data
- JSONB columns for extracted_data, overlay_layers, doctrinal_scores, wargame_evidence, content
- Indexes on (scenario_id, team) for every team-filtered table
- TIMESTAMPTZ for all timestamp columns with DEFAULT NOW()

Create 7 PostgreSQL data stores following the existing pattern in `backend/src/planning/stores/plan-store.ts` and `backend/src/strategic/ingestion/document-store.ts`. Each store accepts a `Pool` instance in its constructor.

**CRITICAL:** Every query that returns team-specific data MUST include `AND team = ANY($N)` where `$N` is the visibleTeams parameter. This is the information barrier enforcement at the data layer.

1. **ScenarioStore** (`scenario-store.ts`):
   - `create(data: CreateExerciseScenario): Promise<ExerciseScenario>`
   - `findById(id: string): Promise<ExerciseScenario | null>`
   - `findAll(): Promise<ExerciseScenario[]>`
   - `update(id: string, data: Partial<ExerciseScenario>): Promise<ExerciseScenario>`
   - `advancePhase(id: string): Promise<ExerciseScenario>` — increments currentPhaseIndex
   - `delete(id: string): Promise<void>`

2. **ScenarioDocumentStore** (`document-store.ts`):
   - `create(data: CreateScenarioDocument): Promise<ScenarioDocument>`
   - `findByScenario(scenarioId: string, visibleTeams: string[]): Promise<ScenarioDocument[]>`
   - `findByScenarioAndPhase(scenarioId: string, phase: string, visibleTeams: string[]): Promise<ScenarioDocument[]>`
   - `findById(id: string, visibleTeams: string[]): Promise<ScenarioDocument | null>`
   - `updateExtraction(id: string, extractedData: Record<string, unknown>, confidence: number): Promise<void>`
   - `countByScenario(scenarioId: string): Promise<number>`

3. **IPBStore** (`ipb-store.ts`):
   - `create(data: CreateIPBAssessment): Promise<IPBAssessment>`
   - `findByScenario(scenarioId: string, visibleTeams: string[]): Promise<IPBAssessment[]>`
   - `findByScenarioAndPerspective(scenarioId: string, team: string, perspective: string, visibleTeams: string[]): Promise<IPBAssessment | null>` — returns latest version
   - `findById(id: string, visibleTeams: string[]): Promise<IPBAssessment | null>`
   - `createNewVersion(parentId: string, data: Partial<IPBAssessment>): Promise<IPBAssessment>` — copies parent, increments version, sets parentVersionId
   - `getVersionHistory(assessmentId: string, visibleTeams: string[]): Promise<IPBAssessment[]>` — follow parentVersionId chain

4. **COAStore** (`coa-store.ts`):
   - `create(data: CreateScenarioCOA): Promise<ScenarioCOA>`
   - `findByScenario(scenarioId: string, visibleTeams: string[]): Promise<ScenarioCOA[]>`
   - `findById(id: string, visibleTeams: string[]): Promise<ScenarioCOA | null>`
   - `updateScores(id: string, scores: ExerciseCOAScore): Promise<void>`
   - `updateWargameEvidence(id: string, evidence: Record<string, unknown>): Promise<void>`
   - `recordDecision(id: string, decision: string, notes: string): Promise<void>`
   - `updateDecisionHash(id: string, hash: string): Promise<void>`
   - `updateBlockchainTx(id: string, txHash: string): Promise<void>`
   - `updateNarrative(id: string, narrative: string): Promise<void>`

5. **OrderStore** (`order-store.ts`):
   - `create(data: CreateExerciseOrder): Promise<ExerciseOrder>`
   - `findByScenario(scenarioId: string, visibleTeams: string[]): Promise<ExerciseOrder[]>`
   - `findById(id: string, visibleTeams: string[]): Promise<ExerciseOrder | null>`
   - `updateContent(id: string, content: object): Promise<void>`
   - `markPublished(id: string): Promise<void>` — sets status='published' and publishedAt=NOW()
   - `findByPhase(scenarioId: string, phase: string, visibleTeams: string[]): Promise<ExerciseOrder[]>`

6. **TaskStore** (`task-store.ts`):
   - `create(data: CreatePlanningTask): Promise<PlanningTask>`
   - `findByScenario(scenarioId: string, visibleTeams: string[]): Promise<PlanningTask[]>`
   - `findByOrder(orderId: string, visibleTeams: string[]): Promise<PlanningTask[]>`
   - `findByRole(scenarioId: string, role: string, visibleTeams: string[]): Promise<PlanningTask[]>`
   - `updateStatus(id: string, status: string): Promise<void>` — sets completedAt on 'complete'
   - `findById(id: string, visibleTeams: string[]): Promise<PlanningTask | null>`

7. **GateStore** (`gate-store.ts`):
   - `create(data: CreateExerciseGate): Promise<ExerciseGate>`
   - `findByScenario(scenarioId: string): Promise<ExerciseGate[]>`
   - `findByPhase(scenarioId: string, phase: string): Promise<ExerciseGate[]>`
   - `openGate(id: string, openedBy: string): Promise<void>` — sets isOpen=true, openedBy, openedAt=NOW()
   - `isPhaseReady(scenarioId: string, phase: string): Promise<boolean>` — all gates for phase are open
