  <files>backend/src/exercise/package-parser.ts</files>
  <action>
Create `backend/src/exercise/package-parser.ts` that infers team, exercise phase, and document type from file paths within a scenario package upload.

**PackageTags interface:**
```typescript
interface PackageTags {
  team: 'blue' | 'red' | 'controller';
  exercisePhase: string;  // 'Competition' | 'Crisis' | 'Conflict Day 4' | etc.
  documentType: ExerciseDocumentType;
  confidence: number; // 0-1, how confident the heuristic is
}
```

**TEAM_HEURISTICS** — ordered regex array. Check each path segment against:
- `/blue[\s_-]?team|team[\s_-]?blue/i` → 'blue'
- `/red[\s_-]?team|team[\s_-]?red/i` → 'red'
- `/scenario[\s_-]?phases?|exercise[\s_-]?control|excon/i` → 'controller'
- Default if no match: 'controller' (shared documents)

**PHASE_HEURISTICS** — ordered regex array applied to full relative path:
- `/competition|phase[\s_-]?1\b/i` → 'Competition'
- `/crisis|phase[\s_-]?2\b/i` → 'Crisis'
- `/day[\s_-]?4|conflict[\s_-]?day[\s_-]?4|phase[\s_-]?3\b/i` → 'Conflict Day 4'
- `/day[\s_-]?10|conflict[\s_-]?day[\s_-]?10|phase[\s_-]?4\b/i` → 'Conflict Day 10'
- `/day[\s_-]?22|conflict[\s_-]?day[\s_-]?22|phase[\s_-]?5\b/i` → 'Conflict Day 22'
- `/negotiat|phase[\s_-]?6\b/i` → 'Negotiation'
- `/overall|phase[\s_-]?3[\s_-]?-?[\s_-]?5/i` → 'Conflict Day 4' (first conflict phase for multi-phase items)
- Default: 'Competition' (earliest phase)

**TYPE_HEURISTICS** — ordered regex array applied to both path and filename:
- `/sitrep|situation[\s_-]?report|situation[\s_-]?update/i` → 'SITREP'
- `/alertord|alert[\s_-]?order/i` → 'ALERTORD'
- `/frago|fragmentary/i` → 'FRAGO'
- `/oob|order[\s_-]?of[\s_-]?battle/i` → 'OOB'
- `/campaign[\s_-]?plan/i` → 'CAMPAIGN_PLAN'
- `/policy[\s_-]?sheet|country[\s_-]?policy/i` → 'COUNTRY_POLICY'
- `/planning[\s_-]?map|hex/i` → 'PLANNING_MAP'
- `/directive|learning[\s_-]?event/i` → 'DIRECTIVE'
- `/conop|concept[\s_-]?of[\s_-]?operations/i` → 'CAMPAIGN_PLAN'
- Default: 'OTHER'

**Main function:** `inferTagsFromPath(relativePath: string): PackageTags`
- Split path into segments
- Apply team heuristics to each segment, take first match
- Apply phase heuristics to the full path
- Apply type heuristics to full path + filename
- Calculate confidence: 1.0 if all three matched, 0.7 if team matched but phase/type defaulted, 0.5 if only defaults

**Validation:** Test the function mentally against the actual scenario/ directory structure:
- `blue team/Team BLUE/2.1 - Phase 3 (Day 4) - Blue Sitrep/CJTF-WP Day 4 Sitrep_AY26 PS.docx` → team=blue, phase=Conflict Day 4, type=SITREP
- `red team/2. Phase 3-5 - Red Campaign Plan/01. CMC JSD ALERTORD to TWN Campaign Cmd_AY26.docx` → team=red, phase=Conflict Day 4, type=ALERTORD
- `scenario phases/02. Phase 1 - Competition (Fri am)/03. Country Sheets.../Japan_Policy_Sheet_2028_2030.docx` → team=controller, phase=Competition, type=COUNTRY_POLICY

Also export a `parseScenarioPackage(files: Array<{relativePath: string, buffer: Buffer, mimeType: string}>): Array<{tags: PackageTags, file: ...}>` convenience function that maps over files applying inferTagsFromPath.

Create `backend/src/exercise/extraction-service.ts` that extends the existing strategic extraction pipeline for exercise-specific document processing.

**ExerciseExtractionService class:**

Constructor takes: `pool: Pool`, `documentParser: DocumentParser` (from strategic/ingestion), and LLM provider config (reuse existing provider pattern from `backend/src/strategic/extraction/providers/`).

**Core method:** `extractDocument(docId: string, textContent: string, tags: PackageTags): Promise<ExtractedExerciseData>`

The method:
1. Chunks the document text using `DocumentParser.chunkDocument()` (existing method)
2. Builds an exercise-specific system prompt based on the document's team and type:

```
EXERCISE_EXTRACTION_SYSTEM_PROMPT template:
"You are a military exercise analyst extracting structured data from exercise scenario documents.

This document is from a training/exercise package (designation: training/exercise).
Team context: {team} | Exercise phase: {exercisePhase} | Document type: {documentType}

Extract the following based on document type:
- OOB: Force composition, unit designations (with SIDC codes where identifiable), equipment types, strength estimates, echelon, geographic locations (lat/lng where inferrable, otherwise named location)
- SITREP: Situation updates, force movements, key events, changed objectives, casualty assessments
- CAMPAIGN_PLAN: Strategic objectives, operational phasing, COA descriptions, main/supporting efforts, decision points
- ALERTORD: Mission assignment, task organization, timeline, initial tasks, reporting instructions
- COUNTRY_POLICY: Access/basing/overflight status, conditions, limitations, diplomatic alignment
- FRAGO: Changed paragraphs from base order, effective time, new tasks/modifications
- PLANNING_MAP: Named regions, hex identifiers (for geographic mapping), key terrain features, approximate coordinates
- DIRECTIVE: Exercise structure, learning objectives, timeline, participating organizations

CRITICAL: Do NOT include intelligence that {team} would not have visibility of. Extract only from {team}'s perspective."
```

3. Calls the LLM with the system prompt + document chunks using the existing extraction provider pattern (Anthropic or OpenAI compatible). Use tool_use / function_calling with a structured schema for the extraction output:

**ExtractedExerciseData** type (define in types.ts if not already):
```typescript
{
  summary: string;
  forceDispositions?: Array<{ unitName: string; echelon: string; sidc?: string; location?: {lat: number; lng: number} | string; strength?: string; equipment?: string[] }>;
  objectives?: Array<{ id: string; description: string; priority: 'primary' | 'secondary' | 'tertiary' }>;
  timeline?: Array<{ event: string; time: string; phase: string }>;
  keyEvents?: Array<{ event: string; significance: string }>;
  accessBasingOverflight?: { access: string; basing: string; overflight: string; conditions: string };
  tasks?: Array<{ assignedTo: string; task: string; purpose: string }>;
  changedItems?: Array<{ field: string; oldValue?: string; newValue: string }>;
  rawExtraction: Record<string, unknown>;
}
```

4. Stores the extraction result via `ScenarioDocumentStore.updateExtraction(docId, extractedData, confidence)`

**Batch method:** `extractScenarioPackage(scenarioId: string, documents: ScenarioDocument[]): Promise<void>`
- Processes documents sequentially (to manage LLM rate limits)
- Logs progress: "Extracting document N/M: {filename}"
- Catches per-document errors without failing the entire batch

Use the existing LLM provider abstraction — check which provider is configured (Anthropic or OpenAI) and use the corresponding SDK. Follow the pattern in `backend/src/strategic/extraction/extractor.ts` for provider selection.
