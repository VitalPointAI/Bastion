Create `frontend/src/components/exercise/OrderEditor.tsx`.

Props: `{ scenarioId: string, perspective: 'blue' | 'red', exercisePhase: string }`

**State:**
- `orders: ExerciseOrder[]` — existing orders for this scenario/team/phase
- `activeOrder: ExerciseOrder | null` — currently viewed/editing order
- `editMode: boolean` — whether content is editable
- `editContent: any` — working copy of order content for editing
- `generating: boolean`, `publishing: boolean`

**Layout — Two-column:**

1. **Left sidebar (30%):** Order list
   - Filter buttons: WARNORD | OPORD | FRAGO | All
   - List of orders showing: type badge, exercise phase, status (draft/published), version number
   - "Generate Order" button group:
     - "Generate WARNORD" — calls `exerciseService.generateOrder(scenarioId, { team: perspective, orderType: 'WARNORD', exercisePhase })`
     - "Generate OPORD" — needs selectedCOAId, shows dropdown of approved COAs first
     - "Generate FRAGO" — needs base order selection, shows dropdown of existing OPORDs
   - "Create Blank Draft" button — creates empty template for manual authoring

2. **Right content area (70%):** Order viewer/editor
   - Header showing: Order type, team, exercise phase, status badge, version
   - **WARNORD view/edit:** Sections for each WARNORDContent field:
     - Situation (textarea)
     - Mission Statement (textarea)
     - Commander's Intent (textarea)
     - Initial Tasks (table: assignedTo dropdown, task textarea, purpose textarea, deadline date picker)
     - Timeline Summary (textarea)
     - Service & Support (textarea)
     - Command & Signal (textarea)
   - **OPORD view/edit:** 5-paragraph format with collapsible sections:
     - 1. Situation (enemy forces, friendly forces, assumptions — each sub-section editable)
     - 2. Mission (textarea)
     - 3. Execution (concept of operations textarea, subordinate tasks table, coordinating instructions textarea)
     - 4. Service & Support (textarea)
     - 5. Command & Signal (textarea)
   - **FRAGO view/edit:** Shows only changed paragraphs with reference to base order
     - "Changed Paragraphs" indicator badges
     - Each changed paragraph editable
     - Effective time (datetime input)
     - Reference to base order (shown as link)

3. **Action bar (bottom):**
   - "Edit" toggle button — switches between view and edit mode
   - "Save Draft" — saves edits without publishing: `exerciseService.updateOrderContent(orderId, editContent)`
   - "Publish Order" — prominent button that calls `exerciseService.publishOrder(orderId)`. Shows confirmation dialog: "Publishing this order will create {N} planning tasks for {team} staff. Continue?"
   - After publish: Shows success message with task count created

**Per CONTEXT.md requirements enforced:**
- Both AI-generated and manual authoring modes (generate button + blank draft button)
- Per-team order generation — order content reflects the team's perspective (Blue refs CJTF WestPAC, Red refs PRC/TCC)
- Order sequence follows doctrine: WARNORD -> OPORD -> FRAGOs. Visually indicate the doctrinal sequence with a simple flow diagram at the top of the order list.
- WARNORD serves as exercise initiation — highlight this with a special badge/callout when it's the first order

**Styling:**
- Order type badges: WARNORD (amber), OPORD (green), FRAGO (blue)
- Status badges: draft (gray), published (green)
- 5-paragraph OPORD sections use numbered headings matching military format
- Edit mode shows subtle border/background change to indicate editable state

Props: `{ scenarioId: string, perspective: 'blue' | 'red', exercisePhase: string }`

- `tasks: PlanningTask[]` — all visible tasks for the scenario
- `summary: BoardSummary | null` — completion stats
- `filterRole: string | 'all'` — filter by assigned role
- `filterPhase: string | 'all'` — filter by exercise phase

**Layout:**

1. **Header bar:**
   - Completion progress bar (percentage from summary.completionPercentage)
   - Filter dropdowns: Role (All | Blue Staff | Red Cell | Exercise Control), Phase (All | Competition | Crisis | ...)
   - Stats badges: Total tasks, Pending count, In Progress count, Complete count

2. **Kanban columns (3 columns, horizontal scroll on mobile):**
   - **Pending** (left, gray header) — Tasks not yet started
   - **In Progress** (center, blue header) — Tasks being worked
   - **Complete** (right, green header) — Finished tasks

   Each column shows task cards matching that status.

3. **Task Card content:**
   - Title (bold)
   - Team badge (blue/red/controller with appropriate color)
   - Assigned role badge
   - Description (truncated to 2 lines, expandable)
   - Exercise phase tag
   - Deadline (if set) — red highlight if overdue, yellow if due today
   - Source order reference (which order created this task, as a clickable link that navigates to order editor)
   - Status change buttons:
     - Pending → "Start" button (→ in_progress)
     - In Progress → "Complete" button (→ complete)
     - Complete → no action (done state)
   - Clicking a status button calls `exerciseService.updateTaskStatus(taskId, newStatus)`

4. **Role-based summary (below Kanban):**
   - Table showing: Role | Pending | In Progress | Complete | % Done
   - Rows: blue_staff, red_cell, exercise_control
   - Styled as a compact summary table

5. **Phase-based summary:**
   - Similar table: Phase | Pending | In Progress | Complete | % Done
   - Shows progress per exercise phase

**Drag-and-drop (optional but nice):** If feasible with existing React setup, support dragging task cards between columns to change status. If not, the button-based status changes are sufficient.

**Styling:**
- Kanban columns with subtle background colors: pending=#f5f5f5 (or dark equivalent), in_progress=#e8f4fd, complete=#e8fde8
- Task cards with left border color matching team (blue/red/gray)
- Overdue deadline styling: red text, slight pulsing background
- Responsive: columns stack vertically on narrow screens

**Refresh:** Fetch tasks on mount and when perspective/phase changes. Also expose a refresh button for manual update.
