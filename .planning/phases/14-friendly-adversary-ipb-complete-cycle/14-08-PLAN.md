  <files>frontend/src/components/exercise/CommanderDecisionPanel.tsx</files>
  <action>
Create `frontend/src/components/exercise/CommanderDecisionPanel.tsx`.

Props: `{ scenarioId: string, perspective: 'blue' | 'red', exercisePhase: string, coas: ScenarioCOA[] }`

**State:**
- `selectedDecision: 'accepted' | 'rejected' | 'modified' | 'combined' | 'returned' | null`
- `decisionNotes: string` -- commander's notes/reasoning
- `selectedCOAId: string | null` -- which COA the decision applies to
- `combinedElements: Record<string, string[]>` -- for 'combined' decisions, which elements from which COAs
- `submitting: boolean`
- `decisionResult: { hash: string } | null` -- confirmation after submission

**Layout:**

Per CONTEXT.md: Commander can accept, reject, modify, combine elements from multiple COAs, or send back for more analysis.

1. **COA Summary Row:** Show each scored COA in a compact card: name, combined score, ranking badge (1st, 2nd, etc.), and a brief 1-line from the narrative.

2. **Decision Action Buttons:**
   - "Accept COA" (green) -- Select one COA as the approved COA
   - "Reject COA" (red) -- Reject the selected COA with notes
   - "Modify COA" (yellow) -- Accept with modifications (opens notes for what to change)
   - "Combine COAs" (blue) -- Opens a UI to select elements from multiple COAs
   - "Return for Analysis" (gray) -- Send all COAs back to staff for more work

3. **Decision Details (shown when a decision type is selected):**
   - For "Accept": Dropdown to select which COA. Notes field (optional).
   - For "Reject": Dropdown to select which COA. Notes field (required -- must say why).
   - For "Modify": Dropdown to select base COA. Notes field (required -- must describe modifications). The system will create a modified copy.
   - For "Combine": Multi-select checkboxes next to each COA's elements (scheme, tasks, support concept). Drag or check elements to include from each COA. Notes field describing the combined intent.
   - For "Return": Notes field (required -- must specify what additional analysis is needed).

4. **Submit Decision button:**
   - Calls `exerciseService.recordDecision(selectedCOAId, selectedDecision, decisionNotes)`
   - Shows spinner during submission
   - On success: Shows confirmation with:
     - Decision type and COA name
     - SHA-256 hash: `{result.hash}` (first 16 chars with "..." for display)
     - "Blockchain anchoring pending" status indicator (the outbox will sync later)
     - Timestamp

5. **Decision History (below the active decision area):**
   - List of prior commander decisions for this scenario/phase
   - Each shows: decision type, COA name, timestamp, hash (abbreviated), blockchain tx (if anchored)

**Access Control:** Only render the decision action buttons if the user has commander authority (check `exerciseRole` -- could be 'exercise_control' or a commander-flagged role). For non-commanders, show the decisions read-only.

**Styling:**
- Decision buttons use strong colors matching their action
- The blockchain hash display uses monospace font, with a copy-to-clipboard icon
- Decision history entries use a timeline visual (vertical line with dots)
