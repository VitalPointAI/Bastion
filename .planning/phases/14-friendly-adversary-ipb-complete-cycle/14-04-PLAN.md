<task type="auto">
  <name>Task 1: Exercise Order Generator — WARNORD, OPORD, FRAGO</name>
  <files>backend/src/exercise/order-generator.ts</files>
  <action>
Create `backend/src/exercise/order-generator.ts` with an `ExerciseOrderGenerator` class.

Constructor takes: `pool: Pool`, `orderStore: OrderStore`, `documentStore: ScenarioDocumentStore`, `ipbStore: IPBStore`, `coaStore: COAStore`, `scenarioStore: ScenarioStore`, and LLM provider config.

**WARNORD generation:** `generateWARNORD(scenarioId: string, team: 'blue' | 'red', exercisePhase: string, visibleTeams: string[]): Promise<ExerciseOrder>`

1. Load scenario metadata and team-visible documents for the phase
2. Use LLM to generate WARNORDContent from document extractions:
   - **situation**: Brief operational situation from team's intelligence picture (SITREPs, OOBs)
   - **missionStatement**: Derived from team's ALERTORDs and campaign plan
   - **commandersIntent**: Extracted from senior leadership guidance documents
   - **initialTasks**: 3-5 tasks for the team's planning staff, e.g.:
     - For Blue WARNORD: "Conduct mission analysis of CJTF WestPAC AO", "Develop COAs for {phase}", "Prepare intelligence estimate"
     - For Red WARNORD: "Analyze TCC campaign objectives", "Develop COAs for PRC/TCC operations", "Assess Blue force dispositions"
     Each task includes: assignedTo (role), task (action), purpose (why), optional deadline
   - **timelineSummary**: Key dates and milestones from the exercise timeline
   - **serviceAndSupport**: Logistics summary from available documents
   - **commandAndSignal**: Command relationships and communication procedures

3. Per CONTEXT.md: Blue WARNORD references CJTF WestPAC mission and INDOPACOM guidance; Red WARNORD references PRC/TCC campaign objectives and PLA force structure. The LLM prompt must specify which team's perspective to use.
4. Store via `orderStore.create()` with status='draft'

**OPORD generation:** `generateOPORD(scenarioId: string, team: 'blue' | 'red', exercisePhase: string, selectedCOAId: string, visibleTeams: string[]): Promise<ExerciseOrder>`

1. Load selected COA, IPB assessment, scenario documents, and force dispositions
2. Generate full 5-paragraph OPORDContent:
   - **situation**: From IPB assessment — enemy forces, friendly forces, assumptions. Enemy info comes from team's enemy_assessment perspective IPB.
   - **mission**: From the selected COA's mission statement and commander's intent
   - **execution**: concept of operations from COA scheme, subordinate tasks from COA task assignments, coordinating instructions
   - **serviceAndSupport**: Logistics, personnel, civil affairs from available docs
   - **commandAndSignal**: Command relationships, reporting instructions, communications plan
3. Include task assignments derived from the OPORD execution paragraph
4. Store as draft

**FRAGO generation:** `generateFRAGO(scenarioId: string, baseOrderId: string, changedContext: string, visibleTeams: string[]): Promise<ExerciseOrder>`

1. Load the base order (OPORD or previous FRAGO)
2. Accept `changedContext` — a text description of what changed (e.g., "Day 10 SITREP shows Red reinforcements")
3. Use LLM to identify which OPORD paragraphs are affected and generate only the changed content
4. FRAGOContent includes: changedParagraphs (partial OPORDContent), effectiveTime, references (base order ID)
5. Store with reference to base order's exercise phase

**Manual authoring support:** `createDraftOrder(scenarioId: string, team: 'blue' | 'red', orderType: string, exercisePhase: string): Promise<ExerciseOrder>`
- Creates a blank order structure for manual staff authoring
- Pre-populates template fields based on order type

**Content update:** `updateOrderContent(orderId: string, content: WARNORDContent | OPORDContent | FRAGOContent, visibleTeams: string[]): Promise<void>`
- For staff edits to AI-generated content before publishing

NOTE: Do NOT use the existing `docx-generator.ts` / `pdf-generator.ts` directly — they are coupled to `planStore`. Per RESEARCH.md Pitfall 6, create new exercise-specific order content as JSONB. Document export (DOCX/PDF) from exercise orders will be a separate plan.

<task type="auto">
  <name>Task 2: Planning Board Service — Task Lifecycle and Notifications</name>
  <files>backend/src/exercise/planning-board-service.ts</files>
  <action>
Create `backend/src/exercise/planning-board-service.ts` with a `PlanningBoardService` class.

Constructor takes: `pool: Pool`, `orderStore: OrderStore`, `taskStore: TaskStore`, and `bus: MessageBus` (from existing messaging/message-bus.ts).

**Publish order:** `publishOrder(orderId: string, visibleTeams: string[]): Promise<{order: ExerciseOrder, tasks: PlanningTask[]}>`

1. Load the order via `orderStore.findById(orderId, visibleTeams)`
2. Validate order has content and is in 'draft' status
3. Extract task assignments from order content:
   - For WARNORD: initialTasks array
   - For OPORD: subordinate tasks from execution paragraph
   - For FRAGO: new/modified tasks from changed paragraphs
4. Create `PlanningTask` records via `taskStore.create()` for each task assignment:
   - `orderId`: the published order's ID
   - `scenarioId`: from order
   - `team`: from order
   - `assignedRole`: from task's assignedTo field
   - `title`: task action
   - `description`: task purpose
   - `deadline`: from task if specified
   - `status`: 'pending'
5. Mark order as published via `orderStore.markPublished(orderId)`
6. Publish notification via MessageBus:
```typescript
await bus.publish('exercise.order.published', {
  orderId,
  team: order.team,
  orderType: order.orderType,
  exercisePhase: order.exercisePhase,
  taskCount: tasks.length,
});
```
7. Return the order and created tasks

**Task status update:** `updateTaskStatus(taskId: string, status: 'pending' | 'in_progress' | 'complete', visibleTeams: string[]): Promise<PlanningTask>`
- Validate the task exists and is visible to the requester
- Call `taskStore.updateStatus(taskId, status)`
- If status is 'complete', publish notification: `exercise.task.completed`
- Return updated task

**Board summary:** `getBoardSummary(scenarioId: string, visibleTeams: string[]): Promise<BoardSummary>`
```typescript
interface BoardSummary {
  totalTasks: number;
  byStatus: { pending: number; in_progress: number; complete: number };
  byRole: Record<string, { pending: number; in_progress: number; complete: number }>;
  byPhase: Record<string, { pending: number; in_progress: number; complete: number }>;
  completionPercentage: number;
}
```
- Query tasks grouped by status, role, and phase
- Calculate overall completion percentage

**Task reassignment:** `reassignTask(taskId: string, newRole: string, visibleTeams: string[]): Promise<PlanningTask>`
- Updates assignedRole on the task
- Publishes `exercise.task.reassigned` notification

Export the `BoardSummary` type.
