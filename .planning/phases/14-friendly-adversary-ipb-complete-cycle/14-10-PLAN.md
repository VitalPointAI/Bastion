**ExerciseTimeline.tsx:**

Props: `{ scenario: ExerciseScenario, currentPhaseIndex: number, onPhaseSelect: (phase: string) => void }`

Use the installed `gantt-task-react` library (v0.3.9, already in package.json) to render the exercise phase timeline.

1. **Map exercise phases to Gantt tasks:**
   ```typescript
   const ganttTasks = scenario.exercisePhases.map((phase, index) => ({
     start: new Date(/* calculate based on index */),
     end: new Date(/* calculate based on index */),
     name: phase,
     id: `phase-${index}`,
     progress: index < currentPhaseIndex ? 100 : index === currentPhaseIndex ? 50 : 0,
     type: 'task' as const,
     styles: {
       backgroundColor: index === currentPhaseIndex ? '#3b82f6' : index < currentPhaseIndex ? '#22c55e' : '#6b7280',
       progressColor: index === currentPhaseIndex ? '#2563eb' : '#16a34a',
     },
   }));
   ```
   Since exercise phases don't have real dates, distribute them evenly across a visual timeline (each phase = 1 day for visualization purposes, or use the exercise's creation date as start and space phases 2 days apart).

2. **Current phase highlighting:**
   - Current phase bar is blue and animated (subtle pulse)
   - Past phases are green (complete)
   - Future phases are gray (not started)

3. **Click handler:** When a phase bar is clicked, call `onPhaseSelect(phase)` to navigate the dashboard to that phase's context.

4. **Phase labels:** Show phase name and index (e.g., "Phase 1: Competition", "Phase 3: Conflict Day 4")

5. **Fallback:** If `gantt-task-react` has import issues, implement a simple custom timeline using CSS flexbox:
   - Horizontal bar with phase segments, color-coded by status
   - Current phase marker (arrow or highlight)
   - Clickable segments

**GateControl.tsx:**

Props: `{ scenarioId: string, exercisePhase: string }`

Only fully functional for exercise_control role users. For other roles, show gate status as read-only.

1. **State:**
   - `gates: ExerciseGate[]` -- gates for current scenario
   - `phaseFilter: string | 'all'` -- filter by phase
   - `creatingGate: boolean` -- new gate form visible

2. **Gate list:**
   - Group gates by exercise phase
   - Each gate shows:
     - Gate type badge: 'info_release' (blue), 'phase_transition' (amber), 'order_required' (green)
     - Condition description text
     - Status: Open (green check) or Closed (red lock)
     - If open: Opened by, opened at timestamp
     - If closed: "Open Gate" button (exercise_control only)

3. **Create gate form:**
   - Exercise phase dropdown (from scenario.exercisePhases)
   - Gate type dropdown: Information Release, Phase Transition, Order Required
   - Condition description textarea
   - "Create Gate" button

4. **Open gate action:**
   - "Open Gate" button calls `exerciseService.openGate(gateId)`
   - Confirmation dialog: "Opening this gate will release {gateType} for {exercisePhase}. This action cannot be undone. Continue?"
   - After opening: Refresh gate list and show success message

5. **Phase readiness indicator:**
   - For each phase, show a summary: "N/M gates open" with progress bar
   - If all gates open: "Phase Ready" green badge
   - If not all open: "Phase Blocked" amber badge with list of remaining gates

6. **Per CONTEXT.md:** Phase transitions are explicit decisions, not automatic time-based triggers. The "Advance Phase" action should be a prominent button at the top of GateControl, enabled ONLY when all gates for the current phase are open. Clicking it calls `exerciseService.advancePhase(scenarioId)`.
