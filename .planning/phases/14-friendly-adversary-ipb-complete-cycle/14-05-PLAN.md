<task type="auto">
  <name>Task 1: Exercise REST API Routes</name>
  <files>backend/src/api/exercise.ts</files>
  <action>
Create `backend/src/api/exercise.ts` with an Express Router following the patterns in `backend/src/api/strategic.ts` and `backend/src/api/planning.ts`.

**Middleware:** Apply `withExerciseBarrier` middleware to ALL routes. This sets `req.visibleTeams` based on the user's exercise role. For routes that don't require authentication (if any), skip the barrier but default to 'exercise_control' visibility.

**Route structure:** Use `multer` for file upload routes (`multer.array('files')` for multi-file upload). All responses use JSON. Error handling follows existing API pattern (try/catch → res.status(500).json({error})).

**Scenario routes:**
- `POST /api/exercise/scenarios` — Create exercise scenario (name, designation, exercisePhases)
- `GET /api/exercise/scenarios` — List all scenarios
- `GET /api/exercise/scenarios/:id` — Get scenario by ID
- `PUT /api/exercise/scenarios/:id` — Update scenario
- `POST /api/exercise/scenarios/:id/advance-phase` — Advance to next exercise phase
- `DELETE /api/exercise/scenarios/:id` — Delete scenario and all child records

**Document routes:**
- `POST /api/exercise/scenarios/:id/upload` — Multi-file upload with `multer.array('files')`. For each uploaded file:
  1. Infer tags from the file's `originalname` (relative path) using `inferTagsFromPath()`
  2. Parse document via `DocumentParser.parse(buffer, mimeType)`
  3. Create `ScenarioDocument` record via `documentStore.create()` with inferred tags and parsed text
  4. Queue extraction via `ExerciseExtractionService.extractDocument()` (can be async — return 202 Accepted with document IDs if extraction is slow, or block if fast enough)
  Return: Array of created document records with their inferred tags
- `GET /api/exercise/scenarios/:id/documents` — List documents (filtered by visibleTeams). Optional query params: `phase`, `type`, `team`
- `GET /api/exercise/documents/:docId` — Get single document with extraction results

**IPB routes:**
- `POST /api/exercise/scenarios/:id/ipb/assemble` — Trigger IPB assembly. Body: `{ team, perspective, exercisePhase }`. Calls `IPBService.assembleIPB()`. Returns assembled IPB assessment.
- `GET /api/exercise/scenarios/:id/ipb` — List IPB assessments (filtered). Query params: `team`, `perspective`, `phase`
- `GET /api/exercise/ipb/:assessmentId` — Get single IPB assessment with overlay layers
- `GET /api/exercise/ipb/:assessmentId/history` — Get version history
- `POST /api/exercise/ipb/:assessmentId/update-from-sitrep` — Body: `{ sitrepDocId }`. Calls `IPBService.updateIPBFromSITREP()`.

**COA routes:**
- `POST /api/exercise/scenarios/:id/coas` — Create COA. Body: `{ team, exercisePhase, name, description, scheme }`
- `GET /api/exercise/scenarios/:id/coas` — List COAs (filtered). Query params: `team`, `phase`
- `GET /api/exercise/coas/:coaId` — Get single COA with scores
- `POST /api/exercise/coas/:coaId/score` — Trigger COA scoring. Calls `COAScoringService.scoreCOA()`. Returns scores.
- `POST /api/exercise/coas/:coaId/wargame` — Integrate wargame results. Body: `{ wargameSessionId, outcomes }`
- `POST /api/exercise/coas/:coaId/narrative` — Update narrative. Body: `{ narrative }` (staff edit of AI-generated narrative)
- `POST /api/exercise/coas/compare` — Compare multiple COAs. Body: `{ coaIds }`. Returns comparison matrix + rankings + narrative.
- `POST /api/exercise/coas/:coaId/decision` — Record commander decision. Body: `{ decision, notes }`. Returns `{ hash }`.

**Order routes:**
- `POST /api/exercise/scenarios/:id/orders/generate` — Generate order. Body: `{ team, orderType, exercisePhase, selectedCOAId? }`. Routes to WARNORD/OPORD/FRAGO generator based on orderType.
- `POST /api/exercise/scenarios/:id/orders/draft` — Create blank draft for manual authoring. Body: `{ team, orderType, exercisePhase }`
- `GET /api/exercise/scenarios/:id/orders` — List orders (filtered). Query params: `team`, `phase`, `type`
- `GET /api/exercise/orders/:orderId` — Get single order
- `PUT /api/exercise/orders/:orderId/content` — Update order content (staff edits)
- `POST /api/exercise/orders/:orderId/publish` — Publish order → creates planning tasks

**Task routes:**
- `GET /api/exercise/scenarios/:id/tasks` — List tasks (filtered). Query params: `role`, `status`, `phase`
- `GET /api/exercise/scenarios/:id/tasks/summary` — Board summary (completion stats)
- `PUT /api/exercise/tasks/:taskId/status` — Update task status. Body: `{ status }`
- `PUT /api/exercise/tasks/:taskId/reassign` — Reassign task. Body: `{ role }`

**Gate routes:**
- `POST /api/exercise/scenarios/:id/gates` — Create gate. Body: `{ exercisePhase, gateType, conditionDescription }`
- `GET /api/exercise/scenarios/:id/gates` — List gates. Query param: `phase`
- `POST /api/exercise/gates/:gateId/open` — Open gate (controller action)
- `GET /api/exercise/scenarios/:id/gates/phase-ready/:phase` — Check if phase is ready (all gates open)

Instantiate stores and services at the router module level (or use a simple dependency injection pattern consistent with existing API files). Use the existing `pool` from database configuration.
