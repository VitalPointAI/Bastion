The prompt establishes Ironclaw as a demanding but helpful chief of staff, instructs challenge-then-recommend style, red-team/devil's advocate probing. For sections after problem-framing, include cross-references to prior section outputs from derivedDesign. When kgContext is provided (including any results from background research), incorporate relevant knowledge graph data into the prompt to ground questions in scenario-specific intel.

- `getSectionReviewPrompt(section, derivedDesign)`: Returns prompt instructing Ironclaw to summarize what was captured for the section and ask for confirmation/revision.
- `getSynthesisNarrativePrompt(derivedDesign)`: Returns prompt for generating the final operational approach narrative tying all 4 sections together.
- All prompts should reference JP 5-0 doctrine and Strange's CG-CC-CR-CV framework where appropriate.

**design-interview-store.ts:**
- Class `DesignInterviewStore` with methods:
  - `saveInterviewProgress(problemSetId, section, confirmed)`: Persists which sections have been confirmed via interview
  - `getInterviewProgress(problemSetId)`: Returns section confirmation status
  - `markSectionConfirmed(problemSetId, section)`: Marks a section as reviewed/confirmed
  - `getDesignInterviewState(problemSetId)`: Convenience wrapper returning full progress
- Uses the existing `pool` from db/pool.ts. Store interview progress in `design_interview_progress` table (create via inline SQL if not exists — same pattern as other stores).
- Table: problem_set_id (text), section (text), confirmed (boolean), confirmed_at (timestamptz), created_at, updated_at. Unique on (problem_set_id, section).

**design-interview-service.ts:**
- Mirror the structure of `interview-service.ts` closely.
- Internal functions (graph nodes):
  - `getInterviewLLM()`: Uses `createLLMForAgent()` with Ironclaw's model config
  - `routeEntry(state)`: Returns 'ask_question' if phase='start', 'process_answer' if phase='continue'
  - `askQuestion(state)`: Builds system prompt via `getDesignInterviewSystemPrompt()`, filters system messages from conversation (CRITICAL: use `.type !== 'system'` filter per Pitfall 2), invokes LLM, increments questionsAsked. If awaitingSectionConfirm is true, calls `getSectionReviewPrompt()` instead.
  - `processAnswer(state)`: Extracts structured data from user's answer using LLM, merges into derivedDesign, updates sectionCoverage. **KG gap detection and background research dispatch (locked decision):** After extracting structured data and merging into derivedDesign, evaluate KG context completeness for the current section:
    1. Compare entities/concepts referenced in the user's answer and derivedDesign against the kgContext provided to the current turn. Look for referenced actors, geographic features, force structures, or strategic documents that have no corresponding KG entries.
    2. If gaps are detected, build a research query describing the missing knowledge (e.g., "PRC naval force disposition in Taiwan Strait" or "UN Security Council Resolution references for legitimacy assessment").
    3. Fire-and-forget dispatch a background research agent using the existing agent dispatch mechanism (look for `dispatchAgent`, `launchBackgroundTask`, or similar in orchestration/ — wrap the call in try/catch, NEVER await the result).
    4. Append dispatched research topics to `state.pendingResearch` array in derivedDesign so subsequent turns can check if research has returned.
    5. When kgContext is enriched by research results in subsequent turns (the research agent ingests findings into the knowledge graph), the next `askQuestion` call will pick up the enriched context via `getDesignInterviewSystemPrompt(section, derivedDesign, kgContext)`.
    6. CRITICAL: The interview MUST continue immediately regardless of research dispatch success/failure (Pitfall 5). Never block on research results.
  - `checkSectionCoverage(state)`: Calls `evaluateSectionCoverage()`. Routes to 'ask_question' (keep probing), 'section_review_gate' (coverage met), 'advance_section', or 'synthesize_narrative'.
  - `sectionReviewGate(state)`: Sets awaitingSectionConfirm=true, returns summary for user review. Graph returns to __end__ to wait for user input.
  - `advanceSection(state)`: Moves currentSection to next in SECTION_ORDER, resets awaitingSectionConfirm. Calls `designInterviewStore.markSectionConfirmed()`.
  - `synthesizeNarrative(state)`: Uses `getSynthesisNarrativePrompt()` to generate final operational approach narrative. Sets isComplete=true.
- `buildDesignInterviewGraph()`: Constructs StateGraph with conditional edges matching the topology in research Pattern 1.
- Export class `DesignInterviewService` with:
  - `startInterview(problemSetId, mode='new')`: Checks ScopingInterview prerequisite. Fetches initial KG context for the problem set (brain graph query for relevant entities). Creates graph config with thread_id `design-interview-${problemSetId}`. Invokes graph with initial state including kgContext. Returns first AI message + meta.
  - `continueInterview(problemSetId, userMessage)`: Loads state from checkpointer, fetches fresh kgContext (may include results from prior background research), appends user message, invokes graph. Returns AI response + meta.
  - `confirmSection(problemSetId)`: Sets awaitingSectionConfirm=false in state, re-invokes graph to advance. Returns next section's first question or synthesis.
  - `getInterviewState(problemSetId)`: Returns current meta from checkpointer (for resume after page refresh).
  - `resetInterview(problemSetId)`: Clears checkpointer state and store for fresh start.

CRITICAL: Use thread_id `design-interview-${problemSetId}` (NOT `interview-${problemSetId}`) to avoid collision with ScopingInterview (Pitfall 1).
CRITICAL: Filter system messages before LLM invocation using `.type !== 'system'` (Pitfall 2).
CRITICAL: Background KG research dispatch must be fire-and-forget with try/catch, never awaited (Pitfall 5).
