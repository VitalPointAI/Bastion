**design-interview.ts:**
- Create Express Router exported as `designInterviewRouter`
- Endpoints (all under `/api/design-interview`):

  - `POST /:problemSetId/start` — Start a new design interview
    - Body: `{ mode?: 'new' | 'revision' }`
    - Calls `designInterviewService.startInterview(problemSetId, mode)`
    - Returns 200: `{ message: string, state: DesignInterviewMeta }`
    - Returns 400 if scoping prerequisite not met (service returns blocked: true)

  - `POST /:problemSetId/continue` — Continue interview with user message
    - Body: `{ message: string }`
    - Calls `designInterviewService.continueInterview(problemSetId, userMessage)`
    - Returns 200: `{ message: string, state: DesignInterviewMeta }`

  - `POST /:problemSetId/confirm-section` — Confirm current section review gate
    - Body: (empty or `{ revisions?: Record<string, unknown> }`)
    - Calls `designInterviewService.confirmSection(problemSetId)`
    - Returns 200: `{ message: string, state: DesignInterviewMeta }`

  - `GET /:problemSetId/state` — Get current interview state (for resume)
    - Calls `designInterviewService.getInterviewState(problemSetId)`
    - Returns 200: `{ state: DesignInterviewMeta | null }`

  - `DELETE /:problemSetId` — Reset interview for fresh start
    - Calls `designInterviewService.resetInterview(problemSetId)`
    - Returns 204

- Each route wraps in try/catch returning 500 with error message on failure.
- Import auth middleware from existing pattern (check other routes like design.ts for the pattern — likely `requireAuth` or session check).

**index.ts:**
- Import `designInterviewRouter` from `./api/design-interview.js`
- Add `app.use('/api/design-interview', designInterviewRouter)` alongside existing route mounts
- Place near other design-related routes (look for design.ts or design-revisions.ts mount)
