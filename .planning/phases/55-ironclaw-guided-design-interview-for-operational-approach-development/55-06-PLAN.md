  <action>
Extend the existing `useDesignInterview` hook with optional Yjs collaborative state:

**Add Yjs document connection:**
- Use `useYjsDocument` with documentId `design-interview-${problemSetId}` (Pitfall 3: unique prefix, not just problemSetId)
- Only activate Yjs when interview is active (isActive === true) to avoid unnecessary WebSocket connections
- Pass current user's DID, name, and JPP staff role from the existing user context (ProblemSetContext or auth context)

**Shared state maps:**
- `interviewState` map: Mirror the local interview state (currentSection, sectionCoverage, pendingQuestion, lastSectionSummary) into Yjs for all participants to see
- `participantRoles` map: On join, write `{ [userDid]: userRole }`. This tells the backend which roles are present for role-directed questioning.
- When local state updates (from API responses), write to Yjs maps
- When Yjs remote updates arrive (another user's action), merge into local state

**Role awareness in API calls:**
- When calling startInterview or continueInterview, include the `participantRoles` map snapshot in the request body so the backend can direct questions to specific roles
- Add to API calls: `participantRoles: Object.fromEntries(participantRoles.entries())`

**New return values:**
```typescript
{
  // ...existing returns...
  participants: Map<string, string>;  // did -> role of active participants
  isCollaborative: boolean;           // true if >1 participant
}
```

**Cleanup:**
- On unmount or interview reset, remove user from participantRoles map
- Clean up Yjs document connection

CRITICAL: Use documentId `design-interview-${problemSetId}` (NOT just problemSetId) to avoid Yjs document ID collision with COA sketch documents (Pitfall 3).
