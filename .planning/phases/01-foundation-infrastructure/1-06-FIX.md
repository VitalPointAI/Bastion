  <name>Task 1: Research Chain Signatures derived_public_key vs public_key</name>
  <files>frontend/src/lib/mpcRecovery.ts</files>
  <action>
    Investigate the correct Chain Signatures API pattern for per-user key derivation:

    1. Research NEAR Chain Signatures documentation:
       - Check if `derived_public_key` method exists on MPC contract
       - If yes: Use it with derivation path parameter
       - If no: Verify if root key + path-at-signing-time is the correct pattern

    2. Understanding Chain Signatures key model:
       - Root public key: MPC network's master key (same for everyone)
       - Derived keys: Child keys at specific derivation paths
       - Two possible patterns:
         a) derived_public_key(path) returns path-specific key upfront
         b) Root key registered, path used during signing (derivation happens at sign-time)

    3. If pattern (a) exists:
       - Update deriveMPCPublicKey() to call derived_public_key with path
       - Pass derivation path as argument to MPC contract

    4. If pattern (b) is correct (root key + path at signing):
       - Document this in code comments
       - The "same key for all users" behavior is actually correct
       - Different users have different paths → different signatures
       - The public key stored is the root, derivation happens during sign

    5. Update code comments to reflect correct understanding.

    Don't hand-roll: Key derivation algorithms - use Chain Signatures as designed.
  </action>
  <verify>
    - Understand correct Chain Signatures key derivation pattern
    - Code reflects correct understanding with clear comments
    - If derived_public_key exists: different users get different keys
    - If root+path pattern: document why same root key is correct
  </verify>
