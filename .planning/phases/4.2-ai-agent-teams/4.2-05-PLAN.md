**Tech stack:**
- pg-boss for reliable message delivery (already used for blockchain sync)
- XState v5 for workflow state management (existing)
- Zod for message schema validation
- Existing ABAC enforcer for access control
- PostgreSQL for message persistence and audit trail

**Key architecture decisions:**
- Messages are immutable once created - full audit trail
- Every message carries classification and dissemination attributes
- ABAC enforcement happens at subscription delivery time (lazy evaluation)
- Support both synchronous (request/response) and asynchronous (pub/sub) patterns
- Messages can be addressed to: agents (by DID), teams (by DID), channels (by topic)
- Dead letter queue for undeliverable messages with audit logging

**Reference: Message Envelope Structure**
```typescript
interface MessageEnvelope {
  messageId: string;           // UUID v4
  correlationId?: string;      // For request/response pairing
  timestamp: string;           // ISO 8601

  // Routing
  source: {
    did: string;               // Sender DID (agent, user, system)
    type: 'agent' | 'user' | 'system';
  };
  destination: {
    type: 'agent' | 'team' | 'channel' | 'broadcast';
    target: string;            // DID or channel name
  };

  // Security attributes (from ABAC)
  attributes: {
    classification: 'UNCLASS' | 'CUI' | 'CONFIDENTIAL' | 'SECRET' | 'TOPSECRET';
    releasability: string[];   // REL TO countries/groups
    dissemination: string[];   // NOFORN, ORCON, PROPIN, etc.
    originator: string;        // DID of content originator
    orcon: boolean;           // Originator controlled
  };

  // Payload
  messageType: string;         // e.g., 'task.assigned', 'data.request', 'status.update'
  payload: unknown;            // JSON-serializable content

  // Delivery tracking
  priority: 'low' | 'normal' | 'high' | 'critical';
  ttl?: number;               // Time-to-live in seconds
  requiresAck?: boolean;      // Delivery acknowledgment required
}
```

**Reference: Channel Types**
```typescript
type ChannelType =
  | 'agent.direct'            // Direct agent-to-agent
  | 'team.internal'           // Within a team
  | 'team.broadcast'          // To all team members
  | 'system.events'           // System-wide events
  | 'workflow.updates'        // Workflow state changes
  | 'audit.log';              // Audit trail channel
```

**Reference: Existing ABAC Infrastructure**
From `backend/src/security/abac-enforcer.ts`:
- `CLASSIFICATION_LEVELS`: UNCLASS(1), CUI(2), CONFIDENTIAL(3), SECRET(4), TOPSECRET(5)
- `SubjectAttributes`: clearance, nationality, organization, role, caveats
- `ObjectAttributes`: classification, releasability, dissemination, orcon
- `ABACEnforcer.enforce(subject, object, action)`: Core access control

     TASK 4: Message Bus Core

<task id="4" type="auto">
<what>Create the core MessageBus service with pub/sub and delivery</what>
<why>Central hub for all inter-component communication</why>
<how>
1. Create `backend/src/messaging/message-bus.ts`:
   - `MessageBus` singleton class:
     - Dependencies: MessageStore, MessageABACFilter, AgentRegistry, pg-boss

     - **Publishing:**
       - `publish(envelope: CreateMessageInput)` - Create and route message
         - Validate envelope against schema
         - Generate messageId if not provided
         - Store in message store
         - Route based on destination type
         - Return messageId

     - **Subscribing:**
       - `subscribe(did, options)` - Register subscription
         - options: { channels?: string[], messageTypes?: string[], callback }
         - Store subscription in memory + database for persistence
       - `unsubscribe(did, subscriptionId)` - Remove subscription

     - **Delivery:**
       - `deliverToAgent(message, agentDid)` - Direct agent delivery
         - Check ABAC authorization
         - Queue via pg-boss for reliable delivery
         - Record delivery attempt
       - `deliverToTeam(message, teamDid)` - Team broadcast
         - Get team members from TeamRegistry
         - Deliver to each member (ABAC-filtered)
       - `deliverToChannel(message, channel)` - Channel subscribers
         - Get all channel subscribers
         - Deliver to each (ABAC-filtered)

     - **Request/Response:**
       - `request(envelope, timeoutMs)` - Send and await response
         - Generate correlationId
         - Publish message
         - Wait for response with matching correlationId
         - Return response or throw timeout
       - `respond(originalMessageId, response)` - Reply to request
         - Create response with correlationId from original
         - Deliver to original sender

2. Create pg-boss queue integration:
   - Queue: `message-delivery`
   - Job data: { messageId, recipientDid }
   - Worker processes deliveries with retries
   - Dead letter handling for failed deliveries
</how>
