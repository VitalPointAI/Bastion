# Phase 4.2: AI Agent Teams - Context

**Gathered:** 2026-01-19
**Status:** Ready for research

<vision>
## How This Should Work

A comprehensive agent orchestration framework using LangChain (with crewAI patterns) that enables multi-agent teams to collaborate on complex tasks. The system supports three modes of operation:

1. **Task-based crews** — Define a team for a specific purpose (e.g., "strategic analysis crew"), invoke it when needed, get structured results back.

2. **Persistent collaborators** — Long-running teams that work together continuously, building shared context and institutional knowledge over time.

3. **Dynamic assembly** — Agents pulled together on-the-fly based on what the current task needs — no predefined crew required.

Agents communicate via a shared message bus, but with security-aware compartmentalization. Agents only see messages at or below their security clearance level — leveraging the existing ABAC and classification system from Phase 2. A TOP SECRET agent can observe all traffic, but a SECRET agent can't see TOP SECRET communications.

The system includes memory and learning capabilities — agents build knowledge over time, remember past interactions, and improve through experience. Tools and a secure MCP server provide agents with real capabilities beyond just conversation.

A **visual workflow builder** lets operators compose agent teams and define their flows through a drag-and-drop interface — making crew creation accessible without code changes.

</vision>

<essential>
## What Must Be Nailed

- **Security-aware orchestration** — Classification-based compartmentalization is non-negotiable. Agents must only see what their clearance level allows. This is a military system.

- **Flexible team creation** — Easy to define, modify, and invoke crews. Visual workflow builder for non-developers, but also supports code-based definitions for power users.

- **Tool/MCP integration** — Agents need real capabilities. Secure MCP server provides access to tools, databases, external systems — all through a controlled, audited interface.

- **Memory & learning** — Agents that build knowledge over time. Shared crew memory, individual agent memory, and the ability to learn from past executions.

</essential>

<boundaries>
## What's Out of Scope

No explicit exclusions identified — the phase should include everything that fits the comprehensive agent orchestration vision. However, practical scope will be refined during research based on what's achievable with LangChain/crewAI integration.

</boundaries>

<specifics>
## Specific Ideas

- **Tech stack:** LangChain as the foundation, with crewAI patterns for orchestration (crewAI integrates with LangChain)
- **UI:** Visual workflow builder with drag-and-drop interface for composing agent teams and flows
- **Security model:** Message bus with clearance-based filtering — ties into existing ABAC/classification infrastructure
- **Agent DIDs:** Each agent gets a decentralized identity (`did:near:agent-{agentId}`) from Phase 4.1's foundation

</specifics>

<notes>
## Additional Context

This phase significantly expands the original roadmap scope for 4.2. The original plan was focused on per-agent model assignment and dynamic agent creation. The new vision encompasses a full orchestration framework with:

- Multi-modal team configurations (task-based, persistent, dynamic)
- Security-compartmentalized communication
- Visual workflow builder
- Memory and learning systems
- MCP server integration for tool access

Research phase should evaluate:
- LangChain vs crewAI vs hybrid approach
- Message bus implementation with clearance filtering
- Memory architecture (vector stores, conversation history, learning)
- MCP server security model

</notes>
