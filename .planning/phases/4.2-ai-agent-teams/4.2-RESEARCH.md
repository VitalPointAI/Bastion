# Phase 4.2: AI Agent Teams - Research

**Researched:** 2026-01-19
**Domain:** Multi-agent orchestration with LangGraph, MCP integration, visual workflow builder
**Confidence:** HIGH

<research_summary>
## Summary

Researched the AI agent orchestration ecosystem for building multi-agent teams with security-aware compartmentalization, per-agent model configuration, and visual workflow composition. The standard approach uses LangGraph.js as the orchestration backbone with the supervisor pattern for hierarchical agent coordination, MCP (Model Context Protocol) for standardized tool access, and PostgresSaver for production state persistence.

Key finding: Don't hand-roll agent orchestration primitives. LangGraph 1.0 provides battle-tested patterns for state management, checkpointing, human-in-the-loop, and multi-agent coordination. CrewAI is now independent from LangChain (as of 2025), making LangGraph the clear choice for TypeScript projects requiring tight integration with the existing codebase.

**Primary recommendation:** Use LangGraph.js with supervisor pattern + MCP SDK for tool access + PostgresSaver (already have PostgreSQL) + React Flow for visual workflow builder. Agent DIDs integrate naturally with existing Phase 2 DID infrastructure.
</research_summary>

### Pattern 1: Supervisor Multi-Agent (Official LangGraph Pattern)
**What:** Central supervisor routes tasks to specialized worker agents
**When to use:** Hierarchical team structures, task delegation
**Example:**
```typescript
// Source: @langchain/langgraph-supervisor docs
import { createSupervisor, createReactAgent } from "@langchain/langgraph-supervisor";
import { ChatOpenAI } from "@langchain/openai";

// Create specialized workers
const osintAgent = createReactAgent({
  llm: new ChatOpenAI({ model: "gpt-4o" }),
  tools: [/* osint tools */],
  name: "osint_collector",
  description: "Collects open source intelligence"
});

const analysisAgent = createReactAgent({
  llm: new ChatAnthropic({ model: "claude-sonnet-4-20250514" }),
  tools: [/* analysis tools */],
  name: "analyst",
  description: "Analyzes intelligence products"
});

// Create supervisor to coordinate
const supervisor = createSupervisor({
  llm: new ChatOpenAI({ model: "gpt-4o" }),
  agents: [osintAgent, analysisAgent],
  prompt: "You are a team coordinator. Route tasks to appropriate agents."
});

// Compile with persistence
const checkpointer = new PostgresSaver(pool);
await checkpointer.setup();
const workflow = supervisor.compile({ checkpointer });
```

### Pattern 2: Security-Aware State Filtering (Custom for BASTION)
**What:** Filter agent state based on classification level before handoff
**When to use:** Multi-classification environments, coalition operations
**Example:**
```typescript
// Custom state filter for classification-based compartmentalization
import { StateGraph, MessagesAnnotation } from "@langchain/langgraph";

// Extend state with classification
const ClassifiedStateAnnotation = Annotation.Root({
  ...MessagesAnnotation.spec,
  classification: Annotation<"UNCLASS" | "SECRET" | "TOPSECRET">,
  agentClearance: Annotation<"UNCLASS" | "SECRET" | "TOPSECRET">,
});

// Filter messages before agent sees them
function filterByClassification(state: typeof ClassifiedStateAnnotation.State) {
  const clearanceLevel = CLASSIFICATION_LEVELS[state.agentClearance];
  return {
    ...state,
    messages: state.messages.filter(msg => {
      const msgLevel = CLASSIFICATION_LEVELS[msg.classification || "UNCLASS"];
      return msgLevel <= clearanceLevel;
    })
  };
}

const graph = new StateGraph(ClassifiedStateAnnotation)
  .addNode("filter", filterByClassification)
  .addNode("agent", agentNode)
  .addEdge("filter", "agent")
  // ...
```

### Pattern 4: Dynamic Graph from JSON (Visual Builder Backend)
**What:** Convert visual workflow JSON to LangGraph at runtime
**When to use:** User-defined agent compositions
**Example:**
```typescript
interface WorkflowDefinition {
  nodes: Array<{
    id: string;
    type: "agent" | "tool" | "router";
    config: Record<string, unknown>;
  }>;
  edges: Array<{
    source: string;
    target: string;
    condition?: string;
  }>;
}

function buildGraphFromDefinition(def: WorkflowDefinition): CompiledGraph {
  const graph = new StateGraph(AgentStateAnnotation);

  // Add nodes
  for (const node of def.nodes) {
    if (node.type === "agent") {
      graph.addNode(node.id, createAgentNode(node.config));
    } else if (node.type === "router") {
      graph.addNode(node.id, createRouterNode(node.config));
    }
  }

  // Add edges
  for (const edge of def.edges) {
    if (edge.condition) {
      graph.addConditionalEdges(edge.source,
        (state) => evaluateCondition(edge.condition, state),
        { [edge.target]: edge.target }
      );
    } else {
      graph.addEdge(edge.source, edge.target);
    }
  }

  return graph.compile({ checkpointer });
}
```

### Anti-Patterns to Avoid
- **Sharing raw state between agents:** Always use the supervisor pattern or explicit handoff tools
- **Storing secrets in agent state:** Use MCP for secure tool access, never pass API keys through agent state
- **Ignoring classification in multi-agent flows:** Every message handoff must respect clearance levels
- **Custom orchestration logic:** LangGraph's supervisor and handoff patterns are battle-tested
- **Polling for agent completion:** Use LangGraph's async stream with callbacks instead

## Don't Hand-Roll

Problems that look simple but have existing solutions:

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Agent state persistence | Custom DB schema + serialization | LangGraph PostgresSaver | Checkpointing, time-travel, fault recovery built-in |
| Multi-agent coordination | Custom message passing | LangGraph supervisor pattern | Handles handoffs, routing, state sharing |
| Tool protocol | Custom tool interface | MCP SDK | Standard protocol, 1000+ community servers |
| Agent memory | Custom memory schema | LangGraph Store interface | Cross-thread, semantic search, namespaced |
| Visual graph editing | Custom canvas | React Flow | Drag-drop, zoom, selection, undo/redo |
| Agent DID creation | Custom DID logic | Existing Phase 2 DID service | Already built: `did:near:agent-{agentId}` |
| LLM provider switching | Provider-specific code | Existing provider abstraction | Already built in Phase 4 Plan 3-FIX |

**Key insight:** The ecosystem has matured significantly in 2025. LangGraph 1.0 (released October 2025) provides production-grade primitives that previously required custom implementations. MCP (under Linux Foundation) is now the standard for tool interoperability. React Flow powers most visual workflow builders including Flowise's backend.

<common_pitfalls>
## Common Pitfalls

### Pitfall 1: State Explosion in Multi-Agent Systems
**What goes wrong:** Each checkpoint stores full state, leading to unbounded database growth
**Why it happens:** Default checkpointing stores complete message history at every step
**How to avoid:** Implement message trimming, use memory store for long-term facts, set TTL on checkpoints
**Warning signs:** checkpoint_* tables growing rapidly, slow state retrieval

### Pitfall 2: Deadlocks in Supervisor Routing
**What goes wrong:** Supervisor routes to agent A, which hands off to B, which routes back to A
**Why it happens:** Circular dependencies in agent responsibilities
**How to avoid:** Define clear agent boundaries, use "handoff" tools explicitly, log routing decisions
**Warning signs:** Infinite loops in agent logs, timeout errors

### Pitfall 3: Classification Leakage Between Agents
**What goes wrong:** TOP SECRET data visible to SECRET-cleared agent through shared state
**Why it happens:** Not filtering state on every agent transition
**How to avoid:** Filter state BEFORE every agent invocation, audit message flows
**Warning signs:** Security audit failures, agents accessing data above clearance

### Pitfall 4: MCP Server Connection Management
**What goes wrong:** Server connections accumulate, memory leaks, socket exhaustion
**Why it happens:** Not properly closing MCP client sessions
**How to avoid:** Use connection pooling, implement cleanup on workflow completion
**Warning signs:** "Too many open files" errors, memory growth over time

### Pitfall 5: Tool Calling Rate Limits
**What goes wrong:** Agents hit LLM rate limits when making many tool calls
**Why it happens:** Each tool call requires LLM invocation for decision
**How to avoid:** Batch tool results, implement backoff, use cheaper models for routing
**Warning signs:** 429 errors, long agent response times
</common_pitfalls>

### PostgresSaver Setup for Production
```typescript
// Source: LangGraph.js persistence docs
import { PostgresSaver } from "@langchain/langgraph-checkpoint-postgres";
import pg from "pg";

// Use existing pool from backend
const pool = new pg.Pool({
  connectionString: process.env.DATABASE_URL,
});

const checkpointer = new PostgresSaver(pool, undefined, {
  schema: "langgraph_checkpoints" // Isolated schema
});

// IMPORTANT: Call setup() on first run to create tables
await checkpointer.setup();

// Compile graph with checkpointer
const graph = workflow.compile({ checkpointer });

// Invoke with thread ID for persistence
const result = await graph.invoke(
  { messages: [{ role: "user", content: "Analyze this document" }] },
  { configurable: { thread_id: "mission-001" } }
);
```

const server = new McpServer({
  name: "bastion-tools",

  "search_documents",

## Open Questions

Things that couldn't be fully resolved:

1. **LangGraph Platform vs Self-Hosted for Security**
   - What we know: LangGraph Platform provides auth/access control
   - What's unclear: Whether it meets military security requirements (FedRAMP, etc.)
   - Recommendation: Self-host with PostgresSaver, build custom auth layer

2. **React Flow vs Flowise Components**
   - What we know: React Flow is the underlying library Flowise uses
   - What's unclear: Whether to use raw React Flow or extract Flowise components
   - Recommendation: Use React Flow directly for control, reference Flowise for patterns

3. **MCP v2 Migration Path**
   - What we know: v2 coming Q1 2026, v1.x supported 6 months after
   - What's unclear: Breaking changes in v2
   - Recommendation: Build on v1.25.x, plan migration after v2 stable

4. **Agent-to-Agent Cross-Classification Communication**
   - What we know: LangGraph supports multi-agent, we have ABAC
   - What's unclear: Optimal pattern for classification downgrade in handoffs
   - Recommendation: Implement filter node before every agent transition
