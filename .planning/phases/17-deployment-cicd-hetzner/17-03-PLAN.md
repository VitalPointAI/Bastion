  <instructions>
**Part A: Provision Hetzner Server**

1. Go to [Hetzner Cloud Console](https://console.hetzner.cloud/) and create a new project (or use existing).

2. Create a server:
   - **Name:** bastion-dev
   - **Location:** Choose nearest (Falkenstein, Nuremberg, or Helsinki for EU; Ashburn/Hillsboro for US)
   - **Image:** Ubuntu 24.04
   - **Type:** CAX21 (8GB RAM, ~$7/month) or CAX31 (16GB RAM, ~$13/month) — CAX31 recommended for Neo4j headroom
   - **SSH Key:** Add your SSH public key (or create a new one)
   - **Firewall:** Create one allowing TCP 22, 80, 443 inbound (or let server-setup.sh handle UFW)

3. Note the server's **public IP address**.

4. SSH into the server as root and run the bootstrap script:
   ```bash
   # Copy server-setup.sh to the server first
   scp scripts/server-setup.sh root@<SERVER_IP>:/tmp/
   ssh root@<SERVER_IP> bash /tmp/server-setup.sh <YOUR_DOMAIN> "<YOUR_SSH_PUBLIC_KEY>"
   ```
   (Replace `<YOUR_DOMAIN>` with the domain you'll point to this server, `<YOUR_SSH_PUBLIC_KEY>` with the public key for GitHub Actions deploy key)

5. Configure DNS: Point your domain to the server IP (A record). Wait for propagation.

6. Edit `.env.prod` on the server:
   ```bash
   ssh deploy@<YOUR_DOMAIN>
   nano /home/deploy/bastion/.env.prod
   # Set real POSTGRES_PASSWORD and NEO4J_PASSWORD (use strong random values)
   # Add any other backend secrets (OPENAI_API_KEY, NEAR keys, etc.)
   ```

7. **BLOCKING VERIFICATION — .env.prod secrets must not be template values:**
   ```bash
   ssh deploy@<YOUR_DOMAIN> "grep -c 'CHANGE_ME' /home/deploy/bastion/.env.prod"
   ```
   This MUST return `0`. If it returns any non-zero number, .env.prod still contains template placeholder values that will cause database authentication failures. Go back to step 6 and replace ALL `CHANGE_ME` values with real passwords before proceeding.

**Part B: Generate GitHub Actions Deploy Key**

1. Generate a passphrase-free SSH key for GitHub Actions:
   ```bash
   ssh-keygen -t ed25519 -C "github-actions-deploy" -f deploy_key -N ""
   ```

2. Add the **public** key to the server:
   ```bash
   ssh deploy@<YOUR_DOMAIN> "cat >> ~/.ssh/authorized_keys" < deploy_key.pub
   ```

3. The **private** key (contents of `deploy_key`) will be added as a GitHub secret in Part C.

**Part C: Configure GitHub Repository Secrets**

Go to GitHub repo **Settings > Secrets and variables > Actions** and add:

**Secrets (encrypted):**
| Secret Name | Value |
|-------------|-------|
| `HETZNER_HOST` | Server IP or domain |
| `HETZNER_USER` | `deploy` |
| `HETZNER_SSH_KEY` | Contents of `deploy_key` (private key) |
| `VITE_PRIVY_APP_ID` | From Privy dashboard |
| `VITE_PINATA_GATEWAY` | Pinata gateway URL |
| `GHCR_TOKEN` | PAT with `read:packages` (only if repo is private) |
| `GHCR_USER` | GitHub username (only if repo is private) |

**Variables (plaintext, non-secret):**
| Variable Name | Value |
|---------------|-------|
| `VITE_NEAR_NETWORK` | `testnet` |
| `VITE_NEAR_RPC` | `https://rpc.testnet.near.org` |
| `VITE_BACKEND_URL` | `https://<YOUR_DOMAIN>` |

**Part D: Trigger Initial Deployment**

1. Commit and push the Phase 17 files (Plans 01+02 output) to master. This should trigger the deploy workflow.

2. Watch the Actions tab on GitHub for the workflow run.

3. If the workflow succeeds, verify:
   - Visit `https://<YOUR_DOMAIN>` — should see Bastion login page
   - Check server: `ssh deploy@<YOUR_DOMAIN> "docker compose -f /home/deploy/bastion/docker-compose.prod.yml ps"` — all containers should be running
