Create a hook managing timeline state, historical data fetching, and recency computation.

`useBrainTimeline(problemSetId: string, currentData: BrainGraphData)`

State:
- `selectedTime: Date | null` — null means "live/current". When set, shows historical state.
- `timeRange: { start: Date; end: Date }` — computed from the earliest and latest `createdAt` in currentData nodes
- `futureTime: Date` — extends 7 days past "now" for the prediction zone
- `isLive: boolean` — derived: `selectedTime === null`
- `historicalData: BrainGraphData | null` — fetched when selectedTime changes
- `loading: boolean`

Methods:
- `setSelectedTime(time: Date | null): void` — sets time, triggers fetch if non-null
- `goLive(): void` — sets selectedTime to null, clears historicalData
- `computeRecency(node: BrainNode): number` — returns 0-1 value based on how recent the node is relative to the current view time. 1 = very recent (created within last 24h of view time), 0 = stale (created >30 days before view time). Linear interpolation between.

Fetch logic:
- When `selectedTime` changes to non-null, debounce 300ms, then fetch `GET /api/brain/graph-snapshot?problemSetId=${problemSetId}&at=${selectedTime.toISOString()}`
- Store result in historicalData
- When selectedTime is in the future zone (> now), don't fetch — instead, take current data and mark predicted nodes with `isFuturePrediction = true`. For basic predictions: if a container has been adding nodes at rate R per week, project R * weeks_ahead new ghost nodes. This is a simple heuristic — mark them with predictionConfidence proportional to temporal distance (closer = higher confidence).

Recency computation for live view:
- Provide `applyRecencyToNodes(nodes: BrainNode[], viewTime: Date): BrainNode[]` — creates a copy of nodes with a computed `recencyScore` (0-1) that BrainVisualization can use to adjust opacity/vibrancy. Recent nodes get higher scores.

Returns: `{ selectedTime, timeRange, futureTime, isLive, historicalData, loading, setSelectedTime, goLive, computeRecency, applyRecencyToNodes, effectiveData }` where `effectiveData` = historicalData if non-null, else currentData

**BrainTimeline.tsx:**

Visual timeline scrubber at the bottom of the brain layout.

Props:
- `timeRange: { start: Date; end: Date }`
- `futureTime: Date`
- `selectedTime: Date | null`
- `isLive: boolean`
- `loading: boolean`
- `onTimeChange: (time: Date | null) => void`
- `onGoLive: () => void`
- `nodeTimestamps?: Date[]` — optional array of node createdAt dates for the activity density visualization

Implementation:

1. **Track container:** Full-width horizontal bar (height ~48px). Background: rgba(255,255,255,0.02). Contains three visual zones:
   - **Past zone:** From timeRange.start to now. Background: subtle gradient from darker to slightly lighter.
   - **Now marker:** Vertical line at the "now" position. Bright accent color (#4a9eff). Small "NOW" label above.
   - **Future zone:** From now to futureTime. Background: subtle diagonal stripe pattern (indicating prediction). Slightly different tint (more blue/purple).

2. **Range input overlay:** HTML `<input type="range">` positioned over the track, styled to be invisible except for the thumb. Custom thumb via CSS: small bright circle with glow. Min value = timeRange.start.getTime(), max = futureTime.getTime(), value = selectedTime?.getTime() ?? Date.now(). Step = 3600000 (1 hour).

3. **Activity density visualization (optional):** If `nodeTimestamps` provided, render small dots or a mini bar chart along the track showing when nodes were created (activity bursts). This gives visual indication of "busy" periods.

4. **Labels:** Show formatted dates at start, now, and future end. Format: "Mon DD" for dates within a year, "YYYY" for older.

5. **Live button:** Small button at the right end: "LIVE" with a green dot. When clicked, calls `onGoLive`. Highlighted when `isLive` is true.

6. **Loading indicator:** When `loading`, show a subtle animated bar moving across the track.

7. **Time display:** Show the currently selected time formatted nicely: "Mar 11, 2026 14:30" or "LIVE" when live.
