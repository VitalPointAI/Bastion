**Migration SQL (041_brain_annotations_snapshots.sql):**

```sql
-- Brain annotations table
CREATE TABLE IF NOT EXISTS brain_annotations (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  node_id TEXT NOT NULL,
  node_type TEXT NOT NULL CHECK (node_type IN ('entity', 'objective', 'document', 'concept')),
  annotation_type TEXT NOT NULL CHECK (annotation_type IN ('flag', 'note', 'questionable')),
  content TEXT,
  created_by TEXT NOT NULL,
  problem_set_id TEXT NOT NULL,
  is_shared BOOLEAN DEFAULT false,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS idx_brain_annotations_node ON brain_annotations(node_id, node_type);
CREATE INDEX IF NOT EXISTS idx_brain_annotations_ps ON brain_annotations(problem_set_id);
CREATE INDEX IF NOT EXISTS idx_brain_annotations_user ON brain_annotations(created_by);

-- Brain AI context snapshots table
CREATE TABLE IF NOT EXISTS brain_snapshots (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  problem_set_id TEXT NOT NULL,
  title TEXT NOT NULL,
  summary TEXT NOT NULL,
  time_scale TIMESTAMPTZ,
  node_count INTEGER DEFAULT 0,
  edge_count INTEGER DEFAULT 0,
  created_by TEXT NOT NULL,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS idx_brain_snapshots_ps ON brain_snapshots(problem_set_id);
```

**brain-store.ts:**

Create `BrainStore` class (or exported functions — follow the pattern in `actor-store.ts`) with these methods:

1. **Annotations CRUD:**
   - `createAnnotation(input: CreateAnnotationInput): Promise<BrainAnnotationRow>` — INSERT into brain_annotations, return created row
   - `getAnnotations(problemSetId: string, userId: string): Promise<BrainAnnotationRow[]>` — SELECT where problem_set_id matches AND (created_by = userId OR is_shared = true), ORDER BY created_at DESC
   - `updateAnnotation(id: string, userId: string, input: UpdateAnnotationInput): Promise<BrainAnnotationRow | null>` — UPDATE only if created_by = userId (ownership check)
   - `deleteAnnotation(id: string, userId: string): Promise<boolean>` — DELETE only if created_by = userId

2. **Snapshots CRUD:**
   - `createSnapshot(input: CreateSnapshotInput): Promise<BrainSnapshotRow>` — INSERT into brain_snapshots
   - `getSnapshots(problemSetId: string): Promise<BrainSnapshotRow[]>` — SELECT by problem_set_id, ORDER BY created_at DESC
   - `getSnapshot(id: string): Promise<BrainSnapshotRow | null>` — SELECT by id
   - `deleteSnapshot(id: string): Promise<boolean>` — DELETE by id

3. **Graph snapshot (historical):**
   - `getGraphAtTime(problemSetId: string, timestamp: string): Promise<{ nodes: any[]; edges: any[] }>` — Query actors where created_at <= timestamp AND workspace_id = problemSetId from the graph actor store tables. Query relationships where created_at <= timestamp AND both source/target actors exist at that time. Return filtered nodes + edges. Use the `raft_actors` and `raft_relationships` tables (check actual table names from actor-store.ts schema).

4. **Gap detection (heuristic):**
   - `getIntelligenceGaps(problemSetId: string): Promise<GapReport>` — Query actors with fewer than 2 relationships (under-connected nodes). These represent intelligence gaps — entities we know about but don't understand their connections. Return list of gap nodes with their missing connection types based on what similarly-typed nodes typically have.

5. **Pattern alerts (basic):**
   - `getPatternAlerts(problemSetId: string): Promise<PatternAlert[]>` — Query for actors/relationships created in the last 7 days grouped by container. If any container has >50% more new nodes than its 30-day average, generate a "trend" alert. If a new relationship contradicts an existing one (same source+target, opposite type like alliance vs conflict), generate an "anomaly" alert. Return array of PatternAlert.

Use `pool.query()` from `../db.js`. Use snake_case to camelCase mapping in the store methods.

**brain.ts (API router):**

Create Express router with these endpoints. Follow the pattern from `backend/src/api/graph.ts`.

1. `GET /api/brain/annotations?problemSetId=X` — calls `getAnnotations(problemSetId, userId)` where userId comes from request (use same auth pattern as graph.ts)
2. `POST /api/brain/annotations` — body: CreateAnnotationInput, calls `createAnnotation`
3. `PUT /api/brain/annotations/:id` — body: UpdateAnnotationInput, calls `updateAnnotation`
4. `DELETE /api/brain/annotations/:id` — calls `deleteAnnotation`
5. `GET /api/brain/snapshots?problemSetId=X` — calls `getSnapshots`
6. `POST /api/brain/snapshots` — body: CreateSnapshotInput, calls `createSnapshot`
7. `GET /api/brain/snapshots/:id` — calls `getSnapshot`
8. `DELETE /api/brain/snapshots/:id` — calls `deleteSnapshot`
9. `GET /api/brain/graph-snapshot?problemSetId=X&at=ISO_TIMESTAMP` — calls `getGraphAtTime`
10. `GET /api/brain/gaps?problemSetId=X` — calls `getIntelligenceGaps`
11. `GET /api/brain/pattern-alerts?problemSetId=X` — calls `getPatternAlerts`

Register the router in the main app — find where other API routers (like graph.ts) are registered and add `app.use('/api/brain', brainRouter)`. Check `backend/src/index.ts` or `backend/src/app.ts` for the registration pattern.

For auth: check how graph.ts gets the user identity from the request. Use the same approach (likely `req.headers` or a middleware-injected property).
