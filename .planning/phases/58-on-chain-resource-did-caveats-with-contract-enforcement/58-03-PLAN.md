       ```typescript
       export async function updateResourceCaveats(
         resourceId: string,
         problemSetId: string,
         caveats: ResourceCaveats,
       ): Promise<{ success: boolean }> {
         const res = await fetch(`/api/resources/${resourceId}/caveats`, {
           method: 'PATCH',
           headers: { 'Content-Type': 'application/json' },
           body: JSON.stringify({ problemSetId, caveats }),
         });
         if (!res.ok) throw new Error(`Failed to update caveats: ${res.status}`);
         return res.json();
       }

       export async function checkEmploymentAuth(
         resourceId: string,
         params: { roeTier?: number; nationCode?: string; bounds?: string },
       ): Promise<EmploymentAuthResult> {
         const qs = new URLSearchParams();
         if (params.roeTier) qs.set('roeTier', String(params.roeTier));
         if (params.nationCode) qs.set('nationCode', params.nationCode);
         if (params.bounds) qs.set('bounds', params.bounds);
         const res = await fetch(`/api/resources/${resourceId}/employment-check?${qs}`);
         return res.json();
       }
       ```

       - If testnet has state worth preserving: the separate LookupMap approach should work without re-init -- LookupMap is lazily initialized on first write. Verify by calling get_caveats on a non-existent key (should return null, not panic).

    5. Verify deployment by calling a view method via RPC:
       ```bash
       near contract call-function as-read-only $DID_CONTRACT_ID is_paused json-args '{}' network-config testnet now
       ```

    IMPORTANT: If keychain signing fails (no credentials stored), this becomes a checkpoint -- the user will need to authenticate. Try the deploy first; if auth fails, report it clearly.

    NOTE on LookupMap initialization: The `DIDRegistry::new()` init function creates both `dids` and `caveats` LookupMaps. For an UPGRADE (without-init-call), the `new()` function is NOT called. The `caveats` LookupMap will be initialized lazily when `update_resource_caveats` is first called -- BUT the `DIDRegistry` struct deserialization expects the `caveats` field to exist in the stored state.

    CRITICAL: This is actually a problem. The existing on-chain state was serialized as `{ dids, admin, paused }` (3 fields). The new struct expects `{ dids, caveats, admin, paused }` (4 fields). Borsh deserialization is ordered -- it will try to read `caveats` where `admin` is stored and fail.

    SOLUTION: The contract MUST handle migration. Add a `#[private] pub fn migrate(&mut self)` method that is called once after upgrade, OR use the `#[init(ignore_state)]` pattern with a migration function. The safest approach for testnet: if no valuable state exists, redeploy fresh with `new()`. If state must be preserved, add a `migrate()` method to the contract (this needs to be done in Plan 01 -- flag it as a gap if not present).

    For testnet with expendable state, use the clean deploy path:

    ```bash
    near contract deploy $DID_CONTRACT_ID \
      use-file ./contracts/did-registry/target/wasm32-unknown-unknown/release/did_registry.wasm \
    ```
