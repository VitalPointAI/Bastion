**IronclawClient changes (ironclaw-client.ts):**

CRITICAL SECURITY REQUIREMENT: `SET LOCAL` MUST be executed inside a transaction. Per PostgreSQL semantics, `SET LOCAL` outside a transaction reverts at statement end in autocommit mode — but in a connection pool, a plain `SET` (without LOCAL) persists for the pooled connection's lifetime, causing cross-user write contamination. The implementation MUST use an explicit transaction wrapper.

- Add a private method `withDIDScope(didSlug: string, fn: (client: pg.PoolClient) => Promise<T>): Promise<T>` that:
  1. Acquires a dedicated connection from the Ironclaw PostgreSQL pool (`pool.connect()`)
  2. Executes `BEGIN`
  3. Executes `SET LOCAL app.current_did_slug = '${didSlug}'` (use parameterized query to prevent SQL injection: `SET LOCAL app.current_did_slug = $1`)
  4. Calls `fn(client)` — the actual work
  5. Executes `COMMIT`
  6. In a `finally` block: `client.release()` to return connection to pool
  7. On error: `ROLLBACK` before release

- Modify the `sendMessage` method signature to accept an optional `didSlug?: string` parameter. When provided, wrap the webhook call sequence inside `withDIDScope(didSlug, async (client) => { ... })` so the SET LOCAL is scoped to the transaction.

- Add a public `setCurrentDID(didSlug: string, client: pg.PoolClient): Promise<void>` method for callers that manage their own transactions — this executes only the `SET LOCAL` statement on the provided client. Document that the caller is responsible for BEGIN/COMMIT.

- Add a `registerMcpServer(mcpUrl: string)` method that sends `/mcp add bastion-core ${mcpUrl}` via the webhook at startup. This is called once when Bastion starts and Ironclaw health check passes.
- Add a `didToSlug(did: string): string` utility function: `did.replace('did:near:', '').replace(/\./g, '-')` — export it for use by other modules.

**docker-compose.yml changes:**
- Change `bastion-mcp` port from `3334:3334` to `4000:4000` and `MCP_PORT=4000` to match the blueprint's `http://bastion:4000/mcp` convention.
- Add `MCP_BASTION_URL=http://bastion-mcp:4000/mcp` to the `ironclaw` service environment section so the MCP registration URL is configurable.
- Keep the `bastion-mcp` container name as-is; only the port changes.

NOTE: The blueprint's `http://bastion:4000/mcp` refers to the MCP container accessible on the ironclaw-network. Since `bastion-mcp` is already on that network, the URL becomes `http://bastion-mcp:4000/mcp`.
