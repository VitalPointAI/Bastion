**agent-config.ts (new REST route file):**
- Export `agentConfigRouter` (Express Router).
- `GET /api/agent-config/:userId` — Looks up AgentConfig by DID (`:userId` is the NEAR account, resolved to DID via `did:near:${userId}`). Returns 200 with config JSON. If not found, creates default config via `agentConfigStore.createDefault()` and returns it. Auth: must be the requesting user's own DID (compare against `req.user.did` from existing auth middleware).
- `PUT /api/agent-config/:userId` — Updates AgentConfig via `agentConfigStore.upsert()`. Validates required fields (displayName, rank, staffSection, position, unit). After successful save, calls `ironclawService.syncUserIdentity(config.did, config)` to immediately push updated identity files. Returns 200 with updated config. Auth: same user check.
- Import auth middleware from existing auth module (check `backend/src/auth/` or `backend/src/middleware/` for the authentication middleware pattern used by other routes).

**ironclaw-service.ts modifications:**
- Add `async syncUserIdentity(did: string, config: AgentConfig): Promise<void>` method to `IronclawService` class:
  1. Convert DID to slug: `const slug = didToSlug(did);`
  2. Write USER.md: `await this.client.sendMessage('system', '/file write users/${slug}/identity/USER.md\n${renderUserMd(config)}');`
  3. Write SOUL.md: same pattern with `renderSoulMd(config)`
  4. Write HEARTBEAT.md: same pattern with `renderHeartbeatMd(config)`
  5. Write AGENTS.md: same pattern with `renderAgentsMd(config)`
  6. Update `identityLastSyncedAt` on the config: `await agentConfigStore.upsert({ ...config, identityLastSyncedAt: new Date() });`
- Modify the existing `handleMessage` flow: At the start, before sending the user's message to Ironclaw, check if `identityLastSyncedAt` is null or older than the current session start. If so, call `syncUserIdentity()`. This ensures identity files are always current per blueprint Section 3.1: "written by Bastion before each job."
- Import `didToSlug` from `ironclaw-client.ts`, renderers from `identity-renderer.ts`, and `agentConfigStore` from `agent-config-store.ts`.

Also wire the `agentConfigRouter` into the main Express app. Check `backend/src/api/` or `backend/src/index.ts` for the existing route mounting pattern and add `app.use('/api/agent-config', agentConfigRouter)`.
