  <files>backend/src/ironclaw/routine-service.ts, backend/src/ironclaw/ironclaw-service.ts</files>
  <action>
**routine-service.ts:**
- Export `interface BuiltInRoutine { id: string; name: string; description: string; defaultCron: string; editable: boolean; category: 'knowledge' | 'monitoring' | 'reporting'; }`
- Export `const BUILT_IN_ROUTINES: BuiltInRoutine[]`:
  1. `bastion_knowledge_sync` — "Sync shared knowledge to Ironclaw workspace" — cron: `0 */6 * * *` (every 6 hours) — category: knowledge — editable: true (cron only)
  2. `bastion_user_knowledge_sync` — "Sync user-specific knowledge on login" — triggered on login (no cron) — category: knowledge — editable: false
  3. `weekly_capability_update` — "Update Ironclaw on available Bastion capabilities" — cron: `0 9 * * 1` (Monday 9am) — category: monitoring — editable: true
  4. `daily_situation_brief` — "Generate morning situation brief" — cron: `0 6 * * *` (6am daily) — category: reporting — editable: true

- Export `class RoutineService`:
  - `async syncKnowledge(): Promise<void>` — Writes `shared/knowledge/BASTION_CONTEXT.md` to Ironclaw workspace via webhook. Content includes: problem set names, active operations, available tool list, current agent team list. Gathered by querying Bastion's existing stores.
  - `async syncUserKnowledge(did: string): Promise<void>` — Writes user-specific context to `users/{didSlug}/knowledge/` including: user's problem set memberships, recent activity, assigned tasks.
  - `async registerRoutine(routineId: string, cron: string): Promise<void>` — Sends routine registration to Ironclaw via webhook command.
  - `async unregisterRoutine(routineId: string): Promise<void>` — Removes routine from Ironclaw.
  - `async registerUserRoutines(did: string, routines: RoutineSpec[]): Promise<void>` — Registers all custom routines for a user.

- Export singleton `routineService`.

**ironclaw-service.ts modifications:**
- In the `handleMessage` flow, after `syncUserIdentity` check, also call `routineService.syncUserKnowledge(did)` on first message of session (piggyback on the identity freshness check).
- Add a method `async initializeRoutines(): Promise<void>` that registers all built-in routines with Ironclaw. This is called once at startup after MCP registration.
- Wire `initializeRoutines` into the startup sequence (wherever MCP registration happens — from 60-01's `registerMcpServer` call).
