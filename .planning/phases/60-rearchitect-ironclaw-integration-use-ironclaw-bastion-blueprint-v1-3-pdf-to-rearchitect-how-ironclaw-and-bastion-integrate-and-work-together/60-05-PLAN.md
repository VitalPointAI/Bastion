**skill-packs.ts:**
- Export `interface SkillPack { id: string; name: string; description: string; staffSections: StaffSection[]; triggers: string[]; requiredTools: string[]; trustLevel: 'high' | 'medium' | 'low'; }`
- Export `const SKILL_PACKS: SkillPack[]` with 7 role-specific packs:
  1. `intel-analysis` — S2: intelligence preparation, threat assessment, collection management. Triggers: "analyze threat", "IPB", "collection plan". Required tools: bastion.knowledge.search, bastion.ops.get_problem_set.
  2. `ops-planning` — S3: MDMP workflow, OPORD drafting, synchronization matrix. Triggers: "draft OPORD", "synchronize", "COA analysis". Required tools: bastion.ops.get_campaign_plan, bastion.ops.get_coa.
  3. `logistics-support` — S4: supply management, LOGSTAT formatting, maintenance tracking. Triggers: "supply status", "LOGSTAT", "maintenance report". Required tools: bastion.resources.list, bastion.resources.get_status.
  4. `personnel-admin` — S1: personnel readiness, morale reports, casualty tracking. Triggers: "personnel status", "strength report". Required tools: bastion.personnel.list_staff.
  5. `comms-cyber` — S6: C4ISR architecture, network status, spectrum management. Triggers: "network status", "comms plan", "spectrum". Required tools: bastion.resources.search_capabilities.
  6. `civil-affairs` — S9: PMESII analysis, civil-military coordination. Triggers: "civil assessment", "PMESII". Required tools: bastion.knowledge.search.
  7. `command-decision` — Commander/XO: COA comparison, decision brief, risk assessment. Triggers: "decision brief", "compare COAs", "risk matrix". Required tools: bastion.ops.get_coa, bastion.knowledge.get_relationships.
- Export `function renderSkillPackMd(pack: SkillPack): string` — generates SKILL.md with YAML frontmatter (name, triggers, required_tools, trust) and markdown body per Ironclaw's expected format.

**skill-packs.ts API route (backend/src/api/routes/skill-packs.ts):**
- Export `skillPacksRouter` (Express Router).
- `GET /api/skill-packs` — Returns the `SKILL_PACKS` array as JSON. Import `SKILL_PACKS` from `backend/src/ironclaw/skill-packs.ts`. No auth required (skill catalog is not sensitive).
- Mount in main app router alongside other API routes.

**SkillsTab.tsx:**
- On mount, fetch `GET /api/skill-packs` to load the skill catalog dynamically. Do NOT hardcode the skill pack list in the frontend.
- Display all 7 skill packs as toggleable cards
- Each card shows: name, description, applicable staff sections, trigger examples
- Cards relevant to the user's staffSection are highlighted/recommended
- Toggle adds/removes pack ID from `config.enabledSkillPacks` array
- Custom skills section at bottom: list of `config.customSkills` with add/edit/remove. Each custom skill has name, description, triggers (comma-separated).
- Register SkillsTab in AgentConfigPanel's tab list.

**ChannelsTab.tsx:**
- Sections: "Bastion In-App" (always enabled, shows notification preference), "Telegram" (enable/disable toggle, pairing status, notification level dropdown)
- Telegram section shows:
  - If `config.telegramEnabled && config.telegramChatId`: "Paired" status with chat ID and "Unpair" button
  - If `config.telegramEnabled && !config.telegramChatId`: "Not paired" with "Pair Now" button that opens TelegramPairWizard
  - If `!config.telegramEnabled`: Toggle to enable, then pair
- Notification level dropdown (Critical/Urgent/Routine/Informational) per channel
- Display the blueprint's notification priority routing table as a reference card:
  - CRITICAL: Telegram DM + Bastion in-app
  - URGENT: Telegram during duty hours; Bastion-only outside
  - ROUTINE: Bastion in-app only; daily digest
  - INFORMATIONAL: Workspace memory write only
- Register ChannelsTab in AgentConfigPanel's tab list.

**TelegramPairWizard.tsx:**
- 3-step wizard:
  1. "Initiate" — Explain the process, show "Start Pairing" button. On click, call backend to send `/telegram pair` to Ironclaw via webhook for this user's DID.
  2. "Enter Code" — Show 6-digit code input field. Instruct user to check their Telegram for a message from the bot. On submit, call backend to send `/telegram confirm ${code}` via webhook.
  3. "Complete" — Show success/failure. On success, update `config.telegramChatId` and show confirmation.
- Each step has back/cancel navigation
- Error handling for: timeout (code not entered within 5 minutes), invalid code, network errors
- The backend calls go through existing Ironclaw webhook (add a thin endpoint `/api/agent-config/:userId/telegram-pair` and `/api/agent-config/:userId/telegram-confirm` that call `ironclawClient.sendMessage(did, '/telegram pair')` and `ironclawClient.sendMessage(did, '/telegram confirm ${code}')` respectively). Add these two endpoints to `backend/src/api/routes/agent-config.ts`.
