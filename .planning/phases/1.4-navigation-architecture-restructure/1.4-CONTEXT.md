# Phase 1.4: Navigation Architecture Restructure - Context

**Gathered:** 2026-02-22
**Status:** Ready for planning

<domain>
## Phase Boundary

Restructure frontend navigation from 6-tab layout (Home, Governance, Strategic, Validity, Missions, Admin) to doctrine-aligned 4+1 activity-based structure: Decide, Design, Campaign, Monitor + Admin. This is a reorganization of existing components into new navigation containers — no new features are added.

</domain>

<decisions>
## Implementation Decisions

### Navigation Layout & Style
- Top horizontal tabs, similar to current layout pattern
- Text-only labels (no icons): Decide, Design, Campaign, Monitor, Admin
- Tab names are final — use exactly as stated
- Admin tab sits in the same row but right-aligned, visually separated from the 4 main activity tabs

### Landing Experience
- Default landing tab is **Monitor**, with **ValidityMap** as the primary landing component
- Always start on Monitor/ValidityMap — do not persist last-visited tab across sessions
- No overview/dashboard page — go straight to the primary component within Monitor

### Sub-Navigation Within Tabs
- Collapsible left sidebar drawer within each tab for navigating sub-components
- Sidebar **open by default** when entering a tab, collapsible to maximize content space
- **Consistent pattern across all tabs** — every tab uses the same sidebar drawer, even tabs with fewer sub-components
- Sidebar items use **doctrinal labels** (e.g., "IPB", "COA Development", "WARNORD") with tooltips for terms that are not well-known or not standard doctrine

### URL Structure & Routing
- Activity-based paths matching tab names: `/decide`, `/design`, `/campaign`, `/monitor`, `/admin`
- History-based routing (clean URLs like `/monitor`, not hash-based)
- Old routes (`/governance`, `/strategic`, `/validity`, etc.) redirect to their new equivalents
- Sub-route structure (e.g., `/monitor/validity-map`) — Claude's discretion on whether sub-sections get their own URL segments based on bookmarkability needs

### Claude's Discretion
- Sub-route URL segments — whether sub-sections within tabs are reflected in the URL or handled as client-side state
- Sidebar item ordering within each tab
- Transition animations between tabs/sub-sections
- Collapsed sidebar width and toggle button placement

</decisions>

<specifics>
## Specific Ideas

- Navigation should reflect what users DO (activities) rather than doctrinal levels of war — a brigade S2 and COCOM J5 both use the same tool
- Sidebar labels should use the language military professionals expect (doctrinal terms), with tooltips only where a term might be unfamiliar or non-standard

</specifics>
