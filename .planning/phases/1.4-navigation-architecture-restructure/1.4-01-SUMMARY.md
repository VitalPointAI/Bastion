# Phase 1.4 Plan 01: Tab Container Components and Shared Sidebar Shell Summary

**One-liner:** Six new files in `frontend/src/components/tabs/` — shared TabLayout sidebar shell + 4 doctrine-aligned activity tab containers wrapping existing components.

## What Was Built

### TabLayout Shared Shell (`TabLayout.tsx` + `TabLayout.css`)

A reusable layout wrapper that renders a collapsible left sidebar (`<aside>`) and content area (`<main>`) in a flex row. Key properties:
- Sidebar open by default (`useState(true)`) per user decision
- Toggle button with chevron `‹`/`›` and accessible `aria-label`
- Active sidebar item: left blue border + blue text via CSS custom properties
- Sidebar open width: 220px; collapsed: 40px; smooth CSS `transition` on width
- Responsive: sidebar collapsed by default on mobile (768px breakpoint)
- `tab-placeholder` CSS class for mission-context placeholder views

### MonitorTab (Default Landing)

Sidebar items: IPB Map (default) | Actor Graph | Actor Detail

- Defaults to `StrategicValidityDashboard` (which contains ValidityMap as its own default view)
- Fetches graph data from `/api/graph?workspaceId=default` in `useEffect`; shows "Loading graph data..." while null
- Actor graph click navigates to actor-detail view via `selectedActorId` state
- `NodeDetailPanel` renders with `onClose` returning to actor-graph

### DecideTab

Sidebar items: Governance Overview (default) | Proposals | Voting | MDMP Workflow | Commander's Guidance | Assumptions

- All sidebar items render `DAODashboard` for v1 — DAODashboard already contains proposals, voting, MDMP governance panel toggle, commander guidance, and assumptions internally
- Sidebar items preview future decomposition without requiring any refactoring of DAODashboard

### DesignTab

Sidebar items: Strategic Documents (default) | COA Development | Escalation Modeling | Force Ratio | Branch / Sequel | Sustainment

- Strategic Documents renders `StrategicDashboard` (document ingestion, objectives, MIDLIFE)
- COA Development, Escalation, Force Ratio, Branch/Sequel, Sustainment all render informative placeholder messages directing users to Campaign > Missions for mission context
- No imports of EscalationLadder, ForceRatioDisplay, BranchSequelTimeline, SustainmentDisplay — these require complex mission-scoped required props

### CampaignTab

Sidebar items: Missions (default) | OPORD / WARNORD | Command Structure | Force Allocation

- Missions view handles complete mission flow: `MissionList` → `MissionDetail` → `MissionWizard` via local state (`selectedMissionId`, `showWizard`)
- `MissionWizard` only renders when `userDID` is available (from `useUser()`)
- Orders, Command Structure, Force Allocation show placeholder messages (these sub-views live inside MissionDetail in current architecture)
