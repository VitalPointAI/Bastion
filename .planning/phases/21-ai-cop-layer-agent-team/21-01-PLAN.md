<task type="auto" tdd="true">
  <name>Task 2: CCO schema loader and validator</name>
  <files>backend/src/cop/cco/cco-schema-loader.ts, backend/src/cop/cco/cco-validator.ts, backend/src/cop/cco/cco-schema-loader.test.ts</files>
  <behavior>
    - loadCCOSchema() builds a Map of CCO class URIs to CCOClassMapping objects
    - getCCOClassMap() returns the loaded map (empty if not loaded)
    - validateCCOClass('cco:Person') returns { valid: true }
    - validateCCOClass('cco:NonexistentClass') returns { valid: false, reason: 'Unknown CCO class: cco:NonexistentClass' }
    - suggestCCOClass('nation', {}) returns 'cco:GovernmentOrganization'
    - suggestCCOClass('individual', {}) returns 'cco:Person'
    - suggestCCOClass('organization', {}) returns 'cco:Organization'
    - suggestCCOClass('unknown_type', {}) returns 'cco:Entity' (fallback)
  </behavior>
  <action>
Create `backend/src/cop/cco/cco-schema-loader.ts`:
- Since parsing real OWL/Turtle files in Node.js requires the `n3` library (and adds complexity), implement a pragmatic approach: bundle a hand-curated JSON file of the ~50-100 relevant CCO classes from the 4 required modules (Core+Geospatial, Agent, Event, Artifact+Information Entity). This avoids an n3 dependency while maintaining CCO compliance.
- Create `backend/src/cop/cco/cco-classes.json` with the curated class entries: uri, label, module, parentClass.
- `loadCCOSchema()` reads the JSON file and populates a module-level `Map<string, CCOClassMapping>`.
- `getCCOClassMap()` returns the current map.
- Include classes relevant to military COP: cco:Agent, cco:Person, cco:Organization, cco:GovernmentOrganization, cco:MilitaryOrganization, cco:GeospatialRegion, cco:GeospatialLocation, cco:ActOfConflict, cco:ActOfPerforming, cco:InformationContentEntity, cco:Artifact, cco:Vehicle, cco:Weapon, cco:ActOfCommunication, cco:ActOfDirectiveAction, etc.

Create `backend/src/cop/cco/cco-validator.ts`:
- `validateCCOClass(proposedClass: string)` -- looks up in map, returns CCOValidationResult.
- `suggestCCOClass(entityType: string, entityAttributes: Record<string, unknown>)` -- maps RAFT entity types to CCO classes using the RAFTToCCOMap defined in cco-types.ts. Mapping: nation->cco:GovernmentOrganization, organization->cco:Organization, individual->cco:Person, non_state_actor->cco:Organization, military_unit->cco:MilitaryOrganization, location->cco:GeospatialRegion, document->cco:InformationContentEntity, equipment->cco:Artifact, vehicle->cco:Vehicle, weapon->cco:Weapon. Default fallback: 'cco:Entity'.

Test file: `backend/src/cop/cco/cco-schema-loader.test.ts` -- test loadCCOSchema, validateCCOClass, suggestCCOClass with the behaviors above.

  <files>backend/src/cop/svg/svg-allowlist.ts, backend/src/cop/svg/svg-sanitizer.ts, backend/src/cop/svg/svg-sanitizer.test.ts</files>
  <behavior>
    - sanitizeSVG strips script tags from SVG input
    - sanitizeSVG strips onclick/onload/onerror attributes
    - sanitizeSVG strips javascript: URIs
    - sanitizeSVG strips external xlink:href references
    - sanitizeSVG preserves valid SVG elements (path, rect, circle, text, g)
    - sanitizeSVG preserves data-entity-id and data-layer-id attributes

    - validateSVGSafety returns { safe: true } for clean SVG and { safe: false, violations } for dangerous SVG

Create `backend/src/cop/svg/svg-sanitizer.ts`:
- `sanitizeSVG(svgString: string): string` -- uses DOMPurify with USE_PROFILES: {svg: true, svgFilters: false}, ALLOWED_TAGS, ALLOWED_ATTR, FORBID_TAGS, FORBID_ATTR, ALLOW_DATA_ATTR: true. Check for: script tags, on* attributes, javascript: URIs, external URLs in href/xlink:href, foreignObject, data: URIs on non-image elements. Returns list of violations found.
