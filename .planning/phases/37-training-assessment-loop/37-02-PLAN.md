**aggregation-service.ts:**
Create an aggregation service that runs when an AAR is finalized. Export as singleton `aggregationService`.

- propagateRatings(aarId: string): Promise<void>
  1. Get the AAR by id, get its problemSetId (tactical training event)
  2. Get all METL assessments linked to this AAR via metlStore.getAssessmentsByAAR(aarId)
  3. For each assessment, the rating is already stored at the tactical level. Now propagate upward:
     - Get the problem set's parentProblemSetId (exercise level)
     - If parent exists and parent has parentProblemSetId (strategy level), propagate there too
     - "Propagation" means: for each assessed METL task, the latest rating at the tactical level IS the authoritative rating. The strategic dashboard queries across the hierarchy, so no duplicate records needed -- the aggregation query in metlStore.getLatestProficiency already handles this via sourceProblemSetId.
  4. Reset decay timers via decayService.resetTimers for all assessed task IDs

- checkReframingTrigger(problemSetId: string): Promise<boolean>
  1. Get MOEs and MOPs for the problem set
  2. Count declining MOEs and red MOPs
  3. Thresholds: 2+ declining MOEs OR 3+ red MOPs triggers suggestion
  4. If triggered, log the suggestion (actual gate creation will be wired in Plan 06)
  5. Return boolean

**decay-service.ts:**
Create a decay service for computing and resetting proficiency decay. Export as singleton `decayService`.

- computeDecayStatus(assessedAt: Date | null, decayDays: number): DecayStatus
  - If assessedAt is null, return 'expired' (never assessed)
  - If elapsed days > decayDays, return 'expired'
  - If elapsed days > decayDays * 0.75, return 'warning'
  - Otherwise return 'current'

- resetTimers(metlTaskIds: string[]): Promise<void>
  - This is a conceptual "reset" -- since decay is computed on read from assessed_at, there's nothing to actually reset in a separate table. The most recent assessment's assessed_at IS the timer. This method exists as a hook for future notification clearing.
  - For now, log that timers were reset for the given task IDs.

- getDecayReport(sourceProblemSetId: string): Promise<Array<{ metlTaskId: string; taskName: string; rating: string; decayStatus: DecayStatus; daysRemaining: number }>>
  - Uses metlStore.getLatestProficiency to get current state
  - Enriches with daysRemaining calculation

**assessment-routes.ts:**
Create Express router with all assessment endpoints. Follow the existing pattern from design.ts (Router, async handlers, try/catch, res.json).

AAR endpoints:
- POST /aars -- create new AAR (body: { problemSetId, trainingEventName, initiatedBy })
- GET /aars/problem-set/:problemSetId -- list AARs for a problem set
- GET /aars/:id -- get single AAR with observations
- PATCH /aars/:id -- update AAR text sections (only if not finalized)
- POST /aars/:id/finalize -- finalize AAR (body: { finalizedBy }), calls aggregationService.propagateRatings after finalization
- POST /aars/:id/observations -- add observation (body: { observationType, content, metlTaskId?, suggestedByAi?, createdBy })
- PATCH /aars/observations/:id -- update observation (body: { aiAccepted?, content? })

METL endpoints:
- POST /metl/tasks -- create METL task
- GET /metl/tasks/problem-set/:problemSetId -- list tasks for problem set
- GET /metl/tasks/inherited/:problemSetId/:sourceProblemSetId -- get inherited tasks
- POST /metl/tasks/:id/promote -- promote supplemental task to strategic
- POST /metl/assessments -- create assessment
- GET /metl/assessments/aar/:aarId -- get assessments by AAR
- GET /metl/proficiency/:sourceProblemSetId -- get latest proficiency summary (for dashboard)
- GET /metl/history/:metlTaskId -- get assessment history for a task

MOE endpoints:
- POST /moes -- create MOE
- GET /moes/problem-set/:problemSetId -- list MOEs
- PATCH /moes/:id/status -- update MOE status/trend
- POST /moes/:id/observations -- add observation
- GET /moes/:id/observations -- list observations
- POST /moes/observations/:id/approve -- approve observation (body: { approvedBy })

MOP endpoints (same pattern as MOE):
- POST /mops -- create MOP
- GET /mops/problem-set/:problemSetId -- list MOPs
- PATCH /mops/:id/status -- update MOP status/trend
- POST /mops/:id/observations -- add observation
- GET /mops/:id/observations -- list observations
- POST /mops/observations/:id/approve -- approve observation

Reframing trigger:
- GET /reframing-check/:problemSetId -- returns { shouldTrigger, decliningMOEs, redMOPs }

All handlers: try/catch with res.status(500).json({ error: message }). Use Zod for body validation on POST/PATCH endpoints.
