**1. Create `backend/src/agents/cog-analysis.ts`** following the problem-framing.ts agent pattern:

- Export `CoGSuggestion` interface with fields:
  - `type`: 'cog' | 'critical-capability' | 'critical-requirement' | 'critical-vulnerability'
  - `label`: string (suggested node label)
  - `description`: string (why this element matters)
  - `parentType`: CoGNode['type'] | null (where it should attach in the tree)
  - `side`: 'friendly' | 'adversary' (which tree)
  - `rationale`: string (doctrinal reasoning)
  - `confidence`: number (0-1)
  - `confidenceBounds`: { lower: number; upper: number }

- Export `CoGAnalysisOutput` interface:
  - `suggestions`: CoGSuggestion[] (suggested nodes to add)
  - `validationIssues`: Array<{ nodeId: string; issue: string; severity: 'warning' | 'error' }> (problems with existing tree)
  - `completenessScore`: number (0-1, how complete the analysis is)
  - `confidenceBounds`: { lower: number; upper: number }

- Export `COG_ANALYSIS_AGENT` manifest constant (AgentPhase.Support, AutonomyLevel.NotAutonomous, HYBRID_HUMAN_LED pattern)

- Export async function `analyzeCenterOfGravity(cogAnalysis: CoGAnalysis): Promise<CoGAnalysisOutput>` — v1 rule-based stub that:
  - Checks if friendly/adversary trees have root nodes; if not, suggests default CG nodes
  - For each tree with a CG root, checks for CC/CR/CV children and suggests missing levels
  - Validates that CG nodes have at least one CC, CCs have at least one CR, CRs have at least one CV
  - Returns validation issues for empty descriptions, orphaned nodes, etc.
  - Returns completeness score based on tree depth coverage (4 levels = 1.0)
  - Uses conservative confidence bounds (0.3-0.7 range for rule-based)

**2. Create `backend/src/agents/loe-gap-analysis.ts`** following the same pattern:

- Export `LOEGapSuggestion` interface with fields:
  - `type`: 'unaddressed-vulnerability' | 'missing-linkage' | 'phase-gap' | 'loe-suggestion'
  - `description`: string (what the gap is)
  - `affectedLoeId`: string | null (which LOE, if applicable)
  - `affectedCogNodeId`: string | null (which CoG node, if applicable)
  - `recommendation`: string (how to fix it)
  - `priority`: 'high' | 'medium' | 'low'
  - `confidence`: number (0-1)
  - `confidenceBounds`: { lower: number; upper: number }

- Export `LOEGapAnalysisOutput` interface:
  - `suggestions`: LOEGapSuggestion[]
  - `coverageScore`: number (0-1, what percentage of CVs are addressed by LOEs)
  - `confidenceBounds`: { lower: number; upper: number }

- Export `LOE_GAP_ANALYSIS_AGENT` manifest constant

- Export async function `analyzeLOEGaps(loes: LineOfEffort[], cogAnalysis: CoGAnalysis): Promise<LOEGapAnalysisOutput>` — v1 rule-based stub that:
  - Collects all CVs from both friendly and adversary CoG trees
  - Checks which CVs have LOE decisive point links (via cogLinks)
  - Reports unaddressed CVs as 'unaddressed-vulnerability' suggestions
  - Checks for LOEs with no decisive points (suggests adding them)
  - Checks for phases with no decisive points across any LOE (phase gaps)
  - Calculates coverage score as (linked CVs / total CVs)
  - Uses conservative confidence bounds
