# Phase 46 Plan 02: Swarm Coordinator — Leader Election, Peer Mesh, Movement Techniques

## Goal
Build the swarm coordinator that manages the peer-to-peer mesh, leader/follower roles, formation management, doctrinal movement techniques, and DAO-driven dynamic membership.

## Tasks

### Task 1: SwarmCoordinator Core
**File:** `robot/swarm/coordinator.py`

Implement the coordinator that runs on every robot in the swarm:

1. **Lifecycle:** `start()` / `stop()` — open/close UDP broadcast socket, start heartbeat/receive/cleanup loops
2. **UDP mesh:** Broadcast JSON messages via UDP port 5807; simulate mode uses loopback
3. **Member tracking:** `_members` dict keyed by robot_id, stale cleanup after 5s timeout
4. **Position updates:** `update_position(x, y, heading)` called from telemetry/driver

### Task 2: Leader API
Methods only executable when `role == SwarmRole.leader`:

1. `set_formation(formation, spacing_m, heading)` — recompute slots, broadcast `FormationCommand`
2. `move_swarm(target, speed, technique)` — broadcast `MoveCommand`, dispatch to technique handler
3. `halt_swarm()` — broadcast `HaltCommand`
4. `dismiss_swarm()` — broadcast `DismissCommand`
5. `share_vision(detections, scene_description)` — broadcast `SwarmVisionShare`
6. `add_resource(msg)` — DAO-driven add, recompute slots, broadcast updated formation
7. `remove_resource(msg)` — DAO-driven remove, recompute slots, broadcast updated formation

### Task 3: Movement Techniques
Four doctrinal movement technique implementations:

1. `_move_traveling()` — all elements move simultaneously
2. `_move_traveling_overwatch()` — lead moves to midpoint, then continues; trail follows
3. `_move_bounding_overwatch()` — alternating bounds with overwatch pauses
4. `_move_successive_bounds()` — each element bounds to predecessor's position

### Task 4: Follower Message Handling
1. `_handle_join_ack()` — accept role assignment and slot index from leader
2. `_handle_formation_command()` — update local formation state, find assigned slot
3. `_handle_move_command()` — compute formation-relative world position, drive to it
4. `request_join()` — send join request to discover leader

### Task 5: Peer Message Dispatch
`_handle_message()` router for all swarm message types:
- `swarm:heartbeat` → update member state
- `swarm:join` → leader accepts, assigns slot
- `swarm:join_ack` → follower stores assignment
- `swarm:formation` → follower updates formation
- `swarm:move` → follower drives to slot position
- `swarm:halt` → follower stops
- `swarm:dismiss` → all reset to unassigned
- `swarm:vision` → log shared detections
- `swarm:add_resource` / `swarm:remove_resource` → leader processes DAO directives

### Task 6: Telemetry Aggregation
`_emit_swarm_telemetry()` — compute center of mass, build `SwarmTelemetry` with all member heartbeats, send to Bastion via callback.

## Verification
- Coordinator starts/stops without error
- Leader can set formation and compute slots
- Follower receives commands and computes slot positions
- All movement techniques execute without error
