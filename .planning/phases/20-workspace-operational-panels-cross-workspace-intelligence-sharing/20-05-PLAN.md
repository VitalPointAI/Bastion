  <files>backend/src/api/workspaces.ts</files>
  <action>
Add new endpoints to the existing workspace router. Place them after existing routes, before the module export.

**Import new stores** at top:
```typescript
import { workspacePanelConfigStore } from '../workspace/workspace-panel-config-store.js';
import { workspaceSubscriptionStore } from '../workspace/workspace-subscription-store.js';
import { workspaceEscalationStore } from '../workspace/workspace-escalation-store.js';
```

**Panel Config endpoints:**

1. `GET /:id/panel-config` — Get panel visibility for workspace
   - requireAuth
   - Verify caller is member of workspace (any role)
   - Call `workspacePanelConfigStore.getOrCreateDefault(id, workspace.workspaceType)`
   - Return `{ panelVisibility, defaultTab }`

2. `PUT /:id/panel-config` — Update panel visibility
   - requireAuth
   - Verify caller is commander or xo (council role)
   - Zod validate body: `{ panelVisibility: z.record(z.array(z.string())), defaultTab?: z.string() }`
   - Call `workspacePanelConfigStore.upsertConfig(id, body.panelVisibility, body.defaultTab)`
   - Log activity: 'panel_config_updated'
   - Return updated config

**Subscription endpoints:**

3. `POST /:id/subscriptions` — Request subscription to another workspace's data
   - requireAuth
   - Verify caller is commander/xo of workspace `:id` (subscriber)
   - Zod validate body: `{ publisherWorkspaceId: z.string(), dataTypes: z.array(z.string()) }`
   - Check classification: subscriber must have sufficient clearance for publisher workspace. Use `clearanceSufficient()`.
   - Call `workspaceSubscriptionStore.createSubscription({ subscriberWorkspaceId: id, publisherWorkspaceId: body.publisherWorkspaceId, dataTypes: body.dataTypes, requestedBy: callerDID })`
   - Log activity in BOTH workspaces: 'subscription_requested'
   - Return subscription object

4. `GET /:id/subscriptions` — List subscriptions (both as subscriber and publisher)
   - requireAuth
   - Verify caller is member of workspace
   - Return `{ asSubscriber: [...], asPublisher: [...] }`

5. `PATCH /:id/subscriptions/:subId` — Approve or reject subscription
   - requireAuth
   - Verify caller is commander/xo of the PUBLISHER workspace (not the subscriber)
   - Zod validate body: `{ status: z.enum(['approved', 'rejected']) }`
   - Call `workspaceSubscriptionStore.updateApprovalStatus(subId, body.status, callerDID)`
   - Log activity: 'subscription_approved' or 'subscription_rejected'
   - Return updated subscription

6. `DELETE /:id/subscriptions/:subId` — Cancel subscription
   - requireAuth
   - Verify caller is commander/xo of subscriber workspace
   - Call `workspaceSubscriptionStore.deleteSubscription(subId)`
   - Return 204

**Escalation Rule endpoints:**

7. `GET /:id/escalation-rules` — List escalation rules for workspace
   - requireAuth
   - Verify caller is commander/xo
   - Call `workspaceEscalationStore.listRulesForWorkspace(id)`
   - Return rules array

8. `POST /:id/escalation-rules` — Create escalation rule
   - requireAuth
   - Verify caller is commander/xo
   - Zod validate body:
     ```typescript
     const EscalationRuleSchema = z.object({
       ruleType: z.string(),
       proposalKind: z.string(),
       thresholdConfig: z.record(z.unknown()).optional(),

       autoRouteTo: z.string().optional(),
     });
     ```
   - Call `workspaceEscalationStore.createRule({ workspaceId: id, ...body })`
   - Return created rule

9. `DELETE /:id/escalation-rules/:ruleId` — Delete escalation rule
   - requireAuth, verify commander/xo
   - Call `workspaceEscalationStore.deleteRule(ruleId)`
   - Return 204

**Escalation Trigger endpoint:**

10. `POST /:id/escalate` — Escalate a decision to parent workspace
   - requireAuth
   - Verify caller is commander/xo of workspace `:id`
   - Zod validate body:
     ```typescript
     const EscalateSchema = z.object({
       proposalKind: z.string(),
       description: z.string().min(1).max(2000),
       urgency: z.enum(['urgent', 'standard']).default('standard'),
       data: z.record(z.unknown()).optional(),
     });
     ```
   - Get workspace, verify it has parentWorkspaceId. If not, return 400 "No parent workspace to escalate to"
   - Get parent workspace
   - Look up escalation rules: `workspaceEscalationStore.getRulesForKind(id, body.proposalKind)`
   - Determine voting mechanism: if urgency === 'urgent' → 'autocratic', else use rule's voting_mechanism or default 'democratic'

     - Log activity in source workspace: 'decision_escalated' with metadata { proposalKind, description, urgency, votingMechanism, parentWorkspaceId }
     - Log activity in parent workspace: 'escalation_received' with metadata { sourceWorkspaceId, proposalKind, description, urgency, votingMechanism }
   - Return `{ escalationId: activityId, parentWorkspaceId, votingMechanism, status: 'escalated' }`
   - Future: on-chain proposal creation will be wired when commander credential delegation is implemented
