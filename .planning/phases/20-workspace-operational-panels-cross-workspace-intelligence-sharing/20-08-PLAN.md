**EscalationPanel.tsx:**

Commander-facing panel for escalating decisions to parent workspace.

1. Props: `{ workspaceId: string }`
2. Import `useWorkspace`, `useUser`, `workspaceService`
3. State: `proposalKind`, `description`, `urgency: 'urgent' | 'standard'`, `submitting`, `result`, `error`, `rules` (loaded escalation rules)
4. Guard: If `!activeWorkspace?.parentWorkspaceId`, show "This is a top-level workspace. Decisions cannot be escalated further." with a muted message.
5. Guard: If user role is not commander/xo, show "Only commanders can escalate decisions."
6. On mount: fetch escalation rules via `workspaceService.getEscalationRules(workspaceId, userDID)`
7. Form:
   - Proposal kind: dropdown with options from ProposalKind (or text input if rules are empty). Common kinds: 'ResourceAllocation', 'PolicyChange', 'ROEModification', 'OperationalOrder', 'General'.
   - Description: textarea, min 10 chars
   - Urgency: radio buttons — "Urgent (Commander decision, 1-hour window)" vs "Standard (Council vote, 7-day window)"
   - Active escalation rules display (if any): show matching rule's voting mechanism
   - Submit button: "Escalate to [parent workspace name]"
8. On submit: call `workspaceService.escalateDecision(workspaceId, { proposalKind, description, urgency }, userDID)`
9. Success state: show result with escalation ID, voting mechanism used, parent workspace name
10. Error handling: display error message inline
11. Style: dark theme, form in card layout (bg-gray-800 border-gray-700 rounded-lg p-6)

**SubscriptionManager.tsx:**

Panel for managing cross-workspace data subscriptions.

1. Props: `{ workspaceId: string }`
2. Import `useWorkspace`, `useUser`, `workspaceService`
3. State: `subscriptions` (loaded), `loading`, `showCreateForm`, `selectedPublisherId`, `selectedDataTypes`
4. On mount: fetch `workspaceService.getSubscriptions(workspaceId, userDID)`
5. Two sections:

   **Outgoing (as subscriber):**
   - List of subscriptions this workspace has requested/approved
   - Each row: publisher workspace name, data types, status badge (pending/approved/rejected)
   - Pending: show "Awaiting approval" badge
   - Approved: show green "Active" badge + "Unsubscribe" button
   - "Request New Subscription" button → shows create form

   **Incoming (as publisher):**
   - List of subscriptions other workspaces have requested to this workspace's data
   - Each row: subscriber workspace name, data types, status
   - Pending: show "Approve" (green) and "Reject" (red) buttons
   - Approved: show "Revoke" button

6. Create form (shown when showCreateForm is true):
   - Workspace picker: dropdown of all user's memberships (from context.memberships), excluding current workspace
   - Data types: checkboxes for ['decide', 'design', 'campaign', 'monitor', 'train']
   - Submit: calls `workspaceService.createSubscription(workspaceId, selectedPublisherId, selectedDataTypes, userDID)`
   - Cancel button

7. Action handlers: approve, reject, delete all call workspace-service methods and refresh list
8. Commander/xo only for creating subscriptions and approving incoming ones
9. Style: two-column or stacked sections, dark theme
