    **Source pre-registration:**

    Before invoking the pipeline, the bridge should ensure the feed's sourceName is registered in the source_registry table so TrustAgent can look it up. Two approaches — choose based on what the codebase already provides:

    1. Check if there is a source_registry store/module (grep for `source_registry` in backend/src/). If a `registerSource` or `upsertSource` function exists, use it.
    2. If no store exists, add a simple `ensureSourceRegistered(sourceName, sourceType)` function in the bridge that does a PostgreSQL UPSERT:
       ```sql
       INSERT INTO source_registry (name, type, default_reliability, created_at)
       VALUES ($1, $2, 'C', NOW())
       ON CONFLICT (name) DO NOTHING;
       ```
       This ensures known feed sources get at least 'C' (Fairly Reliable) instead of F6 (Cannot Be Judged).

    Also add a constant map of well-known sources with higher default ratings:
    ```typescript
    const KNOWN_NEWS_AGENCIES: Record<string, string> = {

      'Associated Press': 'B',
      'AP': 'B',
      'BBC': 'B',
      'Al Jazeera': 'C',
      'CNN': 'C',
      'The Guardian': 'C',
      'The New York Times': 'B',
      'NPR': 'B',
    ```

    ```typescript

    ```

    Find where `LLM_CONCURRENCY` is defined (likely in feed-poller.ts or a shared config). Check if the bridge can use a separate concurrency value.
