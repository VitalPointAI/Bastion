# Phase 1.3: NEAR Implicit Account Funding - Context

**Gathered:** 2026-02-04
**Status:** Ready for planning

<domain>
## Phase Boundary

Activate newly created NEAR implicit accounts by transferring minimum NEAR during user registration. The funding mechanism uses a dedicated funding contract on testnet with admin monitoring capabilities.

</domain>

<decisions>
## Implementation Decisions

### Funding Behavior
- Transfer 0.1 NEAR per account (minimum for creation + ~10 transactions buffer)
- Fund immediately after passkey registration, before session creation (blocking)
- Retry up to 3 times with exponential backoff on transient failures
- UX: Hidden from user — show generic "Setting up your account..." loading state
- No crypto terminology exposed to end users

### Failure Handling
- Block registration completely if funding fails after all retries
- Error message: Specific but simple — "Network busy, try again in a few minutes"
- Log all failures, alert admins on high failure rate or low contract balance
- No manual funding endpoint — failed accounts require user to re-register
- No partial account states — either fully funded or not created

### Rate Limiting
- Primary dimension: Per email address (one funded account per email)
- Duplicate email: Block with message "An account with this email already exists. Try logging in."
- No cooldown between retry attempts after failures
- No global rate limit — rely on per-email uniqueness constraint

### Funding Contract
- Separately deployed NEAR smart contract (not a regular account)
- Access-controlled: Only authorized backend can call `fund()` method
- Admin can withdraw remaining balance and top-up contract
- Contract address configured via environment variable

### Admin UI
- New panel in Admin Settings for funding contract management
- Display current contract balance
- Top-up action to add NEAR to contract
- Recent funding activity list (accounts funded, timestamps, amounts)

### Production Strategy
- Testnet only for this phase
- Manual contract deployment, configure address in `.env`
- Mainnet funding deferred to future phase

### Claude's Discretion
- Contract implementation details (Rust structure, method signatures)
- Exponential backoff timing parameters
- Admin activity list pagination/limits
- Alert threshold configuration

</decisions>
