  <name>Task 1: Build MissionCreationService orchestrator</name>
  <files>backend/src/mission-creation/mission-creation-service.ts</files>
  <action>
Create `MissionCreationService` class with singleton export `missionCreationService`.

**Main method: `createMissionFromOPORD(input: CreateMissionInput, createdBy: string): Promise<MissionCreationResult>`**

Orchestration steps (in order, with try/catch around each non-critical step):

1. **Create tactical problem set** via `problemSetStore.createProblemSet()`:
   - name: `input.missionName`
   - description: `input.missionStatement`
   - echelon: `'tactical'`
   - classification: `input.classification`
   - parentProblemSetId: `input.parentProblemSetId`
   - mode: `input.mode`

2. **Assign members per confirmation modal selections** via `problemSetMemberStore.addMember()`:
   - Iterate `input.roleAssignments`
   - For each: `addMember(ps.id, assignment.did, assignment.role, assignment.daoRole, createdBy)`
   - CRITICAL: Do NOT auto-assign creator as commander. Creator may be J3/G3 staff, not the mission commander.
   - For `assignment.isAgent === true`: skip on-chain DAO `add_member` call. Use `addMember()` for off-chain record only. Check if `addMember` has a parameter to skip DAO call -- if not, catch and log the DAO error for agent DIDs. The off-chain membership record is what matters.

3. **Create inheritance chain** via `inheritanceService.createInheritanceChain(ps.id, input.parentProblemSetId, createdBy)`

4. **Set mission metadata** via `missionCreationStore.setMissionMetadata(ps.id, { areaOfOperations: input.areaOfOperations, missionState: 'planning', activatedAt: null, completedAt: null })`

5. **Initialize MDMP workflow** via `mdmpWorkflowService.createWorkflow({ missionId: ps.id, daoId: ps.daoId, createdBy })`:
   - Uses PS ID as missionId (MDMP service uses it as a string key, doesn't query missions table)
   - Wrap in try/catch; set `workflowCreated = true/false`

6. **Store mission assignment snapshot** via `missionCreationStore.createMissionAssignment()`:
   - All 8 doctrinal fields from input
   - task_ids from input.taskIds

7. **Auto-draft WARNO** via private `draftWarno(psId, input)` method:
   - Build WARNODraft from inherited context:
     - situation: from input (caller provides parent OPORD Para 1 summary)
     - mission: concatenate task statements from grouped tasks
     - generalInstructions.timeline: "Timeline TBD pending mission analysis"
     - generalInstructions.initialCoordination: "Report to parent PS for coordination"
     - generalInstructions.movementInstructions: "Movement instructions TBD"
     - serviceSupport: "IAW parent OPORD Para 4"
     - commandSignal.commandPost: "TBD"
     - commandSignal.succession: extract from roleAssignments (commander, xo)
     - commandSignal.frequency: "IAW parent OPORD Annex H"
     - status: 'draft', draftedAt: new Date().toISOString()
   - Store as a note: log via `problemSetActivityStore.log(psId, 'warno_drafted', createdBy, null, { warno })`
   - Mark: `missionCreationStore.markWarnoAsDrafted(assignment.id)`
   - Set `warnoDrafted = true/false`

8. **Log activity** via `problemSetActivityStore.log(ps.id, 'mission_created', createdBy, null, { sourceOpordPsId: input.parentProblemSetId, taskIds: input.taskIds })`

Return `MissionCreationResult` with all status flags.

**Helper method: `resolveCommandersIntent2Up(problemSetId: string): Promise<CommandersIntentChain>`**

Walk parentProblemSetId chain to collect commander's intent from own + parent + grandparent. For each level:
- Get the problem set via `problemSetStore.getProblemSet(id)`
- Try to read commander's intent from JPP Step 2 products. Since JPP products may not be directly queryable from backend service, use a simpler approach: query the `jpp_step_products` table directly for step_id='step2' products containing commander's intent.
- If the PS exists but has no JPP commander's intent (e.g., strategic PS without JPP), return null for that level.
- Gracefully handle missing levels -- include what's available.

**Helper method: `notifyChildrenOfOPORDUpdate(parentPsId: string, actorDid: string, changedFields: string[])`**

After parent OPORD saves, check for linked mission_assignments and log activity to each child PS:
- `const assignments = await missionCreationStore.getAssignmentsBySource(parentPsId)`
- For each: `problemSetActivityStore.log(assignment.targetProblemSetId, 'parent_opord_updated', actorDid, null, { sourceOpordPsId: parentPsId, updatedFields: changedFields })`

<task type="auto">
  <name>Task 2: Create mission creation and CCIR request API routes</name>
  <files>backend/src/api/mission-creation-routes.ts</files>
  <action>
Create Express router `missionCreationRouter` mounted at `/api/problem-sets/:problemSetId/missions`.

**Routes:**

1. **POST `/`** -- Create mission from OPORD
   - Validate request body with zod schema:
     - missionName: z.string().min(3).max(100)
     - missionStatement: z.string().min(1)
     - taskIds: z.array(z.string()).min(1)
     - taskStatement: z.string()
     - purpose: z.string()
     - commandersIntent: (JSONB, optional -- service resolves if not provided)
     - taskOrganization: z.record(z.unknown()).optional()
     - constraints: z.record(z.unknown()).optional()
     - ccirs: z.record(z.unknown()).optional()
     - roeReferences: z.array(z.string()).optional().default([])
     - areaOfOperations: z.object({ type: z.string(), coordinates: z.array(z.unknown()) }).nullable().optional()
     - timeline: z.record(z.unknown()).optional()
     - roleAssignments: z.array(z.object({ did: z.string(), displayName: z.string(), role: z.string(), daoRole: z.string(), isAgent: z.boolean() }))
     - classification: z.enum(['UNCLASSIFIED', 'SECRET', 'TOPSECRET']).default('UNCLASSIFIED')
     - mode: z.string().default('training')
   - Extract `userDid` from `req.headers['x-user-did']` (existing auth pattern)
   - If commandersIntent not provided, call `missionCreationService.resolveCommandersIntent2Up(problemSetId)` to auto-resolve
   - Call `missionCreationService.createMissionFromOPORD(input, userDid)`
   - Return 201 with MissionCreationResult

2. **GET `/`** -- List missions created from this OPORD
   - `missionCreationStore.getAssignmentsBySource(problemSetId)`
   - Return 200 with array of MissionAssignment

3. **POST `/ccir-requests`** -- Create CCIR/PIR request from child to parent
   - Validate: requestType ('ccir' | 'pir'), description (string min 1), targetPsId (string)
   - `ccirRequestStore.createRequest({ requestingPsId: problemSetId, targetPsId, requestType, description, createdBy: userDid })`
   - Log activity on target PS: `problemSetActivityStore.log(targetPsId, 'ccir_request_received', userDid, null, { requestId, requestType })`
   - Return 201

4. **GET `/ccir-requests`** -- List outgoing CCIR requests for this PS
   - `ccirRequestStore.getRequestsByRequester(problemSetId)`
   - Return 200

5. **GET `/ccir-requests/incoming`** -- List incoming CCIR requests targeting this PS
   - `ccirRequestStore.getRequestsByTarget(problemSetId)`
   - Return 200

6. **PATCH `/ccir-requests/:requestId`** -- Resolve a CCIR request (approve/deny)
   - Validate: status ('approved' | 'denied'), responseData (optional JSONB)
   - `ccirRequestStore.resolveRequest(requestId, status, userDid, responseData)`
   - Log activity on requesting PS
   - Return 200

**Router registration:** The executor must also add `import { missionCreationRouter } from './mission-creation-routes.js'` and `app.use('/api/problem-sets/:problemSetId/missions', missionCreationRouter)` in the main server file (likely `backend/src/index.ts` or `backend/src/api/index.ts`). Place this route BEFORE the `/:problemSetId/:tab` catch-all route per Phase 28 decision.
