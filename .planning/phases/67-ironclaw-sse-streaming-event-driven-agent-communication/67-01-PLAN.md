function getUserDid(req: Request): string {
  const anyReq = req as any;
  if (anyReq.zeroTrust?.did) return anyReq.zeroTrust.did as string;
  if (anyReq.user?.did) return anyReq.user.did as string;
  return (req.headers['x-did'] as string) || 'did:near:anonymous';
}

    **File 1: `backend/src/ironclaw/ironclaw-sse.ts`**

    Create the SSE endpoint handler following the established pattern from `doc-intelligence.ts` lines 875-904.

    Export `async function handleSSEStream(req: Request, res: Response): Promise<void>`.

    Implementation:
    1. Extract `scopeId` from `req.params.problemSetId` or compute global scope as `_global_${getUserDid(req)}` if the route is `/global/stream`.
    2. Extract `userDid` from `getUserDid(req)` (import the helper or use the same pattern as ironclaw-router.ts).
    3. **Auth guard (per D-11 / STRIDE T-67-01):** For global scope, verify that the scope matches the authenticated user's DID. For problem-set scope, the existing `requireAuth` middleware on the router handles this.
    4. **SSE connection limit (per STRIDE T-67-03):** Before registering, count existing clients for this scopeId. If > 5 connections per scope, return 429 Too Many Requests. This prevents connection amplification DoS.
    5. Set response headers exactly:
       ```
       Content-Type: text/event-stream
       Cache-Control: no-cache
       Connection: keep-alive
       X-Accel-Buffering: no
       ```
    6. Call `res.flushHeaders()`.
    7. **Last-Event-ID replay (per D-08):** Read `req.headers['last-event-id']` OR `req.query.lastEventId` as fallback (per Pitfall 4). Parse as integer. If present, call `ironclawEventStore.getEventsSince(scopeId, lastEventId)` and write each event as SSE format: `id: ${e.id}\nevent: ${e.event_type}\ndata: ${JSON.stringify(e.payload)}\n\n`.
    8. Register the client: `ironclawEventStore.registerClient(scopeId, res)`.
    9. Start heartbeat interval: every 30 seconds, write `': heartbeat\n\n'` to keep the connection alive through nginx proxies. Store interval handle.
    10. On `req.on('close', ...)`: clear heartbeat interval, call `ironclawEventStore.removeClient(scopeId, res)`, call `res.end()`.

    Also export a `getUserDid` helper (or import from a shared location — check if ironclaw-router.ts exports it; if not, duplicate the 5-line helper inline per existing project pattern of not extracting tiny helpers).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> SSE endpoint | Unauthenticated or wrong-user clients may attempt to connect to another user's stream |
| event payload -> client | Event payloads rendered on client could contain injection vectors |
| client reconnect -> server | Malicious Last-Event-ID values could cause expensive DB queries |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-67-01 | Information Disclosure | ironclaw-sse.ts global stream | mitigate | Validate getUserDid(req) matches scope_id pattern `_global_${userDid}` — reject mismatched scopes with 403 |
| T-67-02 | Tampering | ironclaw-event-store.ts payload | mitigate | event_type validated against IronclawEventType const before insert; payload is JSONB (not raw string) |
| T-67-03 | Denial of Service | ironclaw-sse.ts | mitigate | Limit to 5 concurrent SSE connections per scopeId in registerClient(); return 429 on excess |
| T-67-04 | Tampering | ironclaw-sse.ts Last-Event-ID | mitigate | Parse Last-Event-ID as integer with parseInt; reject NaN; use parameterized query (no SQL injection) |
| T-67-05 | Information Disclosure | ironclaw_events table | accept | Permanent retention per D-07; access gated by requireAuth middleware + scope validation |
</threat_model>
