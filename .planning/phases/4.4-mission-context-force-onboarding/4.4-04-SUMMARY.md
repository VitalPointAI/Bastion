## Decisions Made

**SIDC validation strictness:**
- Enforced 15-character format per MIL-STD-2525D standard
- Returns 400 Bad Request on invalid SIDC

**Cycle detection error handling:**
- Returns 409 Conflict status when relationship would create cycle
- Separate validation endpoint allows pre-flight checking without attempting mutation

**Hierarchy tree structure:**
- Returns nested HierarchyNode objects with unit, relationship, and children
- Relationship field shows how unit connects to parent
- Enables frontend to render tree views without additional processing

**Matrix endpoint design:**
- Returns relationship matrix with unitId/unitName row headers
- Each cell contains relationship type or null
- Includes full units array for frontend grid rendering

4. PATCH /api/command/units/:id - Update unit
5. DELETE /api/command/units/:id - Delete unit
6. POST /api/command/relationships - Create relationship (with cycle detection)
7. GET /api/command/relationships?missionId=X - List relationships
8. DELETE /api/command/relationships/:id - Delete relationship
9. PATCH /api/command/relationships/:id - Update relationship
10. GET /api/command/hierarchy/:missionId - Get hierarchical tree
11. POST /api/command/validate-hierarchy/:missionId - Validate before creating
12. GET /api/command/matrix/:missionId - Get relationship matrix

**Architecture notes:**
- Cycle detection prevents A→B→A command chains
