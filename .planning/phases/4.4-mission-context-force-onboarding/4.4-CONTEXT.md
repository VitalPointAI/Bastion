# Phase 4.4: Mission Context & Force Onboarding — Context

> Decisions captured through discussion on 2026-01-24

## 1. Mission Workspace Creation

### Creation Flow
- **Multi-step wizard** with guided steps
- **Required steps:** Name + at least one participant + Area of Operations (AO) defined on map
- All other configuration (resources, sensors, detailed setup) can be added later

### Templates
- **Optional templates** — users can start blank or pick from a template library (reconnaissance, convoy, etc.)
- Templates provide structure, customizable after selection

### Access & Permissions
- **Any authenticated member** can create missions
- No role restriction on mission creation

### Participant Management
- **Direct add from org roster** — pick known org members, added immediately
- **Invite link/code** — generate shareable link or code for external participants to join
- Both methods supported simultaneously

### Mission Lifecycle
- **Explicit states:** Planning → Active → Complete
- Users manually transition between states

### Duplication
- **Structure only by default** — copy config/structure without people or live data
- **Option to include resources** — can choose to bring vehicles, personnel, equipment when duplicating

### Archival
- **Archive only** — missions are never deleted, only archived and hidden
- No hard delete capability

## 2. Command Relationship Editor

### Visualization
- **Both views available:**
  - Org chart (tree diagram) for hierarchy visualization
  - Table/matrix view showing relationships in grid format
- Toggle between views

### Relationship Types
- **Full military set:**
  - OPCON (Operational Control)
  - TACON (Tactical Control)
  - ADCON (Administrative Control)
  - COCOM (Combatant Command)
  - Support relationships (see below)

### Support Relationship Types
- **Full doctrinal set:**
  - DS (Direct Support)
  - GS (General Support)
  - GSR (General Support-Reinforcing)
  - R (Reinforcing)

### Additional Responsibilities
- Ability to assign joint/combined responsibilities:
  - JTF Comd (Joint Task Force Commander)
  - JFLCC (Joint Force Land Component Commander)
  - JFMCC (Joint Force Maritime Component Commander)
  - Other similar designations

### Assignment UX
- **Both methods:**
  - Drag-and-drop for quick placement onto hierarchy
  - Form-based for detailed configuration (relationship type, dates, notes)

### Multi-Hatted Positions
- **Merged node:** Single node with multiple role badges when one person holds multiple positions

### Permission Cascade
- **Automatic:** Superior automatically gains visibility into subordinate resources based on command relationship

### Temporality
- **Optional dates:** Relationships can have start/end dates if needed, but not required
- History tracked when dates are used

### Validation
- **Advisory warnings:** Show warnings for circular relationships, orphaned units, etc.
- **Allow overrides:** User can save despite warnings

## 3. Resource Catalog Design

### Data Entry
- **Both methods:**
  - Bulk import (CSV/spreadsheet) for initial load
  - Manual entry via forms for updates and additions

### Category Structure
- **Multi-tier taxonomy:** Deep hierarchy matching military logistics standards
- Follows established military classification systems

### Master Catalog
- **Both:**
  - Pre-built standard military equipment database to select from
  - Organizations can extend with custom resource types

### Detail Level
- **Full specification:**
  - Technical data and specifications
  - Maintenance history
  - Certifications and qualifications
  - Capabilities

### Availability Tracking
- **Detailed status with reason codes:**
  - FMC (Fully Mission Capable)
  - PMC (Partially Mission Capable)
  - NMC (Not Mission Capable)
  - Include reason codes for status

### Resource Assignment Model
- **US Doctrinal Approach:**
  - Apportioned (identified for planning)
  - Allocated (made available for use)
  - Assigned (placed under command)
- Enables hybrid pool/unit-owned model

### Location Tracking
- **Required:** Every resource must have a location
- **Pipeline tracking:** Track resources in procurement/production with expected availability dates
- **Automatic where possible:** Integrate multiple sources

### Location Sources
- Device GPS feeds from vehicle/equipment transponders
- Last known from situation reports
- Sensor data fusion for best estimate
- Combine all available sources

### Procurement Pipeline Visualization
- **Timeline/Gantt view:** Show expected arrival dates on a timeline
- Track items through stages (ordered, in transit, QA, delivered)

### Resource Relationships
- **Both:**
  - Auto-infer relationships where possible (weapon → compatible ammo types)
  - Allow manual linking for dependencies

### Consumables (Ammo, Fuel, Supplies)
- **Supply point model:** Track by storage location with quantities
- Not individual item tracking

### Personnel
- **Separate but linked:**
  - Personnel roster is a distinct system
  - Assignable to units and linkable to resources
  - Track readiness status per person
  - **Readiness definition is configurable** by mission requirement and/or staff/Comd

## 4. Map Overlay Controls

### Layer Toggle UI
- **Both:**
  - Floating toolbar on map edge for quick toggles
  - Sidebar panel for detailed layer configuration
- Quick access + detailed control

### Symbology
- **Full MIL-STD-2525D:** Exact military standard symbols
- Familiar to trained users, no simplified alternatives

### Sensor Coverage Visualization
- **Both options per sensor type:**
  - Simple polygons/circles showing coverage extent
  - Gradient heatmap showing detection probability
- User can choose visualization mode

### Real-Time Position Updates
- **Trail + current position:**
  - Show movement trail behind current position
  - Trail display is toggleable (on/off per user preference)
- Smooth visual updates
