  <name>Task 1: Create Command API Router</name>
  <files>
    backend/src/api/command.ts
  </files>
  <action>
    Create backend/src/api/command.ts:

    Unit endpoints:
    - POST /api/command/units - Create unit (body: { missionId, name, sidc, parentDid?, location? })
    - GET /api/command/units?missionId=X - List units for mission
    - GET /api/command/units/:id - Get single unit
    - PATCH /api/command/units/:id - Update unit (name, sidc, location)
    - DELETE /api/command/units/:id - Delete unit (cascade relationships?)

    Relationship endpoints:
    - POST /api/command/relationships - Create relationship (validate no cycle)
    - GET /api/command/relationships?missionId=X - List relationships for mission
    - GET /api/command/hierarchy/:missionId - Get full hierarchy tree (recursive CTE)
    - DELETE /api/command/relationships/:id - Delete relationship
    - PATCH /api/command/relationships/:id - Update relationship type or effective dates

    Special endpoints:
    - POST /api/command/validate-hierarchy/:missionId - Check for cycles without saving
    - GET /api/command/matrix/:missionId - Get relationship matrix view data

    Error handling:
    - 400 for validation errors (invalid SIDC, missing missionId)
    - 409 for cycle detection
    - 404 for unit/relationship not found

    The hierarchy endpoint should return a nested tree structure:
    ```typescript
    interface HierarchyNode {
      unit: Unit;
      relationship?: CommandRelationship; // How connected to parent
      children: HierarchyNode[];
    }
    ```
