## Decisions Made
- **Token security pattern:** Raw invite tokens returned only on creation (one-time visibility), stored as sha256 hash, verified via hash comparison on acceptance
- **DID flexibility:** Support both X-DID header and Authorization Bearer token for user authentication
- **State validation:** Enforce state machine at store level (planning→active→complete→archived) with 409 error for invalid transitions
- **Error consistency:** HTTP status codes aligned with semantic meaning (400 validation, 404 not found, 409 conflict, 410 gone)
