**models.py:**
- Use Pydantic v2 BaseModel
- `MissionState(str, Enum)`: accepted, executing, awaiting_auth, complete, failed, rejected
- `TargetLocation(BaseModel)`: x (float), y (float) — room-relative meters
- `Waypoint(BaseModel)`: x (float), y (float)
- `MissionParams(BaseModel)`: target_location (Optional[TargetLocation]), waypoints (Optional[List[Waypoint]]), speed (int, 0-255), duration_sec (Optional[float]), autonomy_policy (str)
- `MissionJSON(BaseModel)`: mission_id, robot_id, command (str), params (MissionParams), issued_by, timestamp (datetime), auth_token
- `StateUpdateMsg`: type="robot:state_update", mission_id, state (MissionState), timestamp, metadata (dict)
- `TelemetryMsg`: type="robot:telemetry", robot_id, position (dict with x,y), heading (float), battery_pct (int), timestamp
- `RegisterMsg`: type="robot:register", robot_id, auth_token, capabilities (list[str])

**config.py:**
- Load from environment variables using python-dotenv
- Required: BASTION_WS_URL (e.g., ws://192.168.1.100:3001), ROBOT_ID (default "alpha"), AUTH_TOKEN
- Optional: SERIAL_PORT (default /dev/ttyTHS1), CALIBRATION_PROFILE (default "default")
- Validate required vars on import, raise clear error if missing

**calibration.py:**
- `CalibrationProfile` dataclass: name, room_width (meters), room_height (meters), map_bounds (dict with minLat, maxLat, minLng, maxLng)
- `DEFAULT_PROFILES` dict with "default" (5m x 8m room -> small lat/lng bounding box ~0.005 degrees centered on a sensible demo location)
- `room_to_map(x, y, profile)` function — linear transform from room meters to lat/lng
- `load_profile(name)` — loads from DEFAULT_PROFILES or from a JSON config file if exists
- `save_profile(profile)` — saves to `calibration_profiles.json` file
- Support for named configs per CONTEXT.md decision (e.g., "Conference Room A", "Lab")

**rvr_driver.py:**
- `RVRDriver` class wrapping Sphero SDK asyncio variant
- `__init__(serial_port)` — creates `SpheroRvrAsync` with `SerialAsyncDal`
- `async wake()` — wakes RVR+, waits 2 seconds
- `async drive(speed, heading, duration_sec)` — drives at speed/heading for duration, then stops
- `async drive_to_point(x, y, speed)` — calculates heading from current position, drives toward target (simple dead-reckoning: calculate heading angle, drive for estimated time based on distance/speed)
- `async set_leds(r, g, b)` — sets all LEDs to color
- `async flash_leds(r, g, b, count, interval)` — flashes LEDs count times
- `async safe_stop()` — stops all motors immediately
- `async get_battery_pct()` — returns battery percentage (or simulated value if sensor unavailable)
- `async close()` — cleanly closes connection
- **IMPORTANT:** Wrap all Sphero SDK calls in try/except so driver failures don't crash the mission client. Log errors with `structlog`.
- Include a `SIMULATE` flag (from config) — when True, log actions instead of calling real SDK. This allows testing without hardware.

**mission_executor.py:**
- `MissionExecutor` class
- `__init__(driver: RVRDriver, send_state_fn, send_telemetry_fn)` — takes the RVR driver and callback functions for sending WS messages
- `current_mission: Optional[MissionJSON]` — tracks active mission
- `current_state: Optional[MissionState]` — tracks current state
- `async execute_mission(mission: MissionJSON)` — main entry point:
  1. Validate mission (reject if malformed, send rejected state)
  2. Send state_update "accepted"
  3. Dispatch to behavior by command type:
     - `find_engage` -> `_execute_find_engage(mission)`
     - `patrol_route` -> `_execute_patrol_route(mission)`
  4. On completion, send state_update "complete"
  5. On error, send state_update "failed" with error metadata
- `async _execute_find_engage(mission)`:
  1. Send state_update "executing"
  2. Drive to target_location using `driver.drive_to_point()`
  3. Set LEDs green during movement
  4. On arrival, send state_update "awaiting_auth" with metadata: { action: "engage_target", location: target_location }
  5. Wait for authorization response (set an asyncio.Event, store it)
  6. If approved: flash LEDs red 5 times, send state_update "executing" then "complete" with metadata: { result: "target_engaged" }
  7. If denied: set LEDs yellow, send state_update "complete" with metadata: { result: "engagement_denied" }
- `async _execute_patrol_route(mission)`:
  1. Send state_update "executing"
  2. Set LEDs green
  3. For each waypoint in mission.params.waypoints:
     - Drive to waypoint using `driver.drive_to_point()`
     - Send telemetry at each waypoint arrival
  4. Send state_update "complete"
- `async handle_auth_response(approved: bool)` — resolves the awaiting authorization event
- `async abort()` — calls driver.safe_stop(), sends "failed" state

**mission_client.py:**
- Main entry point (`if __name__ == "__main__"`)
- `async run()`:
  1. Load config
  2. Initialize RVR driver (or simulated driver if SIMULATE=true)
  3. Wake RVR+
  4. Connect to Bastion WS endpoint: `websockets.connect(f"{BASTION_WS_URL}/ws/robot")`
  5. Send registration message (robot_id, auth_token, capabilities: ["patrol_route", "find_engage"])
  6. Start telemetry heartbeat task (every 2 seconds, sends position/heading/battery)
  7. Main receive loop: `async for raw in ws:`
     - Parse JSON message
     - Route by type:
       - `mission:assign` -> create MissionExecutor task to execute mission
       - `mission:rejected` -> log rejection reason
       - `auth:response` -> forward to executor.handle_auth_response()
     - Handle parse errors gracefully
  8. On disconnect: safe_stop, attempt reconnect after 5 seconds (exponential backoff up to 60s)
- `async telemetry_loop(ws, driver, robot_id)`:
  - Every 2 seconds: read position (from driver or dead-reckoning estimate), heading, battery
  - Send TelemetryMsg via WS
  - If WS is closed, stop loop
- Use `asyncio.gather()` to run telemetry loop and message receive loop concurrently
- Use `structlog` for all logging with structured fields (robot_id, mission_id, state)
- Top-level `asyncio.run(run())` with clean shutdown on SIGINT/SIGTERM (safe_stop + close)
- Reconnection loop wraps the entire WS connection in a while True with exponential backoff
