Create the `backend/src/robot/` directory and build the core robot module:

**robot-types.ts:**
- Use const objects (not enums) per project convention
- `RobotMissionState` const: pending, accepted, executing, awaiting_auth, complete, failed, rejected
- `MissionJSONSchema` using zod (already installed): mission_id, robot_id, command (enum: 'patrol_route' | 'find_engage'), params (target_location?, waypoints?, speed 0-255, duration_sec?, autonomy_policy), issued_by, timestamp, auth_token
- `RobotWsMessageType` const: register, state_update, telemetry, mission_assign, mission_rejected, auth_request, auth_response
- TypeScript interfaces for each WS message shape (RobotRegisterMsg, RobotStateUpdateMsg, RobotTelemetryMsg, MissionAssignMsg, AuthRequestMsg, AuthResponseMsg)
- `RobotConnectionState` const: connected, disconnected
- Interface `ConnectedRobot`: robot_id, ws reference, state, current_mission_id, did, capabilities, last_heartbeat

**robot-store.ts:**
- PostgreSQL store for robot missions (uses `getPool()` from existing db module)
- `ensureRobotTables()` — creates `robot_missions` and `robot_connections` tables if not exist (follows existing lazy-init pattern)
- `robot_missions` table: id, mission_id, robot_id, problem_set_id, command, params (JSONB), state, issued_by, issued_at, updated_at, gate_id (nullable), rejection_reason (nullable)
- `robot_connections` table: id, robot_id, did, capabilities (JSONB), state, connected_at, last_heartbeat
- CRUD methods: saveMission, updateMissionState, getMission, getActiveMissions, saveConnection, updateConnectionHeartbeat, removeConnection

**robot-mission-service.ts:**
- Singleton pattern via `getRobotMissionService()`
- `connectedRobots` in-memory Map<string, ConnectedRobot> keyed by robot_id
- `handleRobotMessage(ws, msg)` — routes by message type to handler methods
- `handleRegister(ws, msg)` — validates, stores in connectedRobots map and DB, sends ack
- `handleStateUpdate(ws, msg)` — updates mission state in DB, if state is 'awaiting_auth' creates a gate (implementation in Plan 03), broadcasts state change
- `handleTelemetry(ws, msg)` — updates last_heartbeat, stores latest position (integration with ResourceTelemetryService comes in Plan 04)
- `dispatchMission(missionJson)` — validates with MissionJSONSchema, finds connected robot, sends MissionAssignMsg via WS, saves to DB with state 'pending'
- `handleRobotDisconnect(robotId)` — removes from connectedRobots, updates DB state
- `getConnectedRobots()` — returns list of connected robots
- `getMissionStatus(missionId)` — returns current mission state from DB

**index.ts:**
- Barrel export: re-export setupRobotWebSocket, getRobotMissionService, types, robotStore
