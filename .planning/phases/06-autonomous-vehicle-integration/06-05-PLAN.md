**RobotMissionTrigger.tsx (new component):**
- Card-style panel matching existing Direct tab styling (dark theme, Tailwind)
- Header: "Robot Mission Control" with robot icon
- **Connected Robots section:**
  - Fetch `GET /api/robot/robots` on mount
  - Show list of connected robots with status indicator (green dot if connected)
  - If no robots connected, show "No robots connected" with grey text
- **Mission Trigger form:**
  - Dropdown: Mission Type — "Find & Engage Target" or "Patrol Route"
  - For find_engage: x/y coordinate inputs (room meters) for target location, with sensible defaults (e.g., x=2.5, y=3.0)
  - For patrol_route: simple waypoint list (add/remove waypoints, each with x/y inputs). Start with 3 default waypoints forming a triangle.
  - Speed slider: 0-255 (default 50)
  - Robot ID selector (from connected robots list, or text input defaulting to "alpha")
  - Problem Set ID: read from ProblemSetContext or text input
  - "Launch Mission" button — styled as a prominent action button (blue/green)
    - Calls `POST /api/robot/missions/trigger` with form data
    - On success: show success toast with mission_id
    - On 403 policy violation: show error toast with rejection reason
    - On error: show error toast
    - Disable button while request in flight (loading spinner)
- **Active Mission status:**
  - Below the form, show current mission state if one is active
  - Poll `GET /api/robot/missions/:missionId` every 2 seconds while mission active
  - Show state badge with color matching COP layer colors
  - If awaiting_auth: show prominent "Awaiting Authorization" badge in yellow with link to governance/decisions

**DirectTab.tsx modifications:**
- Import and render `<RobotMissionTrigger>` in the Direct tab
- Position it as a new section/card — ideally in the sidebar or as a collapsible panel
- Pass `problemSetId` from context

- `GET /api/robot/calibration/profiles` — returns list of saved calibration profile names
- `GET /api/robot/calibration/profiles/:name` — returns a specific profile
- `PUT /api/robot/calibration/profiles/:name` — saves/updates a calibration profile (JSON body with room_width, room_height, map_bounds)
- Store profiles in a JSON file at `backend/data/calibration-profiles.json` (simple file-based storage for MVP — no DB table needed)
- Default profile seeded on first access if file doesn't exist
