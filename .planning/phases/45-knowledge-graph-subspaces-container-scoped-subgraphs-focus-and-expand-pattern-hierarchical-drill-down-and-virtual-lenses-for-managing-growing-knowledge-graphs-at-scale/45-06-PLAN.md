Create `useBrainNHop` hook for on-demand N-hop neighbor loading with concentric ring expansion.

**Hook signature:**
```typescript
function useBrainNHop(
  workspaceId: string,
): {
  expandedHops: number;                    // current expansion depth (0 = no expansion)
  expandedData: BrainGraphData | null;     // null when no expansion active
  loading: boolean;
  showWarning: boolean;                    // true when hops > 3
  expand: (focusNodeId: string) => void;   // load next hop ring
  reset: () => void;                       // clear expansion (back to 0)
  setFocusNode: (nodeId: string | null) => void;  // change focus node (resets hops)
}
```

**Key behaviors:**

1. **expand(focusNodeId):** Increments `expandedHops` by 1, fetches from `/api/brain/nhop?workspaceId=${workspaceId}&nodeId=${focusNodeId}&hops=${expandedHops + 1}`. The backend returns all nodes within that many hops, not just the new ring.

2. **Race condition protection (per RESEARCH.md Pitfall 2):** Use `AbortController`. Keep a ref to the current controller. On each `expand()` call:
   - Abort the previous in-flight request
   - Create new AbortController
   - Tag the fetch with the requested hop count
   - On response: only apply if `responseHops >= currentExpandedHops` (prevent stale earlier responses from overwriting newer ones)

3. **Warning threshold:** `showWarning = expandedHops >= 3`. When true, the controller should display a warning before the next expand: "This may load many nodes." The hook just exposes the boolean — the UI rendering is done by the controller.

4. **reset():** Sets `expandedHops` to 0, `expandedData` to null, aborts any in-flight request.

5. **setFocusNode(nodeId):** When focus node changes, reset hops to 0 and clear expandedData.

6. **Response mapping:** The N-hop endpoint returns raw graph nodes/edges. Map them to `BrainNode[]` and `BrainEdge[]` matching the types.ts shape. Use the same mapping logic as `useBrainData.ts` (check how it maps API responses to BrainNode/BrainEdge). If the mapping is complex, import the mapping function from useBrainData if it's exported; otherwise, do a simple identity mapping since the backend should return data in the correct shape.

**Error handling:** On fetch error (non-abort), set `loading = false`, do NOT update expandedHops. Log error to console. The controller can retry via another `expand()` call.
