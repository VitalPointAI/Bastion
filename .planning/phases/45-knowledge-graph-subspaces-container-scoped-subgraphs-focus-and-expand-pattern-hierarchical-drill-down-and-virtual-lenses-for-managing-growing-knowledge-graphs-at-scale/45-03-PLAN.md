**Hook signature:**
```typescript
function useBrainLens(problemSetId: string): {
  activeLens: BrainLens;
  allLenses: BrainLens[];       // built-in + user's custom + shared
  setActiveLensId: (id: string) => void;
  saveLens: (lens: Omit<BrainLens, 'id' | 'createdBy' | 'isBuiltIn'>) => Promise<void>;
  deleteLens: (id: string) => Promise<void>;
  cloneLens: (id: string) => Promise<void>;
  applyLensFilters: (nodes: BrainNode[]) => BrainNode[];  // filters nodes by active lens
}
```

**Key behaviors:**
1. `activeLens` defaults to Overview lens on mount
2. `allLenses` = BUILTIN_LENSES + fetched custom lenses from `/api/brain/lenses?problemSetId=X`
3. `applyLensFilters` filters nodes based on `activeLens.nodeTypeFilters`, `activeLens.actorCategoryFilters`, and `activeLens.showGapNodes`. Empty filter arrays mean "show all". Returns only nodes that pass all filters.
4. `saveLens`, `deleteLens`, `cloneLens` call the backend API (POST/DELETE/POST lenses endpoints) and refetch the lens list
5. The hook does NOT call `useBrainClustering` directly — it exposes `activeLens.clusterMode` for the controller to pass to `useBrainClustering`. This avoids a hook-in-hook dependency issue.

**CRITICAL per RESEARCH.md Pitfall 5:** Only trigger force reheat when `clusterMode` actually changes between lens switches. Pure filter-only changes should NOT reheat the simulation.

Fetch custom lenses with `useEffect` on mount + after save/delete/clone. Use simple fetch() to `/api/brain/lenses?problemSetId=${problemSetId}`.
