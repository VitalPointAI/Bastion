Create `useBrainSubspaces` hook that manages subspace state, computes filtered graph data for active subspace, and generates ghost stub nodes.

**Hook signature:**
```typescript
function useBrainSubspaces(
  problemSetId: string,
  data: BrainGraphData,
): {
  subspaces: BrainSubspace[];              // all subspaces (container-auto + custom)
  activeSubspaceId: string | null;
  setActiveSubspaceId: (id: string | null) => void;
  subspaceData: BrainGraphData;            // filtered to active subspace + ghost stubs
  createManualSubspace: (name: string, nodeIds: string[]) => Promise<void>;
  createSmartSubspace: (name: string, query: SmartSubspaceQuery) => Promise<void>;
  deleteSubspace: (id: string) => Promise<void>;
  updateSubspace: (id: string, updates: { name?: string; isShared?: boolean }) => Promise<void>;
}
```

**Key behaviors:**

1. **Container-auto subspaces:** On every `data` change, scan `data.nodes` for unique `containerId` values. Create virtual `BrainSubspace` entries with `subspaceType: 'container'`, using the `containerLabel` from the first node with that containerId. These are NOT persisted — they are computed from the data.

2. **Custom subspaces:** Fetch from `/api/brain/subspaces?problemSetId=X` on mount and after CRUD operations.

3. **Combined list:** `subspaces` = container-auto + custom (manual + smart), sorted: container-auto first (alphabetical), then custom (alphabetical).

4. **Smart subspace membership (per RESEARCH.md Pitfall 3):** Compute at render time by filtering `data.nodes` against `queryDefinition`. Do NOT store computed node IDs. Re-evaluate every time `data` changes:
   ```typescript
   function evaluateSmartSubspace(query: SmartSubspaceQuery, nodes: BrainNode[]): string[] {
     return nodes
       .filter(n => {
         if (query.nodeTypes?.length && !query.nodeTypes.includes(n.type)) return false;
         if (query.actorCategories?.length && n.actorCategory && !query.actorCategories.includes(n.actorCategory)) return false;
         if (query.containerId && n.containerId !== query.containerId) return false;
         if (query.dimeCategories?.length && n.dimeCategory && !query.dimeCategories.includes(n.dimeCategory)) return false;
         if (query.namePattern) {
           const regex = new RegExp(query.namePattern.replace(/\*/g, '.*'), 'i');
           if (!regex.test(n.label)) return false;
         }
         return true;
       })
       .map(n => n.id);
   }
   ```

5. **Subspace filtering + ghost stubs:** When `activeSubspaceId` is set, `subspaceData` contains:
   - Nodes belonging to the active subspace
   - Ghost stub nodes for external nodes connected by at least one edge to a subspace node
   - Ghost edges (the cross-boundary edges with `isGhostLink: true`)
   - Internal edges (both endpoints in the subspace)

   Per RESEARCH.md Pitfall 1: Ghost stub nodes should have `fx`/`fy`/`fz` set (fixed position at subspace boundary) to prevent them from distorting force layout. Set ghost stubs' x/y/z to the average position of their connected subspace nodes, offset by 50 units outward.

6. When `activeSubspaceId` is null, `subspaceData` = original `data` (full graph, no filtering).

interface SubspaceSidebarProps {
  subspaces: BrainSubspace[];

**UI structure:**
1. **Header:** "Subspaces" title with collapse/expand toggle
2. **"Full Graph" entry:** Always first, acts as "home" (sets activeSubspaceId to null)
3. **Container subspaces section:** Collapsible group labeled "Containers", each item shows:
   - Container name (from subspace.name)
   - Node count badge
   - Type badge: small tag showing "auto"
4. **Custom subspaces section:** Collapsible group labeled "Custom", each item shows:
   - Subspace name
   - Type badge: "manual" or "smart" (different colors)
   - For manual: node count
   - For smart: dynamic count computed from current data
   - Delete button (icon, small)
5. **Footer actions:**
   - "Create from selection" button (disabled if selectedNodeIds empty)
   - "Create smart subspace" button

**Click behavior:**
- Click a subspace entry → calls `onSubspaceSelect(subspace.id)`
- Active subspace highlighted with accent border (same accent color as cluster toggle active)
- Double-click is handled by BrainVisualization for cluster drill-in, not by this sidebar
