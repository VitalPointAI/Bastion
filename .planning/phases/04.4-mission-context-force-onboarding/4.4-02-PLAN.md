<task type="auto">
  <name>Task 1: Create Mission API Router</name>
  <files>
    backend/src/api/missions.ts
  </files>
  <action>
    Create backend/src/api/missions.ts following patterns from api/graph.ts and api/strategic.ts:

    Mission CRUD:
    - POST /api/missions - Create mission (validate with MissionInputSchema)
    - GET /api/missions - List missions (filter by state, classification)
    - GET /api/missions/:id - Get single mission
    - PATCH /api/missions/:id - Update mission (name, description, areaOfOps)
    - POST /api/missions/:id/activate - Transition from planning to active
    - POST /api/missions/:id/complete - Transition from active to complete
    - POST /api/missions/:id/archive - Transition from complete to archived

    Participant endpoints:
    - GET /api/missions/:id/participants - List participants
    - DELETE /api/missions/:id/participants/:participantId - Remove participant

    Invite endpoints:
    - POST /api/missions/:id/invites - Create invite (body: { role, inviteeEmail?, inviteeDid?, expirationHours? })
    - GET /api/missions/:id/invites - List pending invites
    - DELETE /api/missions/:id/invites/:inviteId - Cancel invite
    - POST /api/missions/accept-invite - Accept invite (body: { token })

    Error handling:
    - 400 for validation errors
    - 404 for mission/participant not found
    - 409 for invalid state transitions
    - 410 for expired invites

    Include DID extraction from request headers (X-DID or Authorization) for createdBy tracking.
  </action>
  <verify>
    - TypeScript compiles: `cd backend && npx tsc --noEmit`
    - Router exports missionRouter
  </verify>
  <done>
    All mission, participant, and invite endpoints implemented with proper validation and error handling.
  </done>
