# Phase 4.4: Mission Context & Force Onboarding - Research

**Researched:** 2026-01-24
**Domain:** Military operations UI, command structure modeling, resource management, mapping
**Confidence:** HIGH (verified through multiple sources and official documentation)

## Summary

This phase requires building four major feature areas: (1) mission workspace wizard with participant management, (2) command relationship editor with tree visualization, (3) resource catalog with bulk import and availability tracking, and (4) map overlays with MIL-STD-2525D symbology and real-time tracking.

The research confirms that established open-source libraries exist for all major requirements. The codebase already uses React 19, Leaflet/react-leaflet 5.0, XState v5, and react-hook-form - providing a solid foundation. For military symbology, **milsymbol** is the de facto standard with 1000+ symbols generated in <20ms. For org charts, **react-organizational-chart** provides the simplest React-native tree rendering. For drag-drop trees, **react-complex-tree** offers the best accessibility and customization.

**Primary recommendation:** Use the existing tech stack (XState for lifecycle, react-hook-form for wizards, Leaflet for maps) and add specialized libraries only where needed - milsymbol for symbology, react-organizational-chart for command hierarchy visualization, and leaflet-realtime for live tracking.

### Pattern 1: Multi-Step Wizard with XState
**What:** Use XState to manage wizard step transitions with validation gates
**When to use:** Mission creation wizard, any multi-step form with complex validation
**Example:**
```typescript
// Source: Codebase pattern from approval-machine.ts + xstate-wizards pattern
import { setup, assign } from 'xstate';

const missionWizardMachine = setup({
  types: {
    context: {} as {
      name: string;
      participants: string[];
      areaOfOps: GeoJSON.Polygon | null;
      currentStep: number;
    },
    events: {} as
      | { type: 'NEXT' }
      | { type: 'BACK' }
      | { type: 'SET_NAME'; name: string }
      | { type: 'ADD_PARTICIPANT'; participantId: string }
      | { type: 'SET_AREA'; area: GeoJSON.Polygon },
  },
  guards: {
    nameValid: ({ context }) => context.name.trim().length > 0,
    hasParticipants: ({ context }) => context.participants.length > 0,
    hasArea: ({ context }) => context.areaOfOps !== null,
  },
}).createMachine({
  id: 'missionWizard',
  initial: 'nameStep',
  states: {
    nameStep: {
      on: {
        SET_NAME: { actions: assign({ name: ({ event }) => event.name }) },
        NEXT: { target: 'participantsStep', guard: 'nameValid' },
      },
    },
    participantsStep: {
      on: {
        ADD_PARTICIPANT: {
          actions: assign({
            participants: ({ context, event }) => [...context.participants, event.participantId]
          })
        },
        NEXT: { target: 'areaStep', guard: 'hasParticipants' },
        BACK: 'nameStep',
      },
    },
    areaStep: {
      on: {
        SET_AREA: { actions: assign({ areaOfOps: ({ event }) => event.area }) },
        NEXT: { target: 'reviewStep', guard: 'hasArea' },
        BACK: 'participantsStep',
      },
    },
    reviewStep: {
      on: {
        BACK: 'areaStep',
        SUBMIT: 'submitting',
      },
    },
    submitting: { /* invoke API call */ },
    complete: { type: 'final' },
  },
});
```

```typescript
// Source: milsymbol GitHub examples/leaflet-divicons
import ms from 'milsymbol';
import L from 'leaflet';

function createMilSymbolIcon(sidc: string, options?: object): L.DivIcon {
  const symbol = new ms.Symbol(sidc, {
    size: 35,
    ...options,
  });

  const anchor = symbol.getAnchor();

  return L.divIcon({
    className: 'milsymbol-marker',
    html: symbol.asSVG(),
    iconAnchor: [anchor.x, anchor.y],
    iconSize: [symbol.getSize().width, symbol.getSize().height],
  });
}

// Usage in React component
function MilSymbolMarker({ position, sidc, unitName }: Props) {
  const icon = useMemo(() => createMilSymbolIcon(sidc), [sidc]);

  return (
    <Marker position={position} icon={icon}>
      <Popup>{unitName}</Popup>
    </Marker>
  );
}
```

### Pattern 3: Command Hierarchy with Adjacency List
**What:** Store hierarchical command relationships using adjacency list pattern
**When to use:** Command relationship storage where relationships change frequently
**Example:**
```sql
-- Source: PostgreSQL hierarchical patterns research
CREATE TABLE mission_units (
  unit_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  mission_id UUID NOT NULL REFERENCES missions(id),
  name VARCHAR(255) NOT NULL,
  unit_type VARCHAR(50),  -- 'OPCON', 'TACON', 'ADCON', etc.
  created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE command_relationships (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  mission_id UUID NOT NULL REFERENCES missions(id),
  superior_unit_id UUID NOT NULL REFERENCES mission_units(unit_id),
  subordinate_unit_id UUID NOT NULL REFERENCES mission_units(unit_id),
  relationship_type VARCHAR(20) NOT NULL, -- 'OPCON', 'TACON', 'ADCON', 'COCOM', 'DS', 'GS', 'GSR', 'R'
  effective_from TIMESTAMPTZ,
  effective_to TIMESTAMPTZ,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE(mission_id, superior_unit_id, subordinate_unit_id, relationship_type)
);

-- Get full hierarchy using recursive CTE
WITH RECURSIVE unit_hierarchy AS (
  -- Base case: top-level units (no superior)
  SELECT u.*, 0 AS depth, ARRAY[u.unit_id] AS path
  FROM mission_units u
  WHERE u.mission_id = $1
    AND NOT EXISTS (
      SELECT 1 FROM command_relationships cr
      WHERE cr.subordinate_unit_id = u.unit_id
    )

  UNION ALL

  -- Recursive case
  SELECT u.*, h.depth + 1, h.path || u.unit_id
  FROM mission_units u
  JOIN command_relationships cr ON cr.subordinate_unit_id = u.unit_id
  JOIN unit_hierarchy h ON cr.superior_unit_id = h.unit_id
  WHERE u.mission_id = $1
)
SELECT * FROM unit_hierarchy ORDER BY path;
```

### Pattern 4: Invite Token Generation
**What:** Secure, expiring invite tokens for mission participation
**When to use:** Generating shareable invite links/codes
**Example:**
```typescript
// Source: Security best practices research
import { randomBytes, createHash } from 'crypto';

interface InviteToken {
  token: string;          // Return to user
  hashedToken: string;    // Store in database
  expiresAt: Date;
}

function generateInviteToken(expirationHours: number = 72): InviteToken {
  // Generate cryptographically secure random token
  const token = randomBytes(32).toString('base64url');

  // Hash for database storage (SHA-256 sufficient for tokens)
  const hashedToken = createHash('sha256').update(token).digest('hex');

  // Set expiration
  const expiresAt = new Date();
  expiresAt.setHours(expiresAt.getHours() + expirationHours);

  return { token, hashedToken, expiresAt };
}

// Short code alternative (6 chars, alphanumeric)
function generateInviteCode(): string {
  const chars = 'ABCDEFGHJKLMNPQRSTUVWXYZ23456789'; // Avoid ambiguous: 0/O, 1/I/L
  let code = '';
  const bytes = randomBytes(6);
  for (let i = 0; i < 6; i++) {
    code += chars[bytes[i] % chars.length];
  }
  return code;
}
```

### Pattern 5: Real-time Position Updates with leaflet-realtime
**What:** Live position tracking with movement trails
**When to use:** Asset/personnel real-time tracking on maps
**Example:**
```typescript
// Source: leaflet-realtime GitHub documentation
import L from 'leaflet';
import 'leaflet-realtime';

// For push-based updates via WebSocket
const realtimeLayer = L.realtime(undefined, {
  start: false, // Don't auto-poll, we'll push updates
  getFeatureId: (feature) => feature.properties.assetId,
  pointToLayer: (feature, latlng) => {
    const marker = L.marker(latlng, {
      icon: createMilSymbolIcon(feature.properties.sidc)
    });
    return marker;
  },
});

realtimeLayer.addTo(map);

// Push updates from WebSocket
websocket.onmessage = (event) => {
  const geojson = JSON.parse(event.data);
  realtimeLayer.update(geojson);
};

// Handle enter/update/exit for trails
realtimeLayer.on('update', (e) => {
  Object.keys(e.enter).forEach((id) => {
    // New asset appeared - initialize trail
    trails[id] = L.polyline([], { color: 'blue', opacity: 0.5 });
    trails[id].addTo(map);
  });

  Object.keys(e.update).forEach((id) => {
    // Asset moved - extend trail
    const layer = e.update[id];
    const latlng = layer.getLatLng();
    trails[id].addLatLng(latlng);
  });

  Object.keys(e.exit).forEach((id) => {
    // Asset gone - optionally remove trail
    if (trails[id]) {
      map.removeLayer(trails[id]);
      delete trails[id];
    }
  });
});
```

### Anti-Patterns to Avoid
- **Hand-rolling org chart rendering:** Use react-organizational-chart, don't build SVG/CSS trees from scratch
- **Storing symbols as images:** milsymbol generates SVG on-demand, never pre-render to files
- **Nested set for command hierarchy:** Adjacency list with recursive CTEs is simpler and handles frequent updates better
- **Polling for real-time updates:** Use WebSocket push with leaflet-realtime's manual update() method
- **Plain text invite tokens:** Always hash tokens before database storage

## Don't Hand-Roll

Problems that look simple but have existing solutions:

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Military symbols | Custom SVG/icon set | milsymbol | 2525D compliance, 1000s of symbols, maintained |
| Org chart lines | Custom CSS/SVG paths | react-organizational-chart | Handles all edge cases, tree traversal, styling |
| Drag-drop trees | Custom drag handlers | react-complex-tree | Accessibility, keyboard nav, multi-select |
| CSV parsing | Custom parser | Papa Parse (via react-csv-importer) | Handles edge cases, streaming, malformed data |
| Invite tokens | Sequential IDs | crypto.randomBytes | Security - sequential IDs are guessable |
| Polygon drawing | Custom click handlers | react-leaflet-draw | Edit, delete, persist, mobile support |
| Heatmap rendering | Canvas gradient code | leaflet.heat or react-leaflet-heatmap-layer-v3 | Clustering, performance, gradient options |

**Key insight:** Military symbology and hierarchical visualization have decades of standards and edge cases. Libraries like milsymbol encode MIL-STD-2525D rules that would take months to implement correctly.

## Common Pitfalls

### Pitfall 1: Milsymbol SIDC String Format
**What goes wrong:** Invalid or incorrect Symbol Identification Codes produce blank/wrong symbols
**Why it happens:** MIL-STD-2525D SIDCs are 20+ character codes with specific meanings per position
**How to avoid:**
- Use milsymbol's symbol explorer at https://explorer.milsymb.net/
- Validate SIDCs against schema before rendering
- Store SIDC components separately, assemble on render
**Warning signs:** Blank markers, "?" symbols, wrong affiliation colors

### Pitfall 2: Circular Command Relationships
**What goes wrong:** A reports to B, B reports to A creates infinite loop
**Why it happens:** Users drag-drop without awareness of existing relationships
**How to avoid:**
- Validate on save: check for cycles using DFS/BFS
- Show advisory warnings (per CONTEXT.md decision)
- Allow override but log for audit
**Warning signs:** Browser freeze on hierarchy render, stack overflow errors

### Pitfall 3: Real-time Update Performance
**What goes wrong:** Map becomes sluggish with many moving markers
**Why it happens:** Re-rendering entire layer on each position update
**How to avoid:**
- Use leaflet-realtime's feature ID tracking (only updates changed markers)
- Limit trail length (keep last N points, not infinite)
- Use marker clustering for zoomed-out views
- Throttle WebSocket updates (100-500ms batching)
**Warning signs:** Growing memory usage, dropping frame rate, delayed updates

### Pitfall 4: Wizard State Loss on Navigation
**What goes wrong:** User hits browser back button, loses all wizard progress
**Why it happens:** React state doesn't persist across navigation
**How to avoid:**
- Use XState with persistence (localStorage or URL state)
- Show confirmation dialog on page leave
- Consider URL-based step tracking
**Warning signs:** User complaints about lost work, high wizard abandonment rate

### Pitfall 5: GeoJSON Polygon Validation
**What goes wrong:** Invalid polygons cause map errors or server crashes
**Why it happens:** User draws self-intersecting shapes, or data import has malformed coordinates
**How to avoid:**
- Validate GeoJSON on client with Turf.js `booleanValid`
- Validate again on server before storage
- Use Leaflet.draw's `allowIntersection: false` option
**Warning signs:** "Invalid coordinates" errors, map crashes, weird polygon rendering

### Pitfall 6: CSV Import Column Mismatch
**What goes wrong:** User maps columns incorrectly, data ends up in wrong fields
**Why it happens:** Similar column names, no validation, no preview
**How to avoid:**
- Use react-csv-importer's column mapping UI
- Show preview of first 5-10 rows after mapping
- Validate required fields before import
- Allow undo/rollback of bulk imports
**Warning signs:** Nonsensical data values, type errors, user confusion

### Org Chart with Custom Nodes
```typescript
// Source: react-organizational-chart documentation
import { Tree, TreeNode } from 'react-organizational-chart';

interface UnitNodeProps {
  name: string;
  sidc: string;
  relationship: string;
  isMultiHatted?: boolean;
  roles?: string[];
}

function UnitNode({ name, sidc, relationship, isMultiHatted, roles }: UnitNodeProps) {
  return (
    <div className={`unit-node ${isMultiHatted ? 'multi-hatted' : ''}`}>
      <div className="unit-symbol">
        <MilSymbolIcon sidc={sidc} size={24} />
      </div>
      <div className="unit-name">{name}</div>
      <div className="unit-relationship">{relationship}</div>
      {isMultiHatted && (
        <div className="role-badges">
          {roles?.map(role => (
            <span key={role} className="role-badge">{role}</span>
          ))}
        </div>
      )}
    </div>
  );
}

function CommandHierarchy({ units, relationships }: Props) {
  const rootUnit = units.find(u => !relationships.some(r => r.subordinateId === u.id));

  const renderTree = (unitId: string): JSX.Element => {
    const unit = units.find(u => u.id === unitId);
    const children = relationships
      .filter(r => r.superiorId === unitId)
      .map(r => units.find(u => u.id === r.subordinateId));

    return (
      <TreeNode
        key={unit.id}
        label={<UnitNode {...unit} />}
      >
        {children.map(child => renderTree(child.id))}
      </TreeNode>
    );
  };

  return (
    <Tree
      lineWidth="2px"
      lineColor="#4a9eff"
      lineBorderRadius="4px"
      label={<UnitNode {...rootUnit} />}
    >
      {relationships
        .filter(r => r.superiorId === rootUnit.id)
        .map(r => renderTree(r.subordinateId))}
    </Tree>
  );
}
```

### CSV Bulk Import with Validation
```typescript
// Source: react-csv-importer documentation
import { Importer, ImporterField } from 'react-csv-importer';
import 'react-csv-importer/dist/index.css';

interface ResourceRow {
  name: string;
  category: string;
  serialNumber?: string;
  status: 'FMC' | 'PMC' | 'NMC';
}

function ResourceImporter({ onImport }: { onImport: (rows: ResourceRow[]) => void }) {
  return (
    <Importer
      dataHandler={async (rows, { startIndex }) => {
        // Validate batch
        const validRows = rows.filter(row => {
          if (!row.name || !row.category) return false;
          if (!['FMC', 'PMC', 'NMC'].includes(row.status)) return false;
          return true;
        });

        // Process valid rows
        await onImport(validRows as ResourceRow[]);
      }}
      defaultNoHeader={false}
      restartable={true}
    >
      <ImporterField name="name" label="Resource Name" />
      <ImporterField name="category" label="Category" />
      <ImporterField name="serialNumber" label="Serial Number" optional />
      <ImporterField name="status" label="Status (FMC/PMC/NMC)" />
      <ImporterField name="location" label="Location" optional />
    </Importer>
  );
}
```

```typescript

import { setup, assign } from 'xstate';

const missionLifecycleMachine = setup({

          target: 'active',

          target: 'complete',

      on: {
        ARCHIVE: 'archived',
        REOPEN: 'active', // Optional: allow reopening

    },
    archived: {
      type: 'final', // No transitions out per CONTEXT.md (archive only, no delete)
    },
  },
```

## Open Questions

Things that couldn't be fully resolved:

1. **Sensor coverage gradient algorithms**
   - What we know: leaflet.heat provides gradient heatmaps, can customize colors
   - What's unclear: How to model detection probability curves for different sensor types
   - Recommendation: Start with simple circle/polygon coverage, add gradient as enhancement

2. **Personnel readiness definition configurability**
   - What we know: CONTEXT.md specifies readiness is "configurable by mission requirement and/or staff/Comd"
   - What's unclear: Exact data model for configurable readiness criteria
   - Recommendation: Store readiness as JSONB with schema validation, define base schema with extension points

3. **Resource relationship auto-inference**
   - What we know: CONTEXT.md wants auto-inference of weapon-ammo compatibility
   - What's unclear: What data sources exist for military equipment compatibility
   - Recommendation: Start with manual linking, research NATO STANAG equipment databases for future auto-inference

4. **OTH Gold/JREAP message format integration**
   - What we know: These are military data exchange standards
   - What's unclear: Implementation priority - needed for MVP or future phase?
   - Recommendation: Mark as future enhancement unless explicitly required for Phase 4.4
