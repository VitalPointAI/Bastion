<tasks>

<task type="auto">
  <name>Task 1: Create GitBook SUMMARY.md</name>
  <files>docs/whitepaper/SUMMARY.md</files>
  <action>
Create a SUMMARY.md file in docs/whitepaper/ that serves as the GitBook table of contents.

GitBooks uses SUMMARY.md to define the navigation structure. Format:

```markdown
# Summary

## Front Matter

* [Title Page](00-title-page.md)
* [Abstract](00-abstract.md)

## Main Content

* [Introduction](01-introduction.md)
* [Background](02-background-daos.md)
  * [DAOs and Web3](02-background-daos.md)
  * [Military Coordination](02-background-military.md)
  * [AI in Defense](02-background-ai.md)
* [Methodology](03-methodology.md)
* [Results](04-results.md)
* [Discussion](05-discussion.md)
* [Conclusion](06-conclusion.md)
* [References](07-references.md)

## Appendices

* [Appendix A: SITREP](appendix-a-sitrep.md)
* [Appendix B: Demo Script](appendix-b-demo-script.md)

## Meta

* [Assembly Instructions](ASSEMBLY.md)
```

Note: The nested structure under Background creates a collapsible section in GitBooks.
  </action>
  <verify>SUMMARY.md exists with all whitepaper sections linked in proper GitBook format</verify>
  <done>GitBook navigation structure defined</done>

<task type="auto">
  <name>Task 2: Create GitBook configuration</name>
  <files>.gitbook.yaml</files>
  <action>
Create .gitbook.yaml in the repository root to configure GitBooks.

```yaml
root: ./docs/whitepaper/

structure:
  readme: README.md
  summary: SUMMARY.md
```

This tells GitBooks:
- The documentation root is docs/whitepaper/
- Use README.md as the landing page
- Use SUMMARY.md for table of contents navigation

  <verify>.gitbook.yaml exists in repo root with correct paths</verify>
  <done>GitBook configuration ready</done>
</task>
