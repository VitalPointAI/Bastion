<task type="auto" tdd="true">
  <name>Task 2: Enhance mission_client.py with mDNS discovery, DID auth, message stamping, and bridge fallback</name>
  <files>robot/mission_client.py, robot/tests/test_mdns_fallback.py, robot/tests/test_mission_client.py</files>
  <behavior>
    - test_mdns_fallback_on_timeout: When browse_service returns empty list and BRIDGE_HOST is set, connect_and_run uses bridge URL
    - test_mdns_fallback_direct_when_no_bridge: When browse_service returns empty and no BRIDGE_HOST, connect directly to BASTION_WS_URL
    - test_registration_uses_token_first_time: When REGISTRATION_TOKEN is set and no DID, sends {type: "robot:register", token: ..., robot_id: ...}
    - test_registration_uses_did_subsequent: When DID is loaded from file, sends {type: "robot:register", did: ..., robot_id: ...}
    - test_outbound_messages_stamped: All sent messages pass through stamp() and contain message_id
  </behavior>
  <action>
    1. Update `robot/mission_client.py`:

    **mDNS discovery phase (before connect):**
    - Add `async discover_bridge() -> Optional[str]`:
      - Call `browse_service("_bastion._tcp.local.", timeout=cfg.MDNS_BROWSE_TIMEOUT_SEC)`.
      - If found, extract address and relay_port from TXT properties. Return `ws://{address}:{relay_port}/ws/robot`.
      - If not found and cfg.BRIDGE_HOST is set, return `ws://{cfg.BRIDGE_HOST}:{cfg.BRIDGE_PORT}/ws/robot`.
      - If neither, return None.

    **mDNS self-advertisement:**
    - Add `asyncio.create_task(advertise_service("_bastion-robot._tcp.local.", ...))` in run() to advertise robot. Include robot_id and capabilities in TXT records. Cancel on shutdown.

    **DID-based registration (replacing AUTH_TOKEN):**
    - In connect_and_run(), update registration logic:
      - Load DID: `did = cfg.load_persisted_did() or cfg.ROBOT_DID`.
      - If no DID and REGISTRATION_TOKEN is set: send `{type: "robot:register", robot_id: cfg.ROBOT_ID, token: cfg.REGISTRATION_TOKEN, capabilities: [...]}`.
      - If DID exists: send `{type: "robot:register", robot_id: cfg.ROBOT_ID, did: did, capabilities: [...]}`.
      - If neither token nor DID: fall back to legacy `auth_token` if AUTH_TOKEN is set.
      - After registration, listen for `robot:registered` response containing DID. Call `cfg.persist_did(did)` to save.

    **Message stamping:**
    - Replace all `_ws_send(ws, msg.model_dump(mode="json"))` calls with `send_stamped(ws, msg.model_dump(mode="json"))` from common.ws_protocol.
    - Import `from common.ws_protocol import send_stamped, stamp`.

    **Dual-path connectivity:**
    - In run(), after discover_bridge():
      - Primary: connect_and_run() to cfg.BASTION_WS_URL (direct cloud).
      - On disconnect (ConnectionClosed or 5s heartbeat miss), if bridge_url is known, switch to bridge_url as the active connection.
      - Track `active_path: str = "direct" | "bridge"`.
      - On bridge disconnect, attempt direct again.
      - This is a simple failover — not simultaneous dual connections. Robot connects to ONE path at a time, switches on failure.

    2. Write tests:
    - `robot/tests/test_mdns_fallback.py`: Mock browse_service to return empty, verify fallback to BRIDGE_HOST. Mock to return a ServiceResult, verify extracted URL.
    - `robot/tests/test_mission_client.py`: Mock websockets.connect, test registration message content (token vs DID), test that sent messages contain message_id.
