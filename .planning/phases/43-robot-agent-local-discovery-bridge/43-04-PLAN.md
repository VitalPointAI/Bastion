<objective>
Build the complete bridge service as a standalone Python asyncio application. The bridge connects to Bastion cloud via outbound WebSocket, scans the LAN for devices (mDNS + SSDP), relays scan results to cloud, accepts local robot WebSocket connections, proxies robot messages to cloud, and queues commands for offline robots.

Purpose: The bridge is the core new component of Phase 43 -- it extends Bastion's reach to the local network, provides device discovery, and acts as a resilient relay for robots.
Output: Complete `bridge/` directory with all core modules, config, tests, and requirements.
</objective>

    1. Create `bridge/bridge_ws.py`:
       - `async bridge_cloud_loop(cfg, relay, scanner, queue: CommandQueue) -> None`:
         - Connect to `{cfg.CLOUD_WS_URL}/ws/bridge` via websockets.connect().
         - On connect, register: If DID exists, send `{type: "bridge:register", bridge_id: cfg.BRIDGE_ID, did: cfg.BRIDGE_DID}`. If token, send `{type: "bridge:register", bridge_id: cfg.BRIDGE_ID, token: cfg.REGISTRATION_TOKEN}`.
         - Listen for `bridge:registered` response -- persist DID via cfg.persist_did().
         - Run two concurrent tasks:
           a. `_receive_loop(ws, queue, relay)`: Receive cloud messages. Route `mission:assign` to relay if robot is locally connected, otherwise enqueue in command_queue. Handle other message types.
           b. `_scan_report_loop(ws, scanner, interval)`: Every cfg.SCAN_INTERVAL_SEC, run scanner.run_full_scan(), send results as `bridge:discovery_report` via send_stamped().
         - On disconnect, exponential backoff reconnect (same pattern as robot/mission_client.py).
       - `async _relay_robot_message(ws, robot_msg: dict) -> None`: Forward robot message to cloud with `{type: "bridge:robot_relay", bridge_id, robot_message: robot_msg, message_id: robot_msg.get("message_id")}`. Do NOT re-stamp -- preserve original message_id so cloud-side dedup works correctly.

    2. Create `bridge/bridge_relay.py`:
       - `async robot_relay_server(cfg, cloud_ws_ref, queue: CommandQueue, shutdown: asyncio.Event) -> None`:
         - Start websockets.serve() on `0.0.0.0:{cfg.RELAY_PORT}`.
         - On robot connect: track in `connected_robots: dict[str, WebSocket]`.
         - On robot message:
           - If `type == "robot:register"`: Track robot_id. Drain queued commands for this robot. Send each non-expired command.
           - For all messages: forward to cloud via cloud_ws_ref using `_relay_robot_message`.
         - On robot disconnect: remove from connected_robots.
       - `is_robot_connected(robot_id: str) -> bool`: Check connected_robots map.
       - `send_to_robot(robot_id: str, msg: dict) -> bool`: Send to locally connected robot if present. Return True if sent.

    3. Create `bridge/mdns_advertise.py`:
       - `async advertise_bridge(cfg, shutdown: asyncio.Event) -> None`:
         - Import advertise_service from robot.common.mdns (copy the function if importing across packages is problematic).
         - Register `_bastion._tcp.local.` with name=`{cfg.BRIDGE_ID}._bastion._tcp.local.`, port=cfg.RELAY_PORT, properties={bridge_id: cfg.BRIDGE_ID, cloud_url: cfg.CLOUD_WS_URL, version: "1.0", relay_port: str(cfg.RELAY_PORT)}.
         - Also browse for `_bastion-robot._tcp.local.` to discover robots. On discovery, log and optionally initiate connection.
         - Await shutdown event, then unregister.

    4. Create `bridge/bridge_main.py`:

           c. `advertise_bridge(cfg, shutdown)` -- mDNS advertisement + robot browsing
           d. `queue.cleanup_loop(60, shutdown)` -- periodic command queue cleanup

         - `asyncio.run(main())` at bottom.
