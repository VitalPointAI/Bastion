  <action>
Create `backend/src/api/workspaces.ts` as an Express Router following the pattern in `backend/src/api/missions.ts`.

Import requireAuth from `../auth/auth-instance.js`, all workspace stores, signAndSubmitFunctionCall and deriveUserSecretFromAccount from `../near/tx-signer.js`, clearanceSufficient from `../workspace/types.js`.

Use `zod` for input validation (import z from 'zod').

**Validation Schemas:**
```typescript
const CreateWorkspaceSchema = z.object({
  name: z.string().min(2).max(100),
  description: z.string().max(500).optional(),
  workspaceType: z.enum(['Organization', 'Unit', 'Team']),
  classification: z.enum(['UNCLASSIFIED', 'SECRET', 'TOPSECRET']).default('UNCLASSIFIED'),
  parentWorkspaceId: z.string().optional(),
  inviteMode: z.enum(['open', 'gated']).default('gated'),
  discoverability: z.enum(['discoverable', 'private']).default('private'),
});

const CreateInviteSchema = z.object({
  role: z.string().min(1),
  daoRole: z.string().default('member'),
  inviteeEmail: z.string().email().optional(),
  inviteeDid: z.string().optional(),
  expiresInHours: z.number().min(1).max(720).default(72),
});

const UpdateRoleSchema = z.object({
  newRole: z.string().min(1),
  newDaoRole: z.string().min(1),
});
```

**Endpoints (all require requireAuth middleware):**

1. `POST /` — Create workspace
   - Parse body with CreateWorkspaceSchema
   - If parentWorkspaceId, look up parent to get parentDaoId and validate hierarchy depth (max 3 levels)
   - Call `workspaceStore.createWorkspace(input, userDid)` for off-chain record
   - Call `signAndSubmitFunctionCall` for `create_dao` on-chain with the generated daoId
   - If parentDaoId, call `signAndSubmitFunctionCall` for `set_dao_parent`
   - Call `workspaceRoleStore.initRolesForWorkspace(workspace.id, input.workspaceType)` to create military templates
   - Add creator as member: `workspaceMemberStore.addMember(workspace.id, userDid, 'commander', 'council', userDid)`
   - Log activity: `workspaceActivityStore.log(workspace.id, 'workspace_created', userDid, null, { txHash })`
   - Return 201 with workspace object

2. `GET /me` — List user's workspace memberships
   - `workspaceMemberStore.listMemberships(userDid)`
   - For each membership, enrich with workspace name/type from `workspaceStore.getWorkspace`
   - Return enriched memberships array

3. `GET /:id` — Get workspace details
   - `workspaceStore.getWorkspace(req.params.id)`
   - Return 404 if not found
   - Verify caller is a member (check `workspaceMemberStore.getMember`)
   - Return workspace with member count

4. `GET /:id/hierarchy` — Get workspace hierarchy tree
   - `workspaceStore.getHierarchy(req.params.id)`
   - Enrich each workspace with member count
   - Return hierarchy array

5. `PATCH /:id` — Update workspace settings
   - Verify caller has 'manage_workspace' permission (check role via member store + role store)
   - Update name, description, inviteMode, discoverability
   - Log activity

6. `GET /:id/members` — List workspace members
   - `workspaceMemberStore.listMembers(req.params.id)`

7. `POST /:id/members/:memberDid/role` — Change member role
   - Parse body with UpdateRoleSchema
   - Verify caller has 'manage_roles' permission
   - Verify caller's role level >= target member's new role level (delegate up to own level)
   - Call `signAndSubmitFunctionCall` for `assign_role` on-chain
   - Call `workspaceMemberStore.updateRole` off-chain
   - Log activity with old/new role in metadata

8. `POST /:id/members/:memberDid/suspend` — Suspend member
   - Verify caller has 'manage_members' permission
   - `workspaceMemberStore.suspendMember`
   - Log activity

9. `POST /:id/members/:memberDid/unsuspend` — Unsuspend member
   - Verify caller has 'manage_members' permission
   - `workspaceMemberStore.unsuspendMember`
   - Log activity with 'member_unsuspended' type

10. `DELETE /:id/members/:memberDid` — Remove member
   - Verify caller has 'manage_members' permission
   - Call `signAndSubmitFunctionCall` for `remove_member` on-chain
   - `workspaceMemberStore.removeMember` off-chain
   - Log activity

11. `POST /:id/invite` — Create invite
    - Parse body with CreateInviteSchema
    - Verify caller has 'manage_members' permission
    - `workspaceInviteStore.createInvite`
    - Log activity
    - Return 201 with invite + rawToken

12. `GET /:id/invites` — List pending invites
    - `workspaceInviteStore.listPendingInvites`

13. `POST /invite/accept` — Accept invite (body: { token: string })
    - `workspaceInviteStore.getInviteByToken(token)`
    - Return 404 if not found
    - Verify invitee matches (if targeted)
    - Clearance gate: fetch user profile, check `clearanceSufficient(userClearance, workspace.classification)`
    - Gated mode: if workspace.inviteMode === 'gated' and !invite.approvedAt, return 202 (pending approval)
    - On-chain: `signAndSubmitFunctionCall` for `add_member`
    - Off-chain: `workspaceMemberStore.addMember`
    - Mark invite accepted
    - Log activity
    - Return 200 with member

14. `POST /:id/invites/:inviteId/approve` — Approve gated invite
    - Verify caller has 'manage_members' permission
    - `workspaceInviteStore.markApproved`
    - Log activity

15. `DELETE /:id/invites/:inviteId` — Cancel invite
    - Verify caller has 'manage_members' permission
    - `workspaceInviteStore.cancelInvite`

16. `PUT /me/primary` — Set primary workspace (body: { workspaceId: string })
    - `workspaceMemberStore.setPrimary(userDid, body.workspaceId)`

17. `GET /:id/roles` — List workspace roles
    - `workspaceRoleStore.getRolesForWorkspace`

18. `GET /:id/activity` — List workspace activity
    - `workspaceActivityStore.listActivities` with optional query params (limit, offset, types)

19. `POST /notifications/counts` — Get unread counts (body: { lastSeenMap: Record<string, string> })
    - `workspaceActivityStore.getUnreadCountsForUser(userDid, body.lastSeenMap)`

**AI agent membership (locked decision):** All membership endpoints (addMember, invite accept, role change) accept agent DIDs identically to human DIDs. When assigning a role, check the role's `max_agent_tier` from `backend/src/dao/types.ts` — if the DID belongs to an AI agent (detected via agent registry or DID metadata) and the agent's tier exceeds the role's `max_agent_tier`, reject with 403. Agent DIDs flow through the same invite and accept paths as human DIDs.

**Error handling:** Wrap each handler in try/catch. Return appropriate HTTP codes (400 for validation, 401 for auth, 403 for permission, 404 for not found, 500 for server error). Use `error instanceof z.ZodError` for validation errors.

**Permission check helper:** Create a private `checkPermission(workspaceId: string, userDid: string, permission: string)` function that looks up the member's role, then the role's permissions from the role store, and throws 403 if the permission is not present.

Export default router.
