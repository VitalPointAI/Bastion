Interface:
```typescript
interface WorkspaceContextType {
  // State
  activeWorkspaceId: string | null;
  memberships: WorkspaceMembership[];
  activeWorkspace: WorkspaceDetail | null;
  userRoleInActive: string | null;
  primaryWorkspaceId: string | null;
  notificationCounts: Record<string, number>;
  loading: boolean;

  // Actions
  setActiveWorkspace: (id: string) => void;
  refreshMemberships: () => Promise<void>;
  refreshActiveWorkspace: () => Promise<void>;
}
```

Provider logic:
1. On mount (when isAuthenticated + userDID), fetch memberships via `workspaceService.listMyMemberships()`.
2. Derive `primaryWorkspaceId` from memberships (find isPrimary === true).
3. If no activeWorkspaceId set, default to primaryWorkspaceId (or first membership).
4. When `activeWorkspaceId` changes, fetch full workspace details via `workspaceService.getWorkspace(id)`.
5. Derive `userRoleInActive` from memberships array.
6. Notification polling: Set up 5-second interval that calls `workspaceService.getNotificationCounts(lastSeenMap)`. Store `lastSeenMap` in localStorage with key `workspace-last-seen`. Update localStorage on workspace switch (set current time for the workspace being left).
7. Visibility change handler: pause polling when tab hidden, restart on visible.
8. `setActiveWorkspace(id)`: Update state, save to localStorage for persistence across refresh. Update lastSeenMap for previous workspace.
9. `refreshMemberships()`: Re-fetch memberships (called after joining/leaving workspace).
10. `refreshActiveWorkspace()`: Re-fetch active workspace details (called after workspace updates).

Export: `export const useWorkspace = () => useContext(WorkspaceContext);`
Export: `export function WorkspaceProvider({ children }: { children: ReactNode })`

DO NOT integrate into App.tsx yet (that happens in Plan 19-05 when the UI components are ready).
