# Phase 4.5: ATAK/CoT Tactical Interoperability - Context

**Gathered:** 2026-01-25
**Status:** Ready for planning

<domain>
## Phase Boundary

Enable real-time data exchange between BASTION web platform and ATAK/TAK Server tactical systems. Field personnel with ATAK devices share position and mission data with BASTION; BASTION pushes objectives, overlays, and sensor data back to field devices. WebTAK browser-based access included.

</domain>

<decisions>
## Implementation Decisions

### Connection Model
- Support both FreeTAKServer (dev/demo) and official TAK Server (production) via config-based switching
- Authentication method configurable per server: certificates (p12) for official TAK, username/password for FreeTAKServer
- Connection mode configurable per mission: always-on persistent TCP/TLS for active operations, on-demand for planning phases
- Admin configures connection parameters in mission settings

### Data Flow & Mapping
- BASTION → ATAK: Configurable per entity type (admin controls which entities sync)
- ATAK → BASTION: Configurable per CoT type (admin sets filters for ingestion)
- Source of truth: ATAK authoritative for positions (field devices know real-time location), BASTION authoritative for everything else (mission data, objectives, resources)
- Entity mapping uses standard MIL-STD-2525D CoT types only (no custom types requiring ATAK plugins)

### Real-Time Behavior
- Update frequency configurable per entity (high-value assets update frequently, others on change)
- Subscription filters configurable: by callsign, group, geography, or CoT type
- UI shows real-time map markers plus toast notifications for new/changed entities
- Full position track history stored (all updates retained for movement replay and pattern analysis)

### Offline/DDIL Handling
- Queue outbound messages during disconnection (cache locally, send on reconnect - no lost updates)
- Stale ATAK data displayed with visual 'stale' warning indicator (preserves SA while showing data age)
- Reconnection sync strategy configurable by admin (full sync, delta sync, or push-queued-only based on bandwidth)
- Data package export: full .zip packages with KML overlays, markers, and imagery for fully offline ATAK field use

### Claude's Discretion
- Multi-TAK-Server connection handling (single vs simultaneous based on technical constraints)
- WebSocket implementation details and error handling
- Stale threshold timing (how long before showing stale indicator)
- Queue size limits and overflow handling
- Data package format specifics and optional contents

</decisions>

<specifics>
## Specific Ideas

- FreeTAKServer for development/demos lowers barrier to entry
- Standard MIL-STD-2525D ensures interoperability with any ATAK installation without custom plugins
- Full track history enables post-mission analysis and pattern recognition
- Data packages enable true DDIL operation when connectivity is unavailable

</specifics>
