<objective>
Fix Stadia Maps tile 404 errors in ValidityMap and MissionMap caused by two diagnosed root causes:

1. Leaflet noWrap bug (GitHub issues #4646, #7181): noWrap={true} on TileLayer does NOT prevent out-of-bounds tile requests. At zoom 2, valid x tile range is 0-3 but Leaflet requests x=5. Adding bounds={[[-85,-180],[85,180]]} to TileLayer clips tile coordinate calculations to valid world bounds, preventing these bad requests.

2. Stadia Maps returns 401 for non-localhost origins without an API key. Support optional VITE_STADIA_MAPS_API_KEY env var so the tile URL works in non-localhost deployments.

Purpose: Unblock UAT test 2 (Strategic Validity Dashboard map view) and test 3 (Map View Renders).
Output: Both map components load tiles correctly at all zoom levels, with optional API key support for non-localhost deployments.
</objective>

**Step 2 — Update TileLayer in each file.**

Replace the current TileLayer:
```tsx
<TileLayer
  attribution='...'
  url="https://tiles.stadiamaps.com/tiles/alidade_smooth_dark/{z}/{x}/{y}{r}.png"
  maxZoom={18}
  noWrap={true}
/>
```

With:
```tsx
<TileLayer

  maxZoom={18}
  noWrap={true}

```

The `bounds` prop is the actual fix for Leaflet issue #4646/#7181. It clamps tile coordinate calculation to world bounds, preventing x=5 requests at zoom 2. The `noWrap` prop alone does not do this.
