Create comprehensive type definitions for the operational planning domain following patterns from mission/types.ts:

**backend/src/planning/types.ts:**

1. **OperationalPlan** interface:
   - id: string (OPLAN- prefix)
   - missionId: string (links to mission workspace)
   - objectiveIds: string[] (links to strategic objectives - required, minimum 1)
   - name: string
   - classification: Classification
   - planType: 'OPLAN' | 'OPORD' | 'CONPLAN' | 'FRAGORD'
   - step: JP50Step (current workflow step)
   - stepStatuses: Record<JP50Step, StepStatus> (track each step's status)
   - commanderApproval: { coaApproved: boolean; planApproved: boolean; coaApprovedAt?: Date; planApprovedAt?: Date; coaApprovedBy?: string; planApprovedBy?: string }
   - situation: SituationParagraph
   - mission: MissionStatement
   - execution: ExecutionParagraph (populated during COA selection)
   - sustainment: SustainmentParagraph
   - commandSignal: CommandSignalParagraph
   - annexes: Record<AnnexLetter, Annex>
   - yjsDocumentId: string (for Yjs collaboration)
   - createdBy: string (DID)
   - createdAt: Date
   - updatedAt: Date

2. **JP50Step** enum: 'planning_initiation' | 'mission_analysis' | 'coa_development' | 'coa_analysis' | 'coa_comparison' | 'coa_approval' | 'plan_development' | 'plan_approval'

3. **StepStatus**: 'not_started' | 'in_progress' | 'ready' | 'approved' | 'rejected'

4. **COA** interface:
   - id: string (COA- prefix)
   - planId: string
   - number: number (COA 1, 2, 3...)
   - name: string
   - description: string
   - scheme: string (scheme of maneuver)
   - commandersIntent: CommandersIntent
   - tasks: SubordinateTask[]
   - risks: RiskAssessment[]
   - supportingEfforts: string[]
   - decisiveOperation: string
   - shaping: string
   - sustainingOperations: string
   - redTeamResults?: RedTeamResult (populated by Red Team agent)
   - comparisonScore?: COAComparisonScore (populated by Comparator agent)
   - selected: boolean
   - createdBy: string
   - createdAt: Date
   - updatedAt: Date

5. **RedTeamResult** interface:
   - adversaryActions: string[]
   - vulnerabilities: string[]
   - counterActions: string[]
   - outcomeAssessment: string
   - confidenceScore: number (0-100)
   - simulatedAt: Date
   - agentId: string

6. **COAComparisonScore** interface:
   - feasibility: { score: number; rationale: string }
   - acceptability: { score: number; rationale: string }
   - suitability: { score: number; rationale: string }
   - distinguishability: { score: number; rationale: string }
   - completeness: { score: number; rationale: string }
   - overallScore: number
   - ranking: number
   - comparedAt: Date
   - agentId: string

7. **ROERule** interface (for json-rules-engine):
   - id: string (ROE- prefix)
   - missionId: string
   - name: string
   - description: string
   - category: 'weapons' | 'targets' | 'force' | 'procedures' | 'special'
   - conditions: JSONRulesEngineCondition
   - event: { type: 'roe-violation' | 'roe-warning'; params: { severity: string; message: string; overrideAuthority: string; citation: string } }
   - active: boolean
   - createdBy: string
   - createdAt: Date
   - updatedAt: Date

8. **ROEOverride** interface:
   - id: string
   - planId: string
   - ruleId: string
   - actionContext: Record<string, unknown>
   - violations: string[]
   - justification: string (required - must document why override)
   - commanderDID: string
   - approvedAt: Date
   - blockchainTxHash: string (for immutable audit)

9. **PlanVersion** interface:
   - id: string
   - planId: string
   - version: number
   - yjsUpdate: Buffer (Yjs state snapshot)
   - snapshot: OperationalPlan
   - changedBy: string
   - changedAt: Date
   - changeReason?: string

10. **5-paragraph order types:**
    - SituationParagraph: { areaOfInterest, areaOfOperations, enemyForces, friendlyForces, civilConsiderations, attachmentsDetachments }
    - MissionStatement: { who, what, when, where, why }
    - ExecutionParagraph: { commandersIntent, conceptOfOperations, tasks, coordinatingInstructions, fires, riskMitigation }
    - SustainmentParagraph: { logistics, personnel, publicAffairs, civilAffairs, healthServiceSupport }
    - CommandSignalParagraph: { commandPost, succession, signal, codewords }

11. **AnnexLetter** enum: 'A' through 'Z' for standard annexes

```typescript
class PlanStore {
  private initialized = false;

  async ensureInitialized() {
    if (this.initialized) return;
    // Create operational_plans table with JSONB for complex structures
    // Columns: id, mission_id, objective_ids (TEXT[]), name, classification,
    // plan_type, step, step_statuses (JSONB), commander_approval (JSONB),
    // situation (JSONB), mission_statement (JSONB), execution (JSONB),
    // sustainment (JSONB), command_signal (JSONB), annexes (JSONB),
    // yjs_document_id, created_by, created_at, updated_at
    this.initialized = true;
  }

  async create(plan: CreateOperationalPlanInput): Promise<OperationalPlan>
  async findById(id: string): Promise<OperationalPlan | null>
  async findByMission(missionId: string): Promise<OperationalPlan[]>
  async findByObjective(objectiveId: string): Promise<OperationalPlan[]>
  async update(id: string, updates: UpdateOperationalPlanInput): Promise<OperationalPlan>
  async updateStep(id: string, step: JP50Step, status: StepStatus): Promise<OperationalPlan>
  async recordCOAApproval(id: string, commanderDID: string): Promise<OperationalPlan>
  async recordPlanApproval(id: string, commanderDID: string): Promise<OperationalPlan>
  async delete(id: string): Promise<void>
}

export const planStore = new PlanStore();
```
