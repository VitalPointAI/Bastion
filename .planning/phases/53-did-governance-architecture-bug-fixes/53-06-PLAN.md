    Create `backend/src/decisions/decision-dao-bridge.ts`:

    ```typescript
    /**
     * Decision-DAO Bridge — Phase 53
     *
     * Bridges the decision system with on-chain DAO proposals.
     * Every decision is recorded on-chain as an encrypted DAO proposal.
     * Voting membership determined by RACI matrix (single authority for
     * Commander-only decisions, multi-member for staff escalation).
     */

    export class DecisionDAOBridge {
      /**
       * Create a DAO proposal for a decision.
       * Encrypts the decision payload before on-chain storage.
       * Returns the proposal ID to link back to the decision.
       */
      async createProposalForDecision(
        decision: Decision,
        raciAssignments: RACIAssignment[],
        daoId: string,
      ): Promise<number | null>;

      /**
       * Determine voting membership based on RACI.
       * - If only Commander is R/A: single-signer proposal
       * - If multiple positions are R/A: multi-member vote
       * Returns list of NEAR account IDs that should vote.
       */
      private determineVoters(raciAssignments: RACIAssignment[]): string[];

      /**
       * Encrypt decision payload for on-chain storage.
       * Uses the same encryption service as DID documents.
       */
      private async encryptDecisionPayload(decision: Decision): Promise<Uint8Array>;

      /**
       * Check proposal status and sync back to decision.
       * Called periodically or on DAO event to update decision status
       * based on proposal voting outcome.
       */
      async syncProposalStatus(
        decisionId: string,
        daoId: string,
        proposalId: number,
      ): Promise<void>;
    }

    export const decisionDAOBridge = new DecisionDAOBridge();
    ```

    Implementation details:
    - `createProposalForDecision`:
      1. Encrypt decision payload (title, description, context_json, decision_type) using `encryptDIDDocument` or similar encryption utility
      2. Determine voters from RACI (R and A roles get voting rights)
      3. Create proposal via DAO service (use existing `daoService` patterns from gate-service.ts as reference)
      4. Return proposal ID
      5. If DAO creation fails (blockchain unavailable), log warning and return null — decision continues in PostgreSQL, on-chain recording retried later

    - `determineVoters`:
      1. Filter RACI assignments to R and A roles
      2. Map positions to NEAR account IDs (query problem set members by position)
      3. If only one voter (Commander decision): single-signer mode
      4. If multiple voters: multi-member mode

    - `encryptDecisionPayload`:
      1. Serialize decision to JSON
      2. Use encryption key derived from problem set or DAO key
      3. Return encrypted bytes
      4. Follow same pattern as `encryptDIDDocument()` from `identity/did-encryption.ts`

    - `syncProposalStatus`:
      1. Query proposal from DAO service
      2. If approved on-chain: update decision status to 'approved'
      3. If rejected on-chain: update decision status to 'rejected'
      4. Link via `decisionStore.linkDaoProposal()`
