# Phase 4.1: Admin UI - Context

**Gathered:** 2026-01-19
**Status:** Ready for planning

<vision>
## How This Should Work

When an admin opens the Admin UI, they land on an overview dashboard showing system status at a glance — what's healthy, what needs attention, and an activity feed of what's happening in real-time (agent runs, document processing, API calls).

From there, they can navigate to:
- **Configuration** — Set up and manage LLM providers, OSINT sources, API keys, and system preferences
- **User/Role Management** — Control who can access the system and what permissions they have
- **System Monitoring** — Deeper view into operational metrics, agent status, and system health

The experience should feel like a proper command-grade admin console, not just a settings page tucked away in a corner. It's the control room for the entire BASTION system.

</vision>

<essential>
## What Must Be Nailed

- **LLM/OSINT Configuration** — Easy setup and switching of AI providers and intelligence sources
- **System Visibility** — Know at a glance if things are working and what's happening
- **Access Control** — Manage who can do what in the system

All three are equally critical. Can't ship without all three working well.

</essential>

<boundaries>
## What's Out of Scope

- Scope kept flexible for now — will define boundaries as implementation progresses
- End-user features naturally excluded (this is admin-only territory)

</boundaries>

<specifics>
## Specific Ideas

- Match the existing command-center aesthetic — dark theme, tactical feel
- Consistent with the main BASTION interface (Phase 3 established the visual language)
- Overview dashboard + activity feed as the landing experience
- Configuration is a core pillar, not an afterthought

</specifics>

<notes>
## Additional Context

This phase was inserted after Phase 4 to provide administrative control over the system configuration that Phase 4 introduced (LLM providers, OSINT sources, etc.). The backend APIs for configuration already exist from Phase 4 Plan 7 — this phase builds the frontend to manage them.

Key backend infrastructure already in place:
- Admin config API with ADMIN_DIDS access control
- API key masking and encryption for sensitive fields
- Config audit trail logging

</notes>
