## Issues Fixed

### UAT-001: X-DID Header Not Sent (Major)

**Problem:** AdminDashboard called `adminService.isAdmin()` without setting the user's DID first, so the X-DID header was never sent to the backend. Users in ADMIN_DIDS were denied access because the backend couldn't identify them.

**Solution:** Created a UserContext to provide user identity across the app, consumed by AdminDashboard to pass DID to the admin service.

**Changes:**
- Created `frontend/src/context/UserContext.tsx` with UserProvider and useUser hook
- Modified AuthWrapper to wrap children with UserProvider, passing account state
- Updated AdminDashboard to consume userDID from context and call `adminService.setUserDID()` before checking admin access
- Added dependency on userDID to useEffect to re-check when DID becomes available

**Commit:** `42a01fb` - fix(4.1-01): pass user DID to AdminDashboard via UserContext

### UAT-002: User Info Wastes Screen Space (Minor)

**Problem:** User login info was displayed as a large block in the main content area, pushing actual content down and wasting valuable screen real estate.

**Solution:** Created a compact UserStatusBar component for the header and restructured the app layout.

**Changes:**
- Created `frontend/src/components/UserStatusBar.tsx` with compact user display
  - Shows avatar (initials), truncated name, and connected indicator
  - Click reveals dropdown with full account details (account ID, DID status, MPC recovery)
- Created `frontend/src/components/UserStatusBar.css` with dark theme styling
- Restructured App.tsx so AuthWrapper wraps entire app (enables UserStatusBar to access UserContext)
- Simplified AuthWrapper to render children directly with status overlay for account creation
- Updated header to use CSS Grid layout (logo | nav | user status)
- Reduced header padding for more compact appearance

**Commit:** `32ea3e9` - fix(4.1-01): move user info to header with UserStatusBar

## Architectural Changes

### UserContext Pattern

Introduced React Context for user identity propagation:

```
AuthWrapper (UserProvider)
  └── App
      ├── Header
      │   └── UserStatusBar (useUser)
      └── Main
          └── AdminDashboard (useUser)
```

This pattern allows any component within the app tree to access user identity without prop drilling.

### App Structure Refactor

Before:
```
App
  └── header
  └── main
      └── AuthWrapper
          └── content
```

After:
```
AuthWrapper (provides UserContext)
  └── App
      └── header (now has UserStatusBar)
      └── main
          └── content
```
