**ContainerSelector.tsx** — Multi-select dropdown with grouped containers:
- Props: `{ environmentId: string; selectedContainerIds: string[]; onChange: (ids: string[]) => void; suggestedContainerIds?: string[]; onContainerCreated?: () => void }`.
- On mount: fetch `strategicService.getContainersGrouped(environmentId)` to get categories and containers.
- Renders as a custom dropdown (button + floating panel, NOT native select):
  - Button shows selected count ("3 containers selected") or "No containers (Unorganized)" when empty.
  - Dropdown panel groups containers under category headers with ActorCategoryBadge.
  - Each container is a checkbox row: [x] Container Name (doc count).
  - Suggested containers (from AI) have a subtle highlight/star icon and appear at the top of their category.
  - At the bottom of each category group: "+ New container" link.
- **Inline container creation**: Clicking "+ New container" expands an inline form within the dropdown: name input + the category is pre-selected (the category this link is under). Submit creates via `strategicService.createContainer(...)`, auto-selects the new container, and calls `onContainerCreated` to refresh parent data.
- Keyboard accessible: Tab to navigate, Space/Enter to toggle, Escape to close dropdown.
- Click outside closes dropdown.
- Optional prop: if no environmentId provided, component renders disabled state.

- Add `ContainerSelector` below the classification dropdown field.

- After successful upload (when `onUploadComplete` fires with the new document), call `strategicService.assignDocumentToContainers(doc.id, containerIds)` if containerIds is non-empty.
- Container assignment happens AFTER upload completes (non-blocking to upload itself).

- Approach: DocumentUpload resolves environmentId on mount via `strategicService.getEnvironmentByProblemSet(problemSetId)` and passes it to ContainerSelector. Cache the environmentId in state.

**backend/src/strategic/containers/store.ts** — Add `suggestContainers` method:
- `async suggestContainers(documentId: string, environmentId: string): Promise<ContainerSuggestion[]>`
- Fetch the document's text_content (first 3000 chars) from strategic_documents table.
- Fetch all containers for the environment via `getContainersGroupedByCategory(environmentId)`.
- Build a prompt asking the LLM to analyze the document text and suggest which existing containers it belongs to. The prompt should include:
  - List of existing containers with their names and categories
  - First 3000 chars of document text
  - Instructions to return JSON array of `{ containerName, containerId, confidence (0-1), reasoning }` for matches above 0.5 confidence
  - Also suggest a new container if none fit well: `{ newContainerName, suggestedCategory, reasoning }`
- Use the existing LLM provider pattern from extraction service. Import the chat/completion function used in extraction (check `backend/src/strategic/extraction/` for the pattern — likely uses `configService.getActiveProvider()` or similar).
- Parse the JSON response. Return ContainerSuggestion[].
- If LLM call fails, return empty array (non-blocking).

**backend/src/api/strategic.ts** — Add suggestion route:
- `POST /api/strategic/documents/:documentId/suggest-containers` — Body: `{ environmentId }`. Calls `containerStore.suggestContainers(documentId, environmentId)`. Returns `{ suggestions: ContainerSuggestion[] }`.
- This is called AFTER text extraction completes, not during upload.

**frontend/src/lib/strategic-service.ts** — Add method (if not already present from Plan 01 scope, which it isn't):
- `suggestContainers(documentId: string, environmentId: string): Promise<ContainerSuggestion[]>` — POST to `/api/strategic/documents/:documentId/suggest-containers` with `{ environmentId }`.

**frontend/src/components/strategic/ContainerSelector.tsx** — Add suggestion support:
- New prop: `documentId?: string` — When provided AND the document has completed extraction (check via strategicService or a passed flag), call `strategicService.suggestContainers(documentId, environmentId)` on mount.
- While suggestions are loading, show a small "AI analyzing..." indicator in the dropdown.
- When suggestions arrive, highlight suggested containers with a star icon and "AI suggested" tooltip.
- Auto-check suggested containers with confidence > 0.7 (but user can uncheck).
- If suggestion includes a new container recommendation, show it as a special "Create: {name}" option at the top of the relevant category.
- Suggestions are purely advisory — user has full override control.

Note: The AI suggestion flow works best AFTER extraction (when text is available). During initial upload, suggestions won't fire until the document is re-opened. This is by design per RESEARCH.md pitfall #4 — don't block upload with AI inference.
