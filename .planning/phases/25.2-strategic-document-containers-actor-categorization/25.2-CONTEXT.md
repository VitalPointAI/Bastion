# Phase 25.2: Strategic Document Containers & Actor Categorization - Context

**Gathered:** 2026-03-06
**Status:** Ready for planning

<domain>
## Phase Boundary

Organize strategic documents into persistent nation/group containers with actor categorization, enabling incremental construction of strategic environments. Containers are shared across problem sets at a strategic environment level. Feeds into Phase 26 inheritance. Does NOT include full strategic environment inheritance, scheduled agent pipelines, or new AI agent capabilities beyond container-level assignment.

</domain>

<decisions>
## Implementation Decisions

### Container Organization
- Two-level model: actor category (top level) -> containers (second level)
- Top-level categories are user-customizable, defaulting to ally/adversary/neutral/partner but users can create custom categories (e.g., "Coalition", "Threat", "Regional Orgs")
- Container names are fully user-defined — not limited to nations (could be organizations, alliances, threat groups, etc.)
- Containers are shared across problem sets, scoped to a "strategic environment" level
- Create a lightweight `strategic_environments` table now (id, name, created_by) as the home for containers — Phase 26 adds inheritance on top
- Documents can belong to multiple containers (junction table model)
- Access control: role-based + admin/creator can manage containers; other users can view and assign docs

### Actor Categorization
- Color-coded badges per category — doctrinally intuitive defaults (blue=friendly, red=adversary, gray=neutral, green=partner)
- Fixed colors for the four default categories; custom categories pick from a color palette
- Categories are changeable over time (a container can be reassigned from "neutral" to "adversary" as scenario evolves) with audit trail
- Dual navigation: browse by category (see all adversary containers) OR by container (see a specific nation's docs); category acts as both grouping and filter

### Upload Integration
- Container assignment is optional at upload time — unassigned docs go to "Unorganized" section
- Multi-select dropdown in upload form showing existing containers grouped by category
- Inline container creation during upload (type name + pick category)
- AI recommendation: after text extraction during upload, AI analyzes document and pre-fills suggested container(s) and actor category; user can override before confirming upload

### Container Browsing UI
- Replace current flat DocumentList in "Strategic Documents" view with container browser
- Container view grouped by actor category with doc counts per container
- Category filter bar at top (All | Friendly | Adversary | etc.)
- Document cards when drilling into a container (title, level, classification badge, extraction status, agent badges)
- Breadcrumb navigation: Category > Container > Document
- Drag-and-drop for quick single assignment + explicit "Assign to container" action for multi-container management
- Inline container management (create via "+" button, inline rename, delete with confirmation)

### Container-Level AI Agent Assignment
- Surface existing per-document agent badges on document cards within containers
- New capability: assign agents/teams to an entire container (e.g., "Monitor all China docs")
- Auto-apply: when an agent is assigned to a container, it automatically processes any new document added to that container (standing order pattern)

### Claude's Discretion
- Exact data model for strategic_environments and strategic_containers tables (columns, indexes, constraints)
- Container-level agent assignment DB schema and job triggering mechanism
- AI recommendation model/prompt for container suggestion during upload
- Drag-and-drop implementation approach
- Empty state designs
- Error handling and loading states
- Exact color palette for custom categories

</decisions>

<specifics>
## Specific Ideas

- Top-level categories are NOT fixed to "actor types" — user defines what the organizational axis is. Nations was just one example; could be threat types, domains, functional areas, etc.
- Container-level agents act as "standing orders" — auto-process new documents on arrival
- Existing example structure from roadmap (Friendly > US/Japan/Australia, Adversary > China/Russia, Neutral > NATO/ASEAN) is illustrative, not prescriptive

</specifics>

## Existing Code Insights

### Reusable Assets
- `DocumentList` component: current flat doc list with cards, extraction progress, agent badges — can be adapted for container-scoped view
- `DocumentUpload` component: drag-drop upload with title/level/classification — extend with container multi-select
- `AgentAssignmentModal` + `AgentBadges`: existing per-document agent assignment UI — surface in container view
- `strategicService`: frontend service for document CRUD — extend with container endpoints
- `TabLayout`: sidebar pattern used in UnderstandTab — container view replaces StrategicDashboard content
- `MIDLIFE_METADATA` pattern: color-coded badges with label/color/description — reuse pattern for actor categories

### Established Patterns
- `strategic_documents` table: flat structure with workspace_id (will need container_id junction table)
- `strategic_objectives` table: references documents — objective queries may need container-aware filtering
- SSE streaming for extraction progress — can reuse for container-level agent processing
- `DocumentAgentAssignment` type: existing model for per-doc agents — extend for container-level

### Integration Points
- `UnderstandTab` > `StrategicDashboard`: replace inner content with container browser
- `strategic_documents` table: add migration for container junction table
- Upload API (`/api/documents`): extend to accept container assignments
- New `strategic_environments` and `strategic_containers` tables
- New `container_documents` junction table
- New `container_agent_assignments` table

</code_context>
