Create `frontend/src/lib/gate-service.ts`:
- Mirror the gate types from backend (duplicate the interfaces on frontend — DecisionGate, GateProposalContext, CreateGateParams, GateType/GateStatus/GateEnforcement/TimeoutBehavior const objects). Follow existing pattern from governance-service.ts for raw-to-typed transforms.
- NOTE: The frontend gate-service.ts duplicates types from backend/src/gates/gate-types.ts. Both plans define DecisionGate independently. The backend is authoritative — frontend mirrors it. If the backend schema changes, the frontend must be updated to match. Keep the interface shapes identical.
- `fetchGatesForProblemSet(problemSetId: string): Promise<DecisionGate[]>` — GET /api/gates/:problemSetId
- `fetchGatesByTab(problemSetId: string, tab: string): Promise<DecisionGate[]>` — GET /api/gates/:problemSetId/:tab
- `submitGateForApproval(gateId: string, submittedBy: string, context: GateProposalContext): Promise<DecisionGate>` — POST /api/gates/:gateId/submit
- `approveGate(gateId: string, decidedBy: string): Promise<DecisionGate>` — POST /api/gates/:gateId/approve
- `rejectGate(gateId: string, decidedBy: string, reason: string): Promise<DecisionGate>` — POST /api/gates/:gateId/reject
- `overrideGate(gateId: string, overriddenBy: string, justification: string): Promise<DecisionGate>` — POST /api/gates/:gateId/override
- `escalateGate(gateId: string, escalatedBy: string, reason: string): Promise<DecisionGate>` — POST /api/gates/:gateId/escalate
- `createGate(params: CreateGateParams): Promise<DecisionGate>` — POST /api/gates
- `updateGateConfig(gateId: string, config: { enforcement?: string; deadlineAt?: string; timeoutBehavior?: string }): Promise<DecisionGate>` — PATCH /api/gates/:gateId/config
- Follow fetchJson pattern from mdmp-service.ts (check response.ok, throw on error)
- Export singleton: `export const gateService = { fetchGatesForProblemSet, ... }`

Create `frontend/src/context/DecisionGateContext.tsx`:
- `DecisionGateContextType` interface:
  - `gates: DecisionGate[]` — all gates for active problem set
  - `gatesByTab: Record<string, DecisionGate[]>` — pre-grouped
  - `pendingApprovals: DecisionGate[]` — gates with status 'submitted'
  - `loading: boolean`
  - `error: string | null`
  - `submitForApproval: (gateId: string, context: GateProposalContext) => Promise<void>`
  - `approveGate: (gateId: string) => Promise<void>`
  - `rejectGate: (gateId: string, reason: string) => Promise<void>`
  - `overrideGate: (gateId: string, justification: string) => Promise<void>`
  - `escalateGate: (gateId: string, reason: string) => Promise<void>`
  - `refreshGates: () => Promise<void>`
  - `createGate: (params: CreateGateParams) => Promise<void>`
- `DecisionGateProvider` component:
  - Takes `children` and `problemSetId: string`
  - Uses `useProblemSet()` to get `userRoleInActive` for submittedBy/decidedBy
  - Uses `useMode()` to tag gates with training/operational
  - Fetches all gates on mount via gateService.fetchGatesForProblemSet(problemSetId)
  - Groups gates by tab into gatesByTab record
  - Provides action functions that call gateService then refreshGates()
  - Refresh on gate actions (submit, approve, reject, etc.)
- `useDecisionGates(tabId?: string)` hook:
  - Consumes DecisionGateContext
  - If tabId provided, returns only gates for that tab from gatesByTab
  - Returns `{ gates, pendingCount, pendingApprovals, loading, error, ...actions }`
  - `pendingCount`: count of 'submitted' gates for this tab
  - `isCommander`: derives from `useProblemSet().userRoleInActive` — true for 'commander' or 'xo'
