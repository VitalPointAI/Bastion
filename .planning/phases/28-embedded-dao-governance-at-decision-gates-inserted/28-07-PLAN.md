Read gate-service.ts, gate-routes.ts, and inspect backend/src/inheritance/ for parent-child problem set lookup patterns.

**gate-service.ts extensions:**

1. **Escalation enhancements:**
   - In `escalateGate()`: look up the parent problem set via inheritance service. Set the escalated gate's metadata to include `escalatedToParent: parentProblemSetId` and `escalatedFromTab: gate.tab`
   - Add `getEscalatedGatesForParent(parentProblemSetId: string): Promise<DecisionGate[]>` — returns all gates escalated to this parent from child problem sets. Query decision_gates where status='escalated' and decision_context contains escalatedToParent matching this parent ID
   - In `processTimeouts()`: for gates with timeout_behavior='auto_escalate' past deadline, call escalateGate automatically with reason "Auto-escalated: deadline exceeded"

2. **Hierarchical visibility:**
   - Add `getGatesWithChildVisibility(problemSetId: string): Promise<{ ownGates: DecisionGate[], childGates: DecisionGate[] }>` — returns own gates plus gates from child problem sets (use inheritance service to find children, then query their gates)
   - This enables parent commanders to see child problem set gates

3. **Role-based permissions:**
   - Add `canActOnGate(userRole: string, gate: DecisionGate): { canApprove: boolean, canReject: boolean, canOverride: boolean, canEscalate: boolean, canConfigure: boolean }` — derive from DAO membership role:
     - commander/xo: canApprove, canReject, canOverride, canConfigure = true
     - member/planner/analyst: canEscalate = true (can escalate rejected/stalled gates)
     - All roles: canEscalate on rejected or stalled gates
   - Add `configureParentAuthority(problemSetId: string, config: { directAction: boolean }): Promise<void>` — configurable whether parent has direct action or requires formal escalation

**gate-routes.ts additions:**
- `GET /api/gates/:problemSetId/escalated` — returns escalated gates for this problem set (as parent)
- `GET /api/gates/:problemSetId/hierarchy` — returns own gates + child gates
- `GET /api/gates/:gateId/permissions/:userRole` — returns permission object for this role on this gate
