  <name>Task 2: Gate service and REST API routes</name>
  <files>backend/src/gates/gate-service.ts, backend/src/gates/gate-routes.ts, backend/src/index.ts</files>

Create `backend/src/gates/gate-service.ts`:
- `GateService` class with constructor taking GateStore
- `createGate(params: CreateGateParams): Promise<DecisionGate>` — validates gate_type is valid, sets defaults from GATE_DEFAULTS, delegates to store.create()
- `getGatesForProblemSet(problemSetId: string): Promise<DecisionGate[]>` — returns all gates grouped-ready (service just returns flat list, frontend groups by tab)
- `getGatesByTab(problemSetId: string, tab: string): Promise<DecisionGate[]>` — filtered by tab
- `submitForApproval(gateId: string, submittedBy: string, proposalContext: GateProposalContext): Promise<DecisionGate>` — transitions status to 'submitted', sets submitted_by/submitted_at, stores decision_context
- `approveGate(gateId: string, decidedBy: string): Promise<DecisionGate>` — transitions to 'approved', sets decided_by/decided_at
- `rejectGate(gateId: string, decidedBy: string, reason: string): Promise<DecisionGate>` — transitions to 'rejected', stores reason in decision_context
- `overrideGate(gateId: string, overriddenBy: string, justification: string): Promise<DecisionGate>` — for soft-warning gates, transitions to 'overridden' with justification logged
- `escalateGate(gateId: string, escalatedBy: string, reason: string): Promise<DecisionGate>` — transitions to 'escalated'
- `updateGateConfig(gateId: string, enforcement: string, deadlineAt?: Date, timeoutBehavior?: string): Promise<DecisionGate>` — commander/XO gate configuration
- `processTimeouts(): Promise<DecisionGate[]>` — finds gates past deadline, applies timeout_behavior (auto_escalate -> escalated, auto_approve -> approved with log, block -> no change)
- Singleton export: `export const gateService = new GateService(gateStore)`

Create `backend/src/gates/gate-routes.ts`:
- Express Router with routes:
  - `GET /api/gates/:problemSetId` — returns all gates for problem set
  - `GET /api/gates/:problemSetId/:tab` — returns gates filtered by tab
  - `POST /api/gates` — create a new gate (body: CreateGateParams)
  - `POST /api/gates/:gateId/submit` — submit for approval (body: { submittedBy, context: GateProposalContext })
  - `POST /api/gates/:gateId/approve` — approve gate (body: { decidedBy })
  - `POST /api/gates/:gateId/reject` — reject gate (body: { decidedBy, reason })
  - `POST /api/gates/:gateId/override` — override soft-warning (body: { overriddenBy, justification })
  - `POST /api/gates/:gateId/escalate` — escalate gate (body: { escalatedBy, reason })
  - `PATCH /api/gates/:gateId/config` — update gate configuration (body: { enforcement, deadlineAt?, timeoutBehavior? })
- Each route: try/catch with 400/404/500 error handling
- Export as `gateRoutes`

Register routes in `backend/src/index.ts`:
- Import gateRoutes, call `app.use(gateRoutes)` alongside existing route registrations
- Call `gateStore.ensureTable()` during startup (alongside other store init)

Look at how existing routes (mdmp.ts, other route files) are registered in index.ts and follow the same pattern exactly.
