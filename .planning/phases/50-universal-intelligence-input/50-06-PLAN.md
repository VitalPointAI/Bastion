<objective>
Bridge the gap between doc-intelligence geocoded locations and COP layer creation.

Currently, the OSINT pipeline has a complete path from ingested events to COP layers
(osint-cop-pipeline.ts: geocoded events → affiliation/symbol inference → SIDC codes →
COP layer creation → cop:layer_updated broadcast). The doc-intelligence pipeline extracts
locations via geocodingService.extractLocations() in the orchestrator but stops there —
locations are attached to the report JSON but never flow to COP layers.

This plan creates a doc-intelligence-to-COP pipeline mirroring the OSINT pattern, wired
into the orchestrator's post-processing step so that documents with extractable locations
automatically populate COP intel layers.

Output: `doc-cop-pipeline.ts` wired into the orchestrator, with tests.
</objective>

  <action>
    Create `doc-cop-pipeline.ts` following the same pattern as `osint-cop-pipeline.ts`:

    **Function: `updateDocIntelCOPLayer(problemSetId, report, locations)`**

    Input:
    - `problemSetId` — workspace scoping
    - `report` — DocumentIntelligenceReport (contains facts with entities, graphResult with actors)
    - `locations` — geocoded locations from orchestrator (array of {name, lat, lng, confidence})

    Processing:
    1. Filter locations to those with valid lat/lng coordinates
    2. Cross-reference locations against extracted actors from `report.facts[].entities` — associate
       each location with nearby actors/entities from the same fact
    3. Infer affiliation (friendly/hostile/neutral/unknown) from actor ontology types and relationship
       context — mirror the keyword-based approach in osint-cop-pipeline but also check actor node
       properties if available
    4. Infer symbol set (ground/naval/air/cyber/space) from entity types and fact context
    5. Generate MIL-STD-2525D SIDC codes for each location-entity pair
    6. Build `COPSymbolSpec[]` and `COPAnnotationSpec[]`
    7. Create or update a "Document Intelligence" COP layer for the problem set
    8. Broadcast `cop:layer_updated` via message bus

    Edge cases:
    - No locations → return early, no COP layer created
    - Locations without associated entities → create annotation-only markers (no SIDC symbol)
    - Trust-flagged documents → caller must not invoke this function (gate is in orchestrator)

    Tests should cover:
    - Locations with entities → COP symbols created with correct SIDC
    - Locations without entities → annotations only
    - Empty locations array → no layer created
    - Mixed valid/invalid coordinates → only valid ones processed
  </action>
  <verify>Tests pass. Function creates COP symbols from geocoded document locations.</verify>
  <done>doc-cop-pipeline.ts created with updateDocIntelCOPLayer function and full test coverage.</done>
</task>
