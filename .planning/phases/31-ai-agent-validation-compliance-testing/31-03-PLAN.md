Create `backend/src/validation/circuit-breaker.ts`:
- Export class `CircuitBreaker` with methods:
  - `evaluate(agentId: string, category: ValidationCategory, score: number): Promise<{ state: CircuitState; action: 'none' | 'warn' | 'disable' }>` — loads threshold via getThresholdForAgent, compares score, checks grace period (counts consecutive failures from recent agent scores), determines state transition. For immediateDisable categories (authority by default), skip grace period.
  - `disableAgent(agentId: string, category: string, runId: string, triggeredBy: string): Promise<void>` — calls AgentRegistry.deactivateAgent(), inserts CircuitBreakerEvent, calls `activateFallback()`, posts critical alert to AI staff feed.
  - `reinstateAgent(agentId: string, triggeredBy: string, justification?: string): Promise<void>` — TWO DISTINCT PATHS per locked user decision:
    - **Standard path (no justification):** Does NOT simply reactivate. Instead: (1) triggers a re-test by calling `validationRunner.executeAgentTests()` for this agent's fixture, (2) checks the resulting scores against thresholds, (3) ONLY reactivates the agent in registry if ALL category scores pass their respective warning thresholds, (4) inserts reinstatement event (event_type='reinstated') with pass/fail details, (5) if re-test fails, agent stays disabled and method returns the failure reason.
    - **Admin override path (with justification):** Force-reactivates agent in registry WITHOUT re-test. Inserts override event (event_type='override') with the mandatory justification note. Logged for audit trail.
  - `activateFallback(agentId: string): Promise<string | null>` — finds another active agent with same roleKey that has the highest recent validation score. If found, returns fallback agent ID and logs fallback_activated event. If none available, returns null and logs warning.
  - `postCriticalAlert(agentId: string, category: string, score: number, threshold: number): Promise<void>` — creates AIFeedItemRow with priority='critical', urgency='action_required', content describing the failure, and posts to AI staff feed. Look up the actual feed insert pattern from ai-staff-store.ts.
  - `sendWebhook(event: CircuitBreakerEventRow): Promise<void>` — if a webhook URL is configured (check admin config or env var VALIDATION_WEBHOOK_URL), POST JSON payload with agent_id, category, event_type, score, threshold. Fire-and-forget with 5s timeout, log errors but don't throw.

Create `backend/src/validation/validation-runner.ts`:
- Export class `ValidationRunner` with methods:
  - `executeFullRun(triggeredBy: string): Promise<TestRunRow>` — orchestrates a complete validation run:
    1. Creates run record via validationStore.createRun()
    2. Loads all fixture files from `backend/src/validation/fixtures/*.json` using fs.readdir + JSON.parse
    3. For each fixture, calls `executeAgentTests(fixture, runId)` — serialize per-agent (avoid rate limits), but use configurable concurrency (default 2 agents at a time using a simple semaphore pattern)
    4. After all agents complete, calls validationStore.completeRun()
    5. Returns the run record
  - `executeAgentTests(fixture: TestFixture, runId: string): Promise<void>`:
    1. For each scenario in fixture.scenarios, execute the agent's LLM call using the project's agent execution infrastructure (look up how agents are invoked — likely via AgentWrapperConfig or the orchestration layer). Run `fixture.runCount` times for determinism scenarios.
    2. Score each scenario: call scoreDeterminism (if multiple runs), scoreReliability, scoreAuthority as appropriate based on scenario.category.
    3. Insert each result via validationStore.insertResult()
    4. For adversarial scenarios: run once, score with scoreAuthority()
    5. Compute aggregate scores per category, insert via validationStore.insertAgentScore()
    6. Call circuitBreaker.evaluate() for each category. If action='disable', call circuitBreaker.disableAgent().
  - `executeAgentCall(agentId: string, messages: Array<{role: string; content: string}>, context?: Record<string, unknown>): Promise<string | Record<string, unknown>>` — invokes the agent using the project's LLM infrastructure. Look up how existing code invokes agents (agent-wrapper.ts pattern). Return the agent's output. Handle errors gracefully — return error string, don't throw.
  - `loadFixtures(): Promise<TestFixture[]>` — reads all .json files from fixtures directory, validates with basic checks (has scenarios, has agentId), returns parsed array.

Export singleton: `export const validationRunner = new ValidationRunner();`
Export circuit breaker singleton: `export const circuitBreaker = new CircuitBreaker();`

Create `backend/src/validation/validation-scheduler.ts`:
- Export `registerValidationJobs(): Promise<void>` — follows message-bus.ts / blockchain-sync.ts PgBoss pattern:
  1. Get boss via getSharedBoss()
  2. Create queue 'validation-run'
  3. Schedule periodic runs: `boss.schedule('validation-run', '0 */6 * * *')` (every 6 hours default)
  4. Register worker: `boss.work('validation-run', { teamSize: 1 }, async () => { await validationRunner.executeFullRun('scheduled'); })`
  5. Also seed default thresholds via seedDefaultThresholds() on startup
  6. Also ensure validation store tables via validationStore.ensureTable()

Create `backend/src/validation/validation-router.ts`:
- Export `validationRouter` (Express Router) with these endpoints:

  POST `/api/validation/runs` — trigger manual validation run
  - Body: `{ triggeredBy?: string }` (defaults to request user DID)
  - Starts run in background (don't block HTTP response): use setImmediate or fire-and-forget promise
  - Returns 202 with `{ runId, status: 'started' }`

  GET `/api/validation/runs` — list recent runs
  - Query: `?limit=20`
  - Returns TestRunRow[]

  GET `/api/validation/runs/:runId` — get run details with results
  - Returns `{ run: TestRunRow, results: TestResultRow[] }`

  GET `/api/validation/dashboard` — dashboard summary
  - Returns ValidationDashboardSummary[] from validationStore.getDashboardSummaries()

  GET `/api/validation/agents/:agentId/scores` — agent score history
  - Query: `?category=determinism&limit=50`
  - Returns ValidationAgentScoreRow[]

  GET `/api/validation/agents/:agentId/circuit-events` — circuit breaker history
  - Returns CircuitBreakerEventRow[]

  GET `/api/validation/thresholds` — get all thresholds
  - Query: `?scopeType=agent&scopeId=cmd-001`
  - Returns ThresholdConfigRow[]

  PUT `/api/validation/thresholds` — upsert threshold
  - Body: ThresholdConfigRow fields (scope_type, scope_id, category, warning_threshold, critical_threshold, grace_period_runs, immediate_disable)
  - Returns updated threshold

  POST `/api/validation/agents/:agentId/reinstate` — reinstate disabled agent
  - Body: `{ justification?: string }` — if justification present, it's admin override (skips re-test); if absent, standard path (triggers re-test, only reactivates if passes)
  - Calls circuitBreaker.reinstateAgent()
  - Returns 200 with `{ reinstated: boolean, reason?: string }` — reinstated=false if re-test failed

  GET `/api/validation/export/:format` — export validation data
  - :format = 'csv' or 'pdf'
  - Query: `?agentId=optional&from=ISO&to=ISO`
  - For CSV: stream response with Content-Type text/csv
  - For PDF: generate via pdfkit, stream response with Content-Type application/pdf
  - CSV includes: run_id, agent_id, scenario_id, category, functional_score, llm_judge_score, combined_score, disagreement, created_at
  - PDF includes: summary page with agent grid + scores, per-agent detail pages with score charts described textually (tables since pdfkit can't embed Recharts), circuit events table
