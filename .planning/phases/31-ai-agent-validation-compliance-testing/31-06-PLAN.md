  <action>
Create `backend/src/validation/activation-gate.ts`:
- Export const `MINIMUM_SCENARIOS = 3` (per user decision: 3-5 golden prompts required)
- Export `canActivateAgent(agentId: string, roleKey: string): Promise<{ allowed: boolean; reason?: string }>`:
  1. Load fixture via loadFixture(roleKey)
  2. If no fixture found: return `{ allowed: false, reason: 'No test fixture found for role ${roleKey}. Create fixture at backend/src/validation/fixtures/${roleKey}.json' }`
  3. Validate completeness via validateFixtureCompleteness(fixture)
  4. If fixture has < MINIMUM_SCENARIOS scenarios: return `{ allowed: false, reason: 'Fixture has ${n} scenarios, minimum ${MINIMUM_SCENARIOS} required' }`
  5. If fixture has < 2 adversarial scenarios: return `{ allowed: false, reason: 'Fixture has ${n} adversarial scenarios, minimum 2 required' }`
  6. Return `{ allowed: true }`

Modify `backend/src/agents/registry.ts`:
- Import `canActivateAgent` from `../validation/activation-gate.js`
- In the `registerAgent(manifest)` method, after DID generation but before setting the agent as active:
  1. Call `const gate = await canActivateAgent(manifest.agentId, /* derive roleKey from manifest — check how roleKey maps to agentId */)`
  2. If `!gate.allowed`: set `manifest.active = false` and add a note to the manifest (or log a warning). Do NOT throw — allow registration but keep agent inactive until tests are provided.
  3. This ensures the "enforced minimum test scenarios required before agent can be activated" per user decision.
- Also check in any `activateAgent` or `setAgentActive` method if one exists — enforce the gate there too.

Note: The existing agent library (agent-library.ts) seeds default agents. These already have fixtures created in Plan 04, so they should pass the activation gate. But the gate provides forward-looking protection for dynamically created agents.
