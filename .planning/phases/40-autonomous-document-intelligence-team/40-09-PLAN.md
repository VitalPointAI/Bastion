**orchestrator-wiring.ts** - Complete orchestrator graph assembly:

`createWiredDocIntelligenceGraph(config: { problemSetId: string, onProgress?: (event: string, data: any) => void })` function:

1. Import all specialist classes from specialists/ directory
2. Instantiate each specialist with appropriate config (problemSetId, LLM provider)
3. Build the LangGraph StateGraph using DocIntelligenceStateAnnotation from orchestrator.ts:

**Node registration:**
- `triage` - LLM triage node (from orchestrator.ts)
- `format-converter` - FormatConverter.createNode()
- `classifier` - DocumentClassifier.createNode()
- `fact-extractor` - FactExtractor.createNode()
- `objective-extractor` - ObjectiveExtractor.createNode()
- `perspective-friendly` - PerspectiveAnalyst('friendly').createNode()
- `perspective-adversary` - PerspectiveAnalyst('adversary').createNode()
- `perspective-neutral` - PerspectiveAnalyst('neutral').createNode()
- `perspective-partner` - PerspectiveAnalyst('partner').createNode()
- `bias-identifier` - BiasIdentifier.createNode()
- `cross-doc-linker` - CrossDocLinker.createNode()
- `quality-assessor` - QualityAssessor.createNode()
- `trust-agent` - TrustAgent.createNode()
- `report-assembly` - report assembly node (from orchestrator.ts)

**Edge wiring (per RESEARCH.md dependency graph):**
- `START -> triage`
- `triage -> format-converter` (conditional: only if triage says document needs OCR/translation)
- `triage -> classifier` (conditional: skip converter if not needed)
- `format-converter -> classifier` (if converter ran)
- `classifier -> trust-agent` (trust evaluation before extraction)
- Trust gate: `trust-agent -> fact-extractor` ONLY if trust_status != 'flagged'. If flagged, route to `report-assembly` with a "requires human review" flag.
- `classifier -> fact-extractor` (parallel fan-out after classifier)
- `classifier -> perspective-friendly` (conditional per triage)
- `classifier -> perspective-adversary` (conditional per triage)
- `classifier -> perspective-neutral` (conditional per triage)
- `classifier -> perspective-partner` (conditional per triage)
- `classifier -> bias-identifier` (conditional per triage)
- `classifier -> objective-extractor` (conditional per triage)
- `fact-extractor -> cross-doc-linker` (dependency: linker needs facts first)
- All specialist outputs -> `report-assembly` (fan-in)
- `report-assembly -> quality-assessor` (final quality gate)
- `quality-assessor -> END`

**Progress callbacks:** Wrap each node to fire `onProgress('specialist:start', { specialistId, timestamp })` before execution and `onProgress('specialist:complete', { specialistId, duration, entityCount })` after.

**Compile the graph** using LangGraph's `graph.compile()` with existing PostgreSQL checkpointer for fault recovery.

Export the compiled graph factory function.

<task type="auto">
  <name>Task 2: Document upload API with SSE processing stream</name>
  <files>backend/src/api/doc-intelligence.ts</files>
  <action>
Extend the existing doc-intelligence router (created in Plan 02) with document processing endpoints:

**New routes:**

`POST /api/doc-intelligence/process/:problemSetId` - Document upload and immediate processing:
- Accept multipart form data (document file) or JSON body with documentId (if already stored)
- If file upload: use existing DocumentStore to save document, get documentId
- Use existing DocumentParser to extract text from the document
- Load ProblemSetContext from InterviewStore (if not found, return 400: "Complete scoping interview first")
- Invoke `createWiredDocIntelligenceGraph()` with the document
- Return 202 Accepted with `{ processingId, documentId, sseUrl }` for client to connect to SSE stream
- Per user decision: "Immediate processing on document upload -- no batch queue"

`GET /api/doc-intelligence/process/:problemSetId/stream/:processingId` - SSE stream for processing status:
- Follow existing SSE pattern from `backend/src/api/strategic.ts`
- Set headers: Content-Type: text/event-stream, Cache-Control: no-cache, Connection: keep-alive
- Events emitted (per RESEARCH.md Pattern 5):
  - `specialist:start` - `{ agentId, documentId, timestamp }`
  - `specialist:progress` - `{ agentId, stage, detail, entitiesFound }`
  - `specialist:complete` - `{ agentId, result, duration }`
  - `report:assembled` - `{ reportId, entityCount, ratingsSummary }`
  - `processing:error` - `{ error, agentId? }`
  - `processing:flagged` - `{ reason, trustStatus }` (when trust agent flags document)
- Connect the onProgress callback from orchestrator-wiring to this SSE stream
- Clean up SSE connection on client disconnect

`GET /api/doc-intelligence/reports/:problemSetId` - List all intelligence reports for a problem set
`GET /api/doc-intelligence/reports/:problemSetId/:documentId` - Get specific report

`POST /api/doc-intelligence/ratings/:documentId/override` - User override of NATO rating:
- Body: `{ sourceReliability, informationCredibility, reason }`
- Preserve original rating as `originalRating`, set `overriddenBy` to authenticated user DID, log `overrideReason`
- Update strategic_documents NATO columns

`POST /api/doc-intelligence/sources/:documentId/approve` - Approve a flagged source for graph ingestion
- Changes trust_status from 'flagged' to 'trusted'
- Triggers re-processing of the document through extraction specialists (entities can now enter graph)

Register all new routes on the existing Express router.
