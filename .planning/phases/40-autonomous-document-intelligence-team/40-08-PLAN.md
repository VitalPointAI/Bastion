**change-tracker.ts** - Per-user/agent change detection:
- `ChangeTracker` class with methods:
  - `recordAccess(problemSetId: string, accessedBy: string, graphSnapshotHash: string): Promise<void>` - INSERT into briefing_access_log
  - `getLastAccess(problemSetId: string, accessedBy: string): Promise<{ accessedAt: Date, graphSnapshotHash: string } | null>` - most recent access
  - `computeGraphHash(problemSetId: string): Promise<string>` - hash of current graph state. Use a lightweight approach: hash of (entity count + last-modified timestamp + sum of entity IDs). This avoids expensive full-graph serialization.
  - `getChangesSince(problemSetId: string, sinceTimestamp: Date): Promise<ChangeSet>` - query graph entities and relationships created/modified after the timestamp. Return:
    - newEntities: entities created since timestamp
    - modifiedEntities: entities updated since timestamp
    - newRelationships: relationships created since timestamp
    - revokedEntities: entities revoked since timestamp
    - summary: LLM-generated one-paragraph summary of what changed
  - `hasChanges(problemSetId: string, accessedBy: string): Promise<boolean>` - quick check comparing current hash to last-access hash

**predictive-service.ts** - Predictive analytics overlay:
- `PredictiveService` class with methods:
  - `analyzePatterns(problemSetId: string): Promise<PredictiveAnalysis>` - uses LLM to analyze graph trends:
    1. Load recent graph entities, relationships, and tensions for the problem set
    2. Identify patterns: actor relationship strengthening/weakening, tension escalation/de-escalation, capability changes, alliance shifts
    3. Generate "emerging patterns" with explicit uncertainty quantification (per RESEARCH.md Open Question 3)
    4. Each pattern has: description, confidence (0-1 with explicit caveats), supporting evidence (entity/relationship IDs), timeframe, potential outcomes
  - Output: `{ patterns: EmergingPattern[], overallAssessment: string, dataQuality: string }`
  - System prompt: "You are a strategic intelligence analyst identifying emerging patterns in the operational environment. Based on the knowledge graph data, identify trends that may indicate future developments. Quantify your confidence explicitly. Use language like 'moderate confidence based on X corroborating sources' not definitive predictions. If data is insufficient for prediction, say so."
  - Confidence calibration: confidence should reflect number of corroborating sources, recency of data, NATO credibility ratings of contributing documents
  - Present as "emerging patterns" NOT "predictions" per RESEARCH.md recommendation

**briefing-service.ts** - On-demand narrative briefing:
- `BriefingService` class with methods:
  - `generateBriefing(problemSetId: string, requestedBy: string): Promise<StrategicBriefing>` - the main entry point:
    1. Call existing `StrategicContextService.assembleContext(problemSetId)` to get structured data (graph summaries, documents, decisions) with token budgeting
    2. Call `ChangeTracker.getLastAccess()` to find what's new for this user
    3. If changes exist, call `ChangeTracker.getChangesSince()` to get delta
    4. Call `PredictiveService.analyzePatterns()` for emerging patterns
    5. Use LLM to transform all of the above into a human-readable narrative briefing with sections:
       - **Executive Summary**: 2-3 sentence overview of current strategic environment
       - **Key Developments** (if changes): "Since your last briefing on {date}, the following has changed: ..."
       - **Strategic Landscape**: Narrative description of actors, relationships, tensions organized by the problem set's geographic/temporal scope
       - **Emerging Patterns**: From predictive service, with confidence annotations
       - **Intelligence Gaps**: Areas where information is insufficient or contradictory
       - **Recommendations**: Suggested focus areas based on gaps and patterns
    6. Record access via ChangeTracker.recordAccess() with current graph hash
    7. Return structured briefing with both narrative text and metadata (sources cited, entities referenced, confidence scores)
  - `getBriefingHistory(problemSetId: string, requestedBy: string): Promise<BriefingRecord[]>` - past briefings for this user

- System prompt: "You are a senior intelligence briefer preparing a strategic environment briefing. Write in clear, concise military prose. Use the NATO reporting format where appropriate. Annotate claims with source reliability ratings. Highlight what has changed since the requester's last access. Present emerging patterns with explicit confidence levels. Flag intelligence gaps that need attention."

- Add API routes to the existing doc-intelligence router (from Plan 02):
  - `GET /api/doc-intelligence/briefing/:problemSetId` - generates briefing for authenticated user
  - `GET /api/doc-intelligence/briefing/:problemSetId/changes` - quick check if changes exist since last access
  - `GET /api/doc-intelligence/briefing/:problemSetId/history` - past briefings

- Use LLM factory for narrative generation. Anthropic Claude recommended for high-quality prose.
