**interview-prompts.ts** - System prompts for adaptive interview:
- `INTERVIEW_SYSTEM_PROMPT`: You are a strategic planning analyst conducting a scoping interview. Ask one question at a time. Adapt follow-ups based on answers. Cover: geographic scope, temporal range, actors/alliances, core problem/challenge/opportunity, classification ceiling, echelon level, standing intelligence requirements, additional nuance. When you have sufficient information across all categories, summarize what you've captured and ask for confirmation.
- `INTERVIEW_SUMMARY_PROMPT`: Given the conversation history, extract a structured ProblemSetContext JSON object.
- `INTERVIEW_FOLLOW_UP_PROMPT`: Given what we know so far (partial context), determine which areas still need coverage and generate the next question.

**interview-store.ts** - PostgreSQL persistence:
- `saveProblemSetContext(context: ProblemSetContext): Promise<void>` - UPSERT on problem_set_id, incrementing version
- `getProblemSetContext(problemSetId: string): Promise<ProblemSetContext | null>` - retrieve current context
- `getContextVersion(problemSetId: string): Promise<number>` - for re-run detection

**interview-service.ts** - LangGraph StateGraph for the interview:
- Use the InterviewStateAnnotation pattern from RESEARCH.md (messages, questionsAsked, derivedContext, isComplete)
- Nodes: `ask_question` (LLM generates next adaptive question), `process_answer` (extracts info from user response, updates derivedContext), `check_complete` (determines if all categories covered), `summarize` (generates ProblemSetContext from full conversation)
- Conditional edges: check_complete routes to either ask_question (more needed) or summarize (complete)
- Use existing `getCheckpointer()` for PostgreSQL state persistence across refreshes
- `InterviewService` class with:
  - `startInterview(problemSetId: string): Promise<AIMessage>` - begins with first question
  - `continueInterview(problemSetId: string, userMessage: string): Promise<AIMessage>` - processes response, returns next question or summary
  - `getInterviewState(problemSetId: string): Promise<InterviewState>` - for resume
  - `completeInterview(problemSetId: string): Promise<ProblemSetContext>` - validates via ProblemSetContextSchema, saves via InterviewStore
- Use LLM factory (existing `createChatModel` or `getLLM`) for the interview LLM. Use Anthropic Claude for high-quality conversational flow.

**doc-intelligence.ts** - Express API routes (new router):
- `POST /api/doc-intelligence/interview/:problemSetId/start` - starts interview, returns first AI message
- `POST /api/doc-intelligence/interview/:problemSetId/message` - body: { message: string }, returns AI response
- `GET /api/doc-intelligence/interview/:problemSetId/state` - returns current interview state for resume
- `POST /api/doc-intelligence/interview/:problemSetId/complete` - finalizes and stores ProblemSetContext
- `GET /api/doc-intelligence/context/:problemSetId` - returns stored ProblemSetContext
- Register this router in the main Express app (check existing route registration pattern in backend/src/api/).
