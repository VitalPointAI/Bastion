**provenance-store.ts** - PostgreSQL persistence for entity provenance:
- `ProvenanceStore` class with methods:
  - `trackEntity(entityId: string, entityType: string, sourceDocumentId: string, extractedBy: string): Promise<void>` - INSERT into entity_provenance with UNIQUE(entity_id, source_document_id) conflict handling (ON CONFLICT DO NOTHING -- same entity from same source is idempotent)
  - `getEntitySources(entityId: string): Promise<string[]>` - all source_document_ids for an entity
  - `getSourceEntities(sourceDocumentId: string): Promise<{ entityId: string, entityType: string }[]>` - all entities from a source
  - `getEntitiesSolelyFromSource(sourceDocumentId: string): Promise<{ entityId: string, entityType: string }[]>` - entities where this is the ONLY source (critical for revert: these get removed)
  - `getEntitiesWithMultipleSources(sourceDocumentId: string): Promise<{ entityId: string, entityType: string, otherSources: string[] }[]>` - entities corroborated by other sources (these lose the citation but remain)
  - `markRevoked(entityId: string, sourceDocumentId: string, revokedBy: string): Promise<void>` - sets is_revoked=true, revoked_at, revoked_by

**revert-service.ts** - Source revocation with cascade handling:
- `RevertService` class with methods:
  - `previewRevert(sourceDocumentId: string): Promise<RevertPreview>` - returns:
    - entitiesToRemove: entities solely attributed to this source (will be soft-deleted)
    - entitiesToUpdate: entities with multiple sources (will lose this citation)
    - affectedRelationships: edges involving entities to be removed
    - totalImpact: { entitiesRemoved, citationsRemoved, relationshipsAffected }
    This preview lets users see the impact BEFORE executing (Pitfall 5 from RESEARCH.md)
  - `executeRevert(sourceDocumentId: string, executedBy: string): Promise<RevertResult>` - in a database transaction:
    1. Mark all entity_provenance records for this source as is_revoked
    2. For entities solely from this source: soft-delete from graph (mark as revoked, do NOT hard-delete per Pitfall 5)
    3. For entities with multiple sources: remove this source's citation but keep entity active
    4. Update strategic_documents: set trust_status='revoked'
    5. Return summary of all changes made
  - `getRevertHistory(problemSetId: string): Promise<RevertRecord[]>` - audit trail of all revocations
- All operations use database transactions for atomicity
- Soft-delete approach: set a `revoked` flag on graph entities rather than deleting them, allowing recovery if the revocation itself was wrong

**researcher.ts** - Extends SpecialistBase:

`Researcher` class with specialistId 'researcher':
- Two trigger modes per user decision:
  1. **Gap-triggered**: During document extraction, if gaps are detected (missing actor information, temporal gaps, unresolved references), immediately trigger targeted research
  2. **Scheduled OSINT monitoring**: pg-boss scheduled job on configurable cadence (default: daily) that reviews standing intelligence requirements and monitors for new information

- Gap detection:
  1. Analyze knowledge graph for the problem set: entities with low confidence, unresolved references from Cross-Doc Linker, standing requirements from ProblemSetContext not yet addressed
  2. Generate research queries from identified gaps
  3. Use existing web search tools (check existing tool patterns in backend/src) to find relevant OSINT
  4. Generate a research brief (markdown) for each gap filled

- Research pipeline integration:
  1. Research products are stored as strategic_documents with source_type='research_brief', auto-tagged with source URL, retrieval date, and initial trust rating
  2. Research briefs re-enter the document processing pipeline via DocumentOrchestrator.processDocument() -- they get triaged and processed like any other document
  3. Trust Agent evaluates the research source automatically

- Safeguards (Pitfall 3 from RESEARCH.md):
  1. MAX_RESEARCH_DEPTH = 2: research products can trigger one level of follow-up research, never more
  2. Research cooldown: minimum 1 hour between research cycles for the same gap
  3. Gap deduplication: maintain a set of researched gap IDs to avoid re-researching the same gap
  4. Budget limit: configurable max API calls per research cycle (default: 10)

- pg-boss integration:
  - `scheduleOSINTMonitoring(problemSetId: string, cadence: string): Promise<void>` - creates pg-boss scheduled job with singleton key `osint-monitor-${problemSetId}` for deduplication
  - `triggerGapResearch(problemSetId: string, gaps: string[]): Promise<void>` - creates pg-boss job for immediate research
  - Job handler: retrieves ProblemSetContext, identifies gaps, executes research, feeds results back to pipeline

- System prompt: "You are an OSINT researcher supporting strategic intelligence analysis. Given the problem set context and identified knowledge gaps, find relevant open-source information. Focus on: {geographicScope}, {temporalRange}, {actorFocus}. Prioritize authoritative sources. Always cite sources with URLs and retrieval dates."
