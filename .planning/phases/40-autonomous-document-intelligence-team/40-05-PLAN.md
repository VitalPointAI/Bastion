**perspective-analyst.ts** - Extends SpecialistBase:

`PerspectiveAnalyst` class with specialistId 'perspective-analyst':
- Constructor takes a `perspective` parameter: 'friendly' | 'adversary' | 'neutral' | 'partner'
- Each instance analyzes the document from that specific viewpoint
- Input: document text, ProblemSetContext, classification from classifier, known actor information from graph
- Processing:
  1. Build a perspective-specific system prompt: "You are analyzing this document from the {perspective} perspective. Consider the implications, opportunities, threats, and remaining unknowns from the viewpoint of {perspective} actors in the context of: {coreProblem}."
  2. For Friendly: focus on own force advantages, vulnerabilities exposed, operational security concerns
  3. For Adversary: focus on adversary capabilities revealed, intent indicators, potential courses of action
  4. For Neutral: focus on third-party impacts, potential alignment shifts, humanitarian/economic effects
  5. For Partner: focus on coalition implications, interoperability issues, burden-sharing dynamics
  6. Use ProblemSetContext.actorFocus to identify which specific actors to consider for each perspective
- Output: PerspectiveAnalysis validated against PerspectiveAnalysisSchema
- Each perspective instance is a separate LangGraph node (e.g., 'perspective-friendly', 'perspective-adversary') enabling parallel execution

`createPerspectiveAnalysts(perspectives: string[]): PerspectiveAnalyst[]` factory function:
- Called by orchestrator based on triage decision
- Creates one PerspectiveAnalyst per relevant perspective
- Returns array of analysts ready for graph node registration
- Orchestrator determines which perspectives are relevant (e.g., a friendly CONOP might not need adversary perspective, while an intel estimate needs all four)

**bias-identifier.ts** - Extends SpecialistBase:

`BiasIdentifier` class with specialistId 'bias-identifier':
- Primary invocation: ALWAYS for NEWS_ARTICLE, ACADEMIC_RESEARCH, OSINT_REPORT; OPTIONAL for others (per triage)
- Input: document text, ProblemSetContext, document type from classifier
- Processing uses LLM with a bias detection taxonomy:
  1. **Source Framing**: How is information presented? What emphasis/omission patterns?
  2. **Propaganda Indicators**: Emotional language, appeals to authority, strawman arguments, loaded terms
  3. **Information Operations (IO) Markers**: Coordinated messaging patterns, amplification signals, timing correlation with events
  4. **Selection Bias**: What perspectives/facts are included vs excluded?
  5. **Confirmation Bias Risk**: Does this document reinforce existing assumptions without new evidence?
  6. **Cultural/Ideological Lens**: What worldview does the author operate from?
- Each detected bias gets: biasType (from taxonomy), severity (low/medium/high/critical), evidence (quote from document), recommendation (how to adjust interpretation)
- System prompt: "You are an intelligence analyst specializing in information quality and source analysis. Examine this {documentType} for potential biases, propaganda indicators, and information operation markers. Rate each finding by severity. Be thorough but avoid false positives -- not every perspective is bias."
- For military orders and friendly CONOPs, bias detection focuses on assumptions and planning biases rather than propaganda
- Output: BiasAssessment[] validated against BiasAssessmentSchema
