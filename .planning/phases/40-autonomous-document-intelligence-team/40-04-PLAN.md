`FactExtractor` class with specialistId 'fact-extractor':
- Extends the existing GraphBuilder RAFT extraction pattern but adds structured fact output
- Input: document text (chunked), ProblemSetContext, documentId
- Processing:
  1. Use LLM to extract structured facts from each text chunk. System prompt instructs extraction of: named entities (people, organizations, countries), dates/timelines, locations, quantities/capabilities, assertions/claims, with source references (page, paragraph, quote).
  2. For each extracted fact, use GraphBuilder to create/update entities in the knowledge graph. Pass `sourceDocumentId` and `onEntityCreated` callback for SSE streaming.
  3. Write entity_provenance records for every graph entity created, linking entity_id to source_document_id and extracted_by = 'fact-extractor'.
  4. Use existing DocumentParser chunking (DEFAULT_CHUNK_SIZE = 8000) to avoid context window overflow (Pitfall 2 from RESEARCH.md).
  5. Merge chunk results, deduplicating entities across chunks via existing entity resolution service.
- Output: `ExtractedFact[]` validated against ExtractedFactSchema
- System prompt: "You are an intelligence analyst extracting structured facts from documents. For each fact, identify the exact claim, classify its type, assess confidence (0-1), and cite the source passage. Focus on entities, relationships, and claims relevant to: {problemSetContext.coreProblem}. Geographic focus: {problemSetContext.geographicScope}. Temporal focus: {problemSetContext.temporalRange}."
- Use LLM factory for model selection. Use the onProgress callback to report extraction stage.
- Each fact should include entities array (names mentioned in the claim) for downstream cross-document linking.
