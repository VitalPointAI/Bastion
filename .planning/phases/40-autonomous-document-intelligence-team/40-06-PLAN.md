**cross-doc-linker.ts** - Extends SpecialistBase:

`CrossDocLinker` class with specialistId 'cross-doc-linker':
- Runs AFTER Fact Extractor completes (dependency-gated in orchestrator)
- Input: ExtractedFact[] from current document, ProblemSetContext, documentId
- Processing:
  1. Load existing entities from the knowledge graph for the problem set (use existing graph query patterns)
  2. Use existing entity resolution service (`backend/src/graph/resolution/`) for duplicate/co-reference detection between new facts and existing graph entities
  3. For each new entity, check for:
     - **Entity co-reference**: Same entity mentioned in different documents (different names for same actor, same location with different spellings)
     - **Temporal sequencing**: Event in new doc precedes/follows events in existing docs
     - **Corroboration**: Same claim from independent sources -> increase confidence, create CORROBORATES edge
     - **Contradiction**: Conflicting claims from different sources -> create CONTRADICTS edge, flag for analyst attention
  4. Use LLM to assess ambiguous cases where entity resolution alone is insufficient (semantic similarity of claims)
  5. Create CrossDocLink records with type, strength (0-1), and evidence (citing both documents)
  6. Update entity confidence scores in the graph based on corroboration count
- Output: CrossDocLink[] validated against CrossDocLinkSchema
- System prompt: "You are an intelligence analyst specializing in cross-document analysis. Compare newly extracted facts with existing intelligence. Identify corroboration (same fact, independent sources), contradiction (conflicting claims), temporal sequences, and entity co-references. For contradictions, note which source is more recent and which has higher reliability."

**source-store.ts** - PostgreSQL persistence for source trust:
- `SourceStore` class with methods:
  - `getSourceByName(name: string): Promise<SourceEntry | null>` - lookup in source_registry table
  - `upsertSource(source: { sourceName, sourceType, defaultReliability?, trustNotes?, isBlocked? }): Promise<SourceEntry>` - UPSERT on source_name
  - `isSourceBlocked(name: string): Promise<boolean>` - check blocklist
  - `getSourceTrustHistory(name: string): Promise<SourceEntry[]>` - audit trail
  - `updateDocumentTrustStatus(documentId: string, status: 'trusted'|'pending'|'flagged'|'revoked', assessedBy: string): Promise<void>` - update strategic_documents trust columns

**trust-agent.ts** - Extends SpecialistBase:
`TrustAgent` class with specialistId 'trust-agent':
- Evaluates at the SOURCE level (not per-entity -- Pitfall 4 from RESEARCH.md)
- Input: document metadata (source name, origin URL, publication), ProblemSetContext
- Processing:
  1. Check SourceStore for known source: if source_registry has an entry, use its default_reliability. If is_blocked=true, immediately flag and STOP processing.
  2. For unknown sources: use LLM to assess based on source type, publication history, domain reputation
  3. If source reliability is D/E/F or credibility 4/5/6 (isHumanReviewRequired returns true): set trust_status='flagged' on strategic_documents. Entities from this source must NOT be auto-ingested into the graph. Return flag for human review.
  4. For trusted sources: set trust_status='trusted', allow entities to enter graph
  5. For new sources: create entry in source_registry with assessed reliability
- Output: { trustStatus: 'trusted'|'pending'|'flagged', natoRating: NATORating, requiresHumanReview: boolean, reasoning: string }
- System prompt: "You are an intelligence source evaluation specialist. Assess the reliability of this information source using NATO standards. Consider: publication type, known track record, potential biases, geographic origin, relationship to actors in the problem set."

**quality-assessor.ts** - Extends SpecialistBase:
`QualityAssessor` class with specialistId 'quality-assessor':
- Runs on every document as the final quality gate
- Input: all specialist outputs (facts, perspectives, bias findings, trust assessment), document text, ProblemSetContext
- Processing:
  1. Assess source reliability (A-F) based on Trust Agent output + internal consistency of document
  2. Assess information credibility (1-6) based on: corroboration from Cross-Doc Linker, internal consistency, recency, bias findings
  3. Combine into NATO rating with detailed reasoning
  4. Update strategic_documents with nato_reliability and nato_credibility columns
  5. If Bias Identifier found high-severity issues, lower credibility assessment accordingly
- Output: NATORating validated against NATORatingSchema
- User-overridable: the rating is stored with assessedBy='quality-assessor'. Override API (in later plan) will preserve originalRating and log overriddenBy + overrideReason.
