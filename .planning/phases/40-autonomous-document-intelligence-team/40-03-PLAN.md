**orchestrator.ts** - The central LangGraph StateGraph:

Define `DocIntelligenceStateAnnotation` using LangGraph Annotation.Root:
- `documentId: string`
- `problemSetId: string`
- `documentText: string` (chunked via existing DocumentParser)
- `metadata: Record<string, any>` (filename, size, upload source)
- `problemSetContext: ProblemSetContext`
- `triageDecision: TriageDecision`
- `convertedText: string | null` (Format Converter output)
- `classification: any` (Classifier output)
- `facts: ExtractedFact[]` (reducer: array append for parallel writes)
- `perspectives: PerspectiveAnalysis[]` (reducer: array append)
- `biasFindings: BiasAssessment[]` (reducer: array append)
- `crossDocLinks: CrossDocLink[]` (reducer: array append)
- `qualityRating: NATORating | null`
- `specialistResults: Record<string, SpecialistResult>` (reducer: merge objects)
- `report: DocumentIntelligenceReport | null`

CRITICAL: Use custom reducers for all state keys updated by parallel specialist nodes to avoid LangGraph "Can receive only one value per step" errors (Pitfall 1 from RESEARCH.md).

`DocumentOrchestrator` class:
- `constructor(config: { problemSetId: string })` - loads ProblemSetContext from InterviewStore
- `processDocument(documentId: string, text: string, metadata: Record<string, any>): Promise<DocumentIntelligenceReport>` - invokes the StateGraph
- Internal `createGraph()` method builds the StateGraph:
  - Node `triage`: LLM call using TRIAGE_SYSTEM_PROMPT from RESEARCH.md. Reads first 2000 chars + metadata, outputs TriageDecision.
  - Node `format-converter`: runs FormatConverter specialist (conditional -- only if triage says needed)
  - Node `classifier`: runs DocumentClassifier specialist
  - Conditional edge from `triage`: routes to `format-converter` if needed, else directly to `classifier`
  - After `classifier`, fan-out to parallel specialists based on triageDecision.specialists (conditional edges)
  - Node `report-assembly`: collects all specialist outputs from state, assembles DocumentIntelligenceReport, saves to document_intelligence_reports table
  - Use existing `getCheckpointer()` for graph state persistence

`createDocIntelligenceGraph()` export function for external invocation.

Include the TRIAGE_SYSTEM_PROMPT from RESEARCH.md verbatim as a const.

Add SSE progress callbacks: the orchestrator should accept an optional `onProgress: (event: string, data: any) => void` callback that fires for each specialist start/complete/error event. This enables the Mission Control UI in later plans.

**format-converter.ts** - Extends SpecialistBase:
- `FormatConverter` class extending SpecialistBase with specialistId 'format-converter'
- Capabilities:
  1. OCR for scanned PDFs: Use `tesseract.js` (new dependency from RESEARCH.md). Detect scanned pages by checking if existing text extraction yields empty/minimal text. Run Tesseract on those pages.
  2. Language detection: Use LLM call on first ~500 chars to detect language. If non-English, note the language in metadata (actual translation is a future enhancement -- for now, flag language and proceed with available text).
  3. Table/chart detection: Use LLM to identify and describe embedded tables/charts in text form.
- Input: document text (possibly empty if scanned), document buffer/path for OCR
- Output: `{ convertedText: string, language: string, hasOCR: boolean, tables: string[], charts: string[] }`
- Install tesseract.js: add to package.json. Import as `import Tesseract from 'tesseract.js'`.
- System prompt: "You are a document format specialist. Analyze the provided document content for language, embedded data structures, and readability."

**document-classifier.ts** - Extends SpecialistBase:
- `DocumentClassifier` class extending SpecialistBase with specialistId 'document-classifier'
- LLM-driven classification (not keyword-based -- per user decision, replacing MidlifeCategorizer approach):
  - Input: document text (first 3000 chars) + ProblemSetContext
  - LLM classifies using DOCUMENT_TYPES taxonomy from types.ts
  - Scores relevance 0-1 against problem set scope (geographic, temporal, actor overlap)
  - Suggests container placement: which existing containers (Friendly/Adversary/Neutral/Partner) this document relates to
  - Identifies key topics for indexing
- Output validated against Zod schema: `{ documentType: DocumentType, classificationLevel: string, relevanceScore: number, suggestedContainers: string[], suggestedActorCategory: string, keyTopics: string[] }`
- System prompt: "You are a military intelligence document classifier. Given the document excerpt and problem set context, classify the document type, assess relevance, and suggest container placement."
- Use LLM factory for model selection.
